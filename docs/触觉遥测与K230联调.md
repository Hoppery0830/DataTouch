# 触觉遥测与 K230 联调

实现目录为本仓库 STM32F407VET6、ESP32、miniprogram；不要混用旧的独立工程副本。

## 数据路径及速率

六轴力传感器 → UART4 / PC10 TX、PC11 RX / 460800 → F4 TouchTask；ADXL335 → PC0/PC1/PC2 → 10 kHz ADC → 每100组三轴样本计算块统计（100 Hz）。
F4先处理有效力帧与ADC块、计算特征，再以100 ms窗口均值输出力/力矩曲线。F4 USART3 PB10 TX/PB11 RX → ESP32，115200 8N1，与原电机控制共用CRC8通道。

控制回执优先，其次250 ms电机状态，再发10 Hz遥测。遥测只取最新点，不排队重放；序号缺口保留到小程序。电机控制状态机不因特征参数改变。

ESP32缓存最新60点（约6秒），在原deviceCommand轮询请求中批量上传；正常轮询间隔2秒，HTTPS及其它云任务可能增加延迟。云端以设备号保存最新600点（通常约60秒）。同一会话按序号去重；F4重启/时间戳回绕或ESP32重启会开启新会话，曲线不跨会话拼接。断网超过缓存覆盖范围的数据不能补齐，本实现不是完整实验历史归档。云端仅保留实时窗口，不写入原experiments评分表。

## 特征定义

沿用touch_config.h中的力零偏和ADXL标定。没有增加上电自动置零，换传感器或安装状态后应重新标定。

- Fx/Fy/Fz：N，扣除配置零偏；Mx/My/Mz：N·m，保持原传感器力矩单位和零点。
- Ft = sqrt(Fx² + Fy²)，N = |Fz|；上云曲线是100 ms内这些量各自的均值。
- 100 ms摩擦比：均值Ft / 均值N；N不足0.2 N时无效。
- 每2秒非重叠窗口，使用所有已解析的、N≥0.2 N的有效力帧计算：法向/切向均值、均值Ft/均值N、单点摩擦比最大值、切向力总体标准差及峰峰值、Ft向上穿越“窗口均值+2倍标准差”的次数、有效接触样本数。最多存1200个接触样本，超限窗口标记无效。
- 100 ms振动值：该段有效块RMS的平方均值再开方。2秒振动特征：100 Hz块RMS的均值、最大值及0.5～40 Hz包络主频（0.5 Hz步长）。后者不是原始10 kHz加速度频谱；有效块不足或中断/饱和时窗口无效。
- 窗口特征在下一窗口结束前保持上次结果；没有有效特征时显示 --。摩擦比最大值不等同经规范测得的静摩擦系数，阈值上穿次数不等同已确认的粘滑次数。没有生成舒适度综合评分。

## K230 与 USART1

默认 TOUCH_USART1_K230=1：F4 PA9 TX → K230 GPIO12 / UART2 RX，F4 PA10 RX ← K230 GPIO11 / UART2 TX，共地，3.3V TTL，115200 8N1。此模式不发送电脑F/A/S文本；不要将电脑TX与K230 TX同时连接PA10。

兼容K230/stm32_uart_protocol.md现有协议：AA55 + type + len + payload + 加和校验（与ESP32的CRC8不同）。接收0x10补光开关、0x20小端float32 U_curve，返回0x80 ACK。成功状态0，非法内容1，补光硬件未配置2。坏校验不执行；NaN/Inf拒绝。重复开灯不延长超时，8秒自动关灯兜底。重复U_curve在2秒内不增加结果序号；协议无事务ID，两个相同结果相隔不足2秒无法与重试完全区分。

U_curve上传最近结果值、F4接收时间和结果序号。页面显示离散测量点，不把一次结果伪装成连续新采样；有结果不等于K230当前在线，也不与电机测试自动建立实验会话关联。

补光尚未指定接线：touch_config.h 默认 TOUCH_LIGHT_CONFIGURED=0，明确回复未就绪。K230现有流程在LIGHT_ON未获成功ACK时会取消拍摄，这是预期行为。确认驱动控制引脚/电平后，配置 TOUCH_LIGHT_PORT、TOUCH_LIGHT_PIN、TOUCH_LIGHT_ACTIVE、TOUCH_LIGHT_CLOCK_ENABLE() 并启用开关；GPIO只能控制灯驱动，不能直接供灯电流。

PC原始曲线模式：在STM32F407VET6目录执行：

```powershell
cmake --preset Debug -DTOUCH_USART1_K230=0
cmake --build --preset Debug
```

恢复K230将参数改为1，再编译烧录。修改CMake缓存后要重新编译，单改头文件默认值不能覆盖已有CMake定义。PC模式依然向ESP32上传触觉遥测，只关闭K230处理。

## 部署步骤

1. 烧录F4：STM32F407VET6/build/Debug/DataTouchCode.elf。极客核心板使用ADC时，REF+至3.3V、REF−至GND的对应跳线必须连接。
2. 在ESP32目录执行 `pio run -t upload`，保留已有WiFi/云端配置，设备号与小程序一致。
3. 微信开发者工具打开本仓库miniprogram目录。数据库新建 `device_telemetry` 集合；无需客户端直接读写权限，页面通过云函数读取。延续现有device_status和commands集合。
4. 上传并部署 `deviceCommand`（包含telemetry.js）和 `sendCommand`，云端安装依赖。沿用实际环境的设备token配置，不用仓库占位值覆盖已部署的真实密钥。
5. 重新编译小程序，进入“远程控制 → 查看力学与纹理曲线”。在选择器切换力、力矩、摩擦、振动及K230曲线。

新增实时数据读入口沿用现有sendCommand设备访问模型；本次没有实现多用户设备绑定或实验档案归属系统。

## 联调验收

先静止/手动加载六轴力与ADXL，核对本地读数和手机曲线方向/单位；等待2秒以上观察特征。再运行三种电机动作，确认STOP和状态更新仍正常。
关闭传感器或断开F4后，采样有效标志应消失/云端数据过期，不能显示“新鲜零值”。恢复后缺失区间应断线，重启后会话重置。K230完成补光配置后测试ON/OFF ACK、U_curve结果和无OFF时8秒熄灯。

本次软件测试包含F4/ESP32构建、K230协议与重试/超时、统计特征、云端存储去重/过期/设备隔离、页面生命周期和绘图分组。尚需实际硬件和微信开发者工具验证接线、界面显示、云端权限、网络延迟及任务栈余量。

## 遥测线协议 V1

F4→ESP32：`AA 55 21 6C payload[108] CRC8`，CRC与remote_protocol一致（poly 0x31，init 0xFF，覆盖帧头至载荷）。所有多字节数小端，不传C结构体填充。

| 偏移 | 内容 |
| --- | --- |
| 0 | version=1 |
| 1 | flags：bit0力有效、bit1ADC有效、bit2力窗口有效、bit3当前摩擦比有效、bit4K230有结果、bit5ADC饱和、bit6ADC窗口有效 |
| 2 | light：0关闭，1开启；未配置灯时保持0 |
| 3 | reserved=0 |
| 4、8 | 采样序号u32、F4毫秒时间u32 |
| 12、16 | K230结果序号u32、F4接收结果毫秒时间u32 |
| 20起 | 22个float32，顺序如下 |

`Fx,Fy,Fz,Mx,My,Mz,Ft,N,mu100,muWindow,FtStd,FtP2P,Rms100,RmsPeak,Ucurve,muPeak,Nmean,FtMean,Crossings,EnvelopeHz,RmsMean,ContactCount`

云端样本行为28项数组：`[seq,ms,flags,light,kseq,kms,上述22个值]`。无效字段的数值槽可为旧值/0，但消费者必须按flags屏蔽，不能显示为有效测量。K230有效位只表示存在历史结果。
