# 织物触觉舒适度检测系统 — 自建后端方案

> 目标：在**不改动 STM32↔ESP32 的 `protocol.h` 帧协议**、**保留现有 ESP32 WiFi 配网 / WebSocket / 内嵌显示页**的前提下，**新增一条 HTTPS 上云路径**，数据落进**自建后端**（API 服务 + 数据库 + 文件存储），让 **网页 / PC / 小程序多端**都能连、**数据自控**。
> 动因：个人开发环境可能**没有「HTTP 云函数」入口**（见《小程序与微信云开发落地方案.md》§5.1），且希望不被单一平台绑定。
> 一致性约定：本文档的**帧协议术语、四维字段名、`experiments` 表结构、云函数→REST 的接口语义与错误码**，均与《小程序与微信云开发落地方案.md》**逐项对齐**，便于两方案对比与**设备端代码复用**。
> 本文档**只描述方案，不改任何源码/工程**。

## 0. 先对齐：术语、字段与已定前提

> **命名约定（已统一，替换旧的"方案 A/B"叫法）**：**产品形态 A = 设备自带网页**、**产品形态 B = 微信小程序 + 云**、**产品形态 C = 原生 App**（见《产品端方案对比.md》）；**配网方式 ① = 保留热点(APSTA)**、**配网方式 ② = 连上后关热点用 IP（当前采用）**。产品形态 A/B/C 与配网方式 ①/② 是**两个不同维度**（一个是产品/客户端形态，一个是配网方式），**不要用"方案 A/B"指代配网方式**。另注：§12.1 的"三方案对比"用 A/B/C 指代**三种后端选型**（云开发 / 自建后端 / CloudBase），与上述"产品形态 A/B/C"编号无关。

### 0.1 设备侧（已定，不改）

| 端 | 型号/角色 | 现状 |
|---|---|---|
| STM32 | **STM32F407**（采集 + 力控 + **在 STM32 上算四维特征与综合评分**） | 六维力 RS485 **500Hz**（USART1，28B 帧，CRC-16/MODBUS）；振动 ADXL335 **1000Hz**（ADC1+TIM+DMA）；3 路闭环步进电机（USART3/UART4/USART6）；摄像头回弹 **UART5**；DWT 微秒时基 + T0 同步脉冲；FreeRTOS |
| ESP32 | **YD-ESP32-S3（WROOM-1-N16R8，16MB Flash + 8MB PSRAM）**，网关 | 已跑通：门户配网（连上后关热点用真实 IP）、WebSocket `:81`、内嵌显示页、DEMO 模式、UART 解析 `protocol.h` 帧 |
| UART 链路 | STM32 **USART2** ↔ ESP32 **UART2**（GPIO17/18） | **460800, 8N1**（已统一裁定：ESP32 `STM32_BAUD=460800`，STM32 USART2 同步 460800；`Serial.begin(115200)` 是 ESP32 USB 调试口，**不属本链路**） |

### 0.2 帧协议（`src/protocol.h`，**不改动**）

```
[0] 0xAA   [1] 0x55   [2] type   [3] len   [4..] payload(len 字节)   [last] crc8
crc8：多项式 0x31，初值 0xFF，覆盖 sync+type+len+payload
```

| type | 名称 | 载荷 | 说明 |
|---|---|---|---|
| `0x01` | `FRAME_DATA` | `TouchFrame` = 10×float + `uint8 contact`（约 41B） | 单帧时间序列，抽稀到 50–100Hz 后由 STM32 发出 |
| `0x02` | `FRAME_STATUS` | `uint8` | `ExpState`：0 IDLE / 1 ARMED / 2 RUNNING / 3 DONE / 4 ERROR |
| `0x03` | `FRAME_METRICS` | `MetricsFrame` = `softness, smoothness, roughness, rebound`(4×float) + `uint8 flags`（约 17B） | 四维特征；`flags` bit0 = 数据有效 |
| `0x04` | `FRAME_SCORE` | `float` | 综合评分 0–100 |
| `0x05` | `FRAME_CMD` | `uint8` | ESP32→STM32：arm / start / stop / reset |

`TouchFrame` 字段：`t`(s，**相对 T0**) / `x,y,z`(mm) / `Fx,Fy,Fz`(N) / `Mx,My,Mz`(N·mm) / `contact`(0/1)。

**四维字段名（数据库/API/JSON 一律沿用协议原名，不用中文别名当字段名）**：

| 字段 | 中文标签 | 方向 | 对应帧 |
|---|---|---|---|
| `softness` | 柔软度 | 越大越软 | `FRAME_METRICS` |
| `smoothness` | 顺滑度 | 越大越顺滑 | `FRAME_METRICS` |
| `roughness` | 细腻度/粗糙度 | **越小越细腻（融合时取反）** | `FRAME_METRICS` |
| `rebound` | 回弹贴合度 | 越大回弹越好 | `FRAME_METRICS` |
| `composite` | 综合评分 | 0–100 | `FRAME_SCORE` |

### 0.3 归一化与权重（**标定项**，与两份方案共同一致）

```text
norm  = clamp((x - min) / (max - min), 0, 1)     # min/max 由"参考布料集"标定
score = ( 0.30*softness + 0.25*smoothness + 0.20*(1.0 - roughness) + 0.25*rebound ) * 100
WEIGHTS = { softness:0.30, smoothness:0.25, roughness:0.20, rebound:0.25 }
RANGE   = { softness:[0,1], smoothness:[0,1], roughness:[0,1], rebound:[0,1] }
```

> **归一化 / 评分归属（权威）**：四维特征在 **STM32 上归一化到 [0,1]**，综合评分(0-100)在 **STM32 上计算**，是**权威值**；前端（网页/PC/小程序）**只显示**。DEMO 模式下前端 JS 融合**仅为演示**，不代表正式链路。与 ESP32 内嵌页 JS 的 `WEIGHTS`/`RANGE`、STM32 文档 §6.2–6.3 一致；自建后端的 `calibration` 表是这套参数（权重 / 归一化区间，**可调整**）的**下发通道**（§7.5），但**正式以 STM32 为准，标定值最终需同步/转发到 STM32**。

### 0.4 为什么走"自建后端"而不是云开发

| 动因 | 说明 |
|---|---|
| **入口可用性** | 个人环境的云开发控制台**可能没有「HTTP 云函数」入口**，设备上云主路径受阻（《小程序与微信云开发落地方案.md》§5.1 的 R3/待拍板 P3） |
| **多端** | 希望**网页 / PC / 小程序**共用同一套 API 与数据，而不是被单一平台的 SDK 绑定 |
| **数据自控** | 数据落在自己的服务器/自己的磁盘，可自由备份、迁移、导出、二次分析 |
| **不受额度政策影响** | 无平台免费额度/计费政策变动风险 |
| **代价** | 需要**服务器 + 域名 + ICP 备案 + TLS + 运维**（§2–§4、§11）——这是本方案的全部成本 |

**关键约束不变（来自《产品端方案对比.md》§1）**：微信小程序**真机**的 `wx.request` / `wx.connectSocket` 只允许 **HTTPS/WSS**，且域名必须在微信后台**服务器域名白名单**内；**局域网 IP（`192.168.x.x`）无法加入白名单**。所以：
- **网页/PC** → 直连自建后端，局域网或公网都行；
- **小程序真机** → 必须连**已备案的 HTTPS 域名**（或走"小程序→云函数→自建后端"的混合代理，§12.3）。

### 1.2 两条路径的分工

| # | 路径 | 发起方 | 传输 | 落点 | 用途 |
|---|---|---|---|---|---|
| ② | **设备上传**（新增，主路径） | ESP32 在实验 `STATE_DONE` 后 | **HTTPS POST** `/api/v1/device/upload`，HMAC-SHA256 鉴权 | `experiments` + 文件存储 | 无人值守，自动沉淀每次实验 |
| ③a | **客户端查询（历史）** | 网页 / PC / 小程序 | **HTTPS GET** `/api/v1/experiments[...]` + JWT | 读库 | 列表、详情、跨设备/跨时间对比 |
| ③b | **客户端查询（准实时）** | 网页 / PC | **WSS** `/api/v1/ws` 或 **SSE** `/api/v1/stream`；退化为轮询 `latest` | 推送/读库 | 远程"准实时"监控（非毫秒级） |
| ① | **本地实时**（保留，零改动） | 手机/PC 浏览器 | `ws://<ip>:81` / `http://datatouch.local/` | 不落库 | **毫秒级**实时曲线/四维/评分 + 控制（ARM/START/STOP/RESET） |

## 2. 服务器选型

### 2.1 两种部署形态

| 形态 | 说明 | 谁能连 |
|---|---|---|
| **A. 公网云服务器** | 阿里云 / 腾讯云**轻量应用服务器**，或 CVM/ECS；有公网 IP，绑域名 + 备案 + Let's Encrypt | 网页、PC、**小程序真机**（需备案域名）、外网任何地方 |
| **B. 本地服务器** | 你自己的 **PC / NAS / 树莓派**，部署在同一局域网；用 `http://192.168.x.x:8080` 或内网 DNS 访问 | 同一局域网内的网页/PC；**小程序真机连不上**（局域网 IP 无法加白名单）；**免备案** |

### 2.2 推荐配置（公网云服务器）

| 项 | 推荐 | 理由 |
|---|---|---|
| 机型 | **轻量应用服务器 2 核 2G / 4M 带宽 / 60–80GB SSD** | 本系统负载极低：写入 ≈ 每天数十~数百条实验，读取只是分页列表；2C2G 跑 Caddy + Node + PostgreSQL 绰绰有余 |
| 系统 | Ubuntu 22.04 / 24.04 LTS 或 Debian 12 | 生态最好，Docker/证书/文档齐全 |
| 带宽 | 3–5 Mbps 起步，含月流量包（数百 GB–1TB） | 单条摘要 ~3KB、抽稀曲线 5–30KB；**不传原始 500Hz/1kHz 数据**，流量几乎用不完 |
| 磁盘 | 60GB+ SSD | 数据量 ≈ 100MB/月（见 §11.6）；另留系统+备份空间 |
| 数据库 | 与 API **同机** PostgreSQL（Docker 容器） | 量级太小，不需要 RDS；同机省成本、低延迟 |
| 备份 | 同机定时 `pg_dump` + 异地（对象存储/另一块盘） | 防单机故障（§14） |
| 地域 | 内地地域（如上海/广州/北京） | 内地地域才能顺利 ICP 备案；延迟最好 |
| 升级触发 | 日活>10 台设备、曲线改为全量上传、或加视频/图像分析时 | 届时再升 2C4G 或拆库 |

> 如果**不做小程序、只要网页/PC**：优先 **B. 本地服务器**，成本近乎为零且免备案（§2.4、§12.4）。

### 2.3 推荐配置（本地服务器）

| 项 | 推荐 | 说明 |
|---|---|---|
| 硬件 | 现有 PC / NAS（群晖/威联通支持 Docker）/ **树莓派 4B 4GB 起**（+SSD） | 树莓派 4B 跑 Caddy+Node+PostgreSQL 足够；树莓派 3B/Zero 建议改用 SQLite |
| 系统 | Ubuntu Server / Debian / 群晖 Docker / Windows + Docker Desktop | 与公网方案同一份 `docker-compose.yml`，**部署方式完全一致** |
| 地址 | `http://<内网IP>:8080`，或内网 DNS（如 `datatouch.lan`）/ 自签 HTTPS | 浏览器端：局域网 HTTP 可用（但注意混合内容限制，§4.4） |
| 域名/备案 | **不需要** | 局域网 IP 不涉及 ICP |
| 运维 | 定时 `pg_dump` 到 NAS 共享目录；可选接 UPS | 断电风险靠备份兜底 |
| 外网访问（可选） | **Cloudflare Tunnel / frp / Tailscale**（§2.5） | 家宽通常无公网 IPv4，且 80/443 常被运营商封禁 |

### 2.4 "本地部署"与"公网部署"的差别（**必须提前想清楚**）

| 维度 | 本地部署（局域网） | 公网部署（云服务器） |
|---|---|---|
| 域名 + ICP 备案 | **不需要** | **需要**（内地地域，1–3 周） |
| TLS 证书 | 自签即可（客户端需信任）或干脆内网 HTTP | Let's Encrypt 免费证书，自动续期 |
| 小程序真机 | ❌ **不可用**（局域网 IP 无法加白名单） | ✅ 可用（需备案域名 + 白名单） |
| 网页 / PC | ✅ 局域网内直连 | ✅ 任何地方 |
| 离线可用性 | ✅ **强**（外网断了也能查历史） | ❌ 依赖外网 |
| 数据归属 | ★**数据完全在自己手里**（磁盘在你家） | 数据在自己的云主机上（仍在你自己账号下） |
| 成本 | ≈ **¥0–150/年**（多为电费） | **首年 ≈ ¥150–500，常规 ≈ ¥400–800/年**（§11.6） |
| 稳定性 | 依赖家用电力/网络，**单机宕机风险高** | 机房供电/网络，稳定性好得多 |
| 外网访问 | 需 DDNS + 端口映射；家宽**常无公网 IP、80/443 常被封** → 建议 Cloudflare Tunnel / frp | 天然公网可达 |
| 运维量 | 低（但断电/系统升级要自己盯） | 中（防火墙、证书、备份、告警） |
| 备份位置 | NAS/移动硬盘/U盘 | 对象存储 + 本地下载 |
| 合规 | 纯局域网，无备案/等保压力 | 域名备案、数据合规、对外暴露要防刷 |

**推荐组合（"本地 + 公网"双活，成本最低且两边好处都占）**：

```text
现场（同一 WiFi）:   浏览器 ──► 设备内嵌页 http://<ip>/  (毫秒级实时，产品形态 A)
                     浏览器 ──► 本地后端 http://192.168.x.x:8080  (查历史，零延迟、断外网可用)
------------------------------------------------------------------------------------
远程 / 小程序    :   小程序 ──► 公网后端 https://api.example.com  (需备案域名)
                     网页/PC ──► 公网后端 https://api.example.com
------------------------------------------------------------------------------------
数据同步         :   设备同时/择一上报；或用 pg_dump + 定时任务把公网库备份到本地
```

### 2.5 家宽暴露的坑（若选本地 + 外网访问）

| 坑 | 说明 | 对策 |
|---|---|---|
| 无公网 IPv4 | 多数家宽是 NAT 后的内网 IP | Cloudflare Tunnel（免费、无需端口映射）/ frp 内网穿透 / Tailscale（仅自己设备） |
| 80/443 被封 | 运营商对家宽常用端口做限制/需报备 | 换非标准端口（`https://host:8443`）；但**小程序白名单只认默认端口或已备案域名**，非标端口更麻烦 |
| 动态 IP | 公网 IP 会变 | DDNS（阿里云/腾讯云 DNS API 脚本） |
| 备案 | 家宽宽带**无法**做 ICP 备案（备案要求服务器在云厂商/IDC 且有接入商） | 要小程序就必须用云服务器 |
| 安全 | 家庭网络暴露 → 被扫 | 只暴露反向代理，DB 绝不监听公网；限流 + fail2ban；优先隧道方案（不开放入站端口） |

## 3. 域名 + ICP 备案

### 3.1 为什么内地公网访问必须备案

- 依据《互联网信息服务管理办法》，**在中华人民共和国境内**提供互联网信息服务、且服务器在**内地**（阿里云/腾讯云内地地域）时，域名需完成 **ICP 备案**，否则云厂商会**阻断 80/443 的 Web 访问**（未备案域名解析到内地 IP 会被拦截）。
- 与小程序的关系（**这是与微信云开发最大的差别**）：微信要求 `request`/`socket`/`uploadFile` 的**合法域名**必须是一个**已备案**的域名（境内主体）。因此：
  - **小程序真机 + 自建后端 ⇒ 备案是硬门槛**；
  - **仅网页/PC ⇒ 局域网免备案；公网仍建议备案**（不然内地云厂商会拦 Web 端口）。

### 3.2 备案流程与周期（内地云服务器）

```text
1) 买域名（阿里云/腾讯云/Namesilo…），完成域名实名认证（1–3 天）
2) 买内地云服务器（轻量/CVM/ECS），拿到「备案服务码」（轻量一般含 1–5 个）
3) 在云厂商「ICP 备案」控制台提交：
   · 主体信息（个人：身份证 + 手机号 + 人脸核验）
   · 网站信息（域名、网站名称、服务内容"技术研发/实验数据"）
   · 服务器信息（备案服务码绑定实例）
   · 部分地区/类型需《网站备案信息真实性核验单》+ 幕布拍照（现多为 App 人脸核验）
4) 云厂商初审（1–2 工作日）→ 提交省通信管理局（管局审核 5–20 工作日）
5) 通过后获得备案号（如 沪ICP备2026xxxxxx号），在网站底部展示并链接 beian.miit.gov.cn
6) 之后还要做「公安联网备案」（30 日内，免费，自愿但建议做）
```

| 项 | 量级 | 备注 |
|---|---|---|
| 总周期 | **1–3 周**（常见 10–15 个工作日） | **这是整个方案的时间瓶颈，务必最先启动** |
| 费用 | **0 元**（备案本身不收费） | 域名 + 服务器费用另计 |
| 有效期 | 与服务器绑定，服务器到期/更换需变更备案 | 换服务器要"接入备案" |
| 关键提醒 | 备案期间可以用**港澳台/海外服务器**或**局域网**先开发联调，**不要干等** | 见 §3.3、§13-M1 |

### 3.3 免备案选项及其影响

| 选项 | 免备案 | 小程序真机可用 | 速度（内地用户） | 合规/风险 |
|---|---|---|---|---|
| **仅局域网（本地服务器）** | ✅ | ❌ | 极快（局域网） | 无风险；只服务现场 |
| **香港服务器** | ✅（香港无需内地备案） | ❌ 域名无法备案 → **不能加微信白名单** | 中等（延迟 30–80ms，跨境抖动） | 数据出境需自行评估；仍建议加密 |
| **海外服务器**（新加坡/美国/日本） | ✅ | ❌ 同上 | 较差（150–300ms） | 同上 |
| **内地云 + 备案** | ❌ | ✅ | 最好 | 需周期 + 展示备案号 |
| **Cloudflare Tunnel / frp 中转** | 视落地服务器而定 | ❌（域名/通道仍难进白名单） | 中 | 用于"远程查看"，不适合小程序 |

> **结论**：
> - **只要做微信小程序真机 → 必须内地云 + 备案**（或改用 §12.3 的"小程序→云函数→自建后端"混合代理，绕开白名单）；
> - **只做网页/PC → 香港/海外服务器或本地部署都能免备案**，代价是小程序不可用、内地访问稍慢。
> - 备案周期不可压缩，**M1 阶段就用本地/香港环境联调**，备案作为并行任务推进。

### 3.4 域名与白名单落地清单（小程序用）

```text
1) 备案通过后，在微信公众平台 → 开发 → 开发管理 → 服务器域名 中配置：
   · request 合法域名   : https://api.example.com
   · socket 合法域名    : wss://api.example.com          （用 WebSocket 才需要）
   · uploadFile 域名    : https://api.example.com        （若客户端上传曲线/图片）
   · downloadFile 域名  : https://api.example.com        （详情页下载抽稀曲线）
2) 域名必须：HTTPS 有效证书（受信任 CA）、不能是 IP、不能带端口（用 443）、
   且**已完成 ICP 备案**。
3) web-view 业务域名：若在小程序里用 web-view 打开自建 H5，
   还需把该域名配到「业务域名」并上传校验文件到服务器根目录。
4) 域名白名单修改**每月有次数限制**，规划好域名再配；
   开发阶段可在开发者工具勾选"不校验合法域名"调试（真机无效）。
```

## 4. TLS / HTTPS

### 4.1 免费证书（Let's Encrypt）与自动续期

| 方案 | 说明 | 推荐度 |
|---|---|---|
| **Caddy**（Web 服务器，内置 ACME 客户端） | 写 3 行 Caddyfile 即自动申请 + 自动续期（90 天证书，到期前 30 天自动换） | ⭐**首选**（单机最省心） |
| Nginx + certbot | `certbot --nginx -d api.example.com`，systemd timer 自动续期 | 常用 |
| acme.sh + 手动 reload | 最灵活（支持 DNS 验证、泛域名） | 进阶 |
| 云厂商免费 DV 证书 | 阿里云/腾讯云每年可领 1 张 3 个月–1 年 DV 证书 | 备选（要手动换） |

```caddyfile
# /etc/caddy/Caddyfile —— 最小可用配置（自动 HTTPS + 反代 + WSS 透传）
api.example.com {
    encode gzip zstd
    request_body {
        max_size 1MB          # 设备上传体积上限（曲线抽稀后远小于此）
    }
    reverse_proxy 127.0.0.1:8080
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options nosniff
        X-Frame-Options DENY
        Referrer-Policy no-referrer
    }
    log {
        output file /var/log/caddy/api.log {
            roll_size 50MiB
            roll_keep 10
        }
    }
}
# Caddy 自动：申请证书 → 续期 → 80→443 跳转 → WSS 升级透传（无需额外配置）
```

> 续期自检：`systemctl status caddy` / `journalctl -u caddy | grep -i cert`；或加一个"证书剩余天数 < 15 天"的告警（§11.4）。

### 4.2 证书在局域网/内网场景

| 场景 | 做法 |
|---|---|
| 局域网纯 HTTP（浏览器访问管理页） | 直接 `http://192.168.x.x:8080`；**小程序不可用**，但网页/PC 可用 |
| 局域网要 HTTPS（如 H5 需要安全上下文） | 自签证书 + 客户端手动信任；或内网 DNS + 用公网 Let's Encrypt（DNS-01 验证，无需公网可达）+ 内网 DNS 解析 |
| 内网域名 | `datatouch.lan` + 路由器 DNS 或 `dnsmasq`；自签证书签发该域名 |

### 4.3 ESP32 侧证书校验策略（**三档，按阶段选**）

| 档 | 做法 | 安全性 | 适用 |
|---|---|---|---|
| **MVP** | `client.setInsecure();`（不校验证书链） | 低（可被中间人） | 内网/开发/联调，最快跑通 |
| **推荐（正式）** | 内置根 CA：`client.setCACert(ISRG_ROOT_X1_PEM);`（Let's Encrypt 的 ISRG Root X1，有效期至 2035） | 高 | 上线默认 |
| **高安全** | 根 CA + 校验主机名（`WiFiClientSecure` 默认校验）+ 证书透明度/OCSP 视需求 | 最高 | 有攻击面时 |

**⚠️ 嵌入式端 HTTPS 的常见坑（务必看）**：

1. **时间未同步 → 握手失败**：证书有效期校验依赖系统时间。ESP32 必须**先 SNTP 同步**（`configTime`）拿到正确时间，再做 TLS 握手；否则报 `x509 verify failed`。做法：开机/上传前确保 `time(nullptr) > 1700000000`（2023-11 之后），否则先 SNTP 等待（最多 10s），仍失败则本次降级跳过上传（不要静默 setInsecure）。
2. **不要用证书指纹（fingerprint）做长期方案**：Let's Encrypt 证书 **90 天轮换**，指纹 pinning 会导致**每 90 天要重新烧固件**。要 pin 就 pin **根 CA**。
3. **内存**：TLS 握手需要 ~30–50KB 缓冲；ESP32-S3 有 8MB PSRAM，但 `WiFiClientSecure` 默认缓冲（16KB in / 16KB out）在无 PSRAM 配置下可能失败。可 `client.setBufferSizes(4096, 4096);` 缩小（响应体很小）。
4. **HTTPClient 复用**：不要每个实验都新建 TLS 连接；可用 `client.setReuse(true)` 或干脆每次新建（实验频率低，简单优先）。
5. **根 CA 本身会过期**：Let's Encrypt 已从 X1 过渡到 X2（ECDSA）；固件内置根 CA 要留升级路径（可 OTA 或至少预留 NVS 覆盖）。
6. **`setInsecure()` 会影响所有后续请求**：切换回校验需重建 `WiFiClientSecure` 对象。

## 5. 技术栈建议

### 5.1 后端语言 / 框架

| 选项 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|
| **Node.js + Fastify**（或 Express） | 与《小程序与微信云开发落地方案.md》的云函数同为 JS，**同一套 JSON 处理/校验/签名逻辑可直接搬运**；异步 IO 适合本场景；生态成熟（`pg`、`@fastify/websocket`、`pino`） | 需要打包/PM2 或容器 | ⭐**首选** |
| **Python + FastAPI** | 类型校验（Pydantic）+ 自动生成 OpenAPI 文档；若后续要做数据分析（numpy/scipy/FFT）最顺 | 与云函数方案语言不同，签名逻辑要重写 | ⭐**并列首选（若偏数据分析）** |
| Go + Gin/Echo | 单二进制、内存占用小、树莓派上极佳 | 开发速度略慢 | 树莓派/资源紧张时优选 |
| NestJS | 结构规范、适合长期演进 | 对本项目偏重 | 可选 |

> **建议**：**Node.js + Fastify**（理由：设备端/云函数端已有 JS 版本可复用，切换后端只需换 URL 与鉴权校验；M1 一天内能跑通）。若你更熟悉 Python 或未来要做离线分析，用 **FastAPI**。

### 5.2 REST vs WebSocket（**两者都要，职责不同**）

| 通道 | 用途 | 何时用 |
|---|---|---|
| **REST（HTTPS）** | 一切**写入**与**分页查询**（设备上传、历史列表、详情、标定、绑定） | 默认，全部业务接口 |
| **WebSocket（WSS）** | 服务端→客户端的**事件推送**：`experiment.created`（新实验已归档）、`device.online/offline`、`calibration.updated` | 网页/PC 的"自动刷新"与"准实时" |
| **SSE（`text/event-stream`）** | 同 WebSocket 的**只读单向推送**，实现更简单、自动重连、走普通 HTTP（易过代理） | PC/网页只想"看进度"时的轻量选择 |
| **轮询** | `GET /api/v1/experiments/latest` 每 2–5s | **最稳的兜底**（尤其小程序端，M2 就用它） |

> **原则**：**写入永远走 REST**（可重放、可鉴权、可审计）；**推送只用于"通知有新数据"，不用于传大量数据**。实时曲线（毫秒级）永远归设备内嵌页（§10）。

### 5.3 数据库取舍

| 选项 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **PostgreSQL 16** | **JSONB** 完美承载 `weights`/`ranges`/`refMetrics`（等价云开发的文档灵活性）；唯一索引保证 `dedupId` 幂等；`timestamptz` 语义严谨；`text[]` 存 `shareOpenids`/`referenceFabricIds` | 比 SQLite 稍重 | ⭐**公网/多设备首选** |
| MySQL 8 | 生态广、运维资料多，也有 JSON 类型 | JSON 能力弱于 PG；数组类型需变通 | 备选 |
| **SQLite（WAL）** | **零运维、单文件、树莓派/PC 本地部署最合适**；数据量小（<5GB，写入每日几十~几百条）完全够 | 无并发写优势、无网络访问、备份靠文件复制 | ⭐**纯本地/单机 MVP 首选** |
| MongoDB | 与云开发文档型最接近，迁移最平滑 | 幂等/唯一索引与事务不如 SQL 直观 | 可用但不必要 |

> **推荐**：**PostgreSQL**（本方案默认，下文 SQL 均按 PG 写）；若确定只做**局域网单机**，直接上 **SQLite**，代码里换 Prisma/ORM 的 provider 即可（§6.5）。

### 5.4 文件存储（抽稀曲线 / 原始 CSV / 截图）

| 选项 | 适用 | 成本 | 说明 |
|---|---|---|---|
| **本地磁盘**（`/data/curves/{dedupId}.json`） | ⭐**默认（本地 + 单机公网都够用）** | 0 | 由 API 服务以受保护路由下发；备份与数据库一起做 |
| 对象存储 **OSS / COS** | 数据量大、要多副本、要 CDN 分发时 | ≈ ¥0.10–0.15/GB/月 + 流量 | 与云开发的"云存储"等价；用**预签名 URL** 给客户端（有效期 5–30 分钟） |
| **不入库、不入存储** | 只传摘要（M1） | 0 | 最省事 |

> 承袭云开发方案的结论：**曲线抽稀到 20–50Hz 后再存**（单实验 5–30KB）；**原始 500Hz/1kHz 不上传**，仅在"手动导出"时落盘。

### 5.5 鉴权（三类主体，三套机制）

| 主体 | 机制 | 说明 |
|---|---|---|
| **设备（ESP32）** | **HMAC-SHA256 + nonce + 时间窗**（§8.2）；每设备独立 `deviceSecret`，服务端只存 `secretHash` | 无会话、无 cookie，适合嵌入式 |
| **客户端用户**（网页/PC/小程序） | **JWT**（`Authorization: Bearer <token>`）：access 2h + refresh 30d；小程序用 `wx.login` code → 服务端 `code2session` 换 `openid`（**AppSecret 只在服务端**）；网页/PC 用账号密码（argon2id）或（MVP）单一管理 token | 与云开发"免自建用户体系"的差别：自建后端**需要自己的用户体系**（可用"单一用户模式"简化，§15-P4） |
| **运维/脚本** | 静态 API Key（`X-Api-Key`）+ IP 白名单（可选） | 仅用于管理接口与批量导出 |

## 6. 数据库 schema

### 6.1 通用约定

> 1. **字段名严格沿用 `protocol.h` / `MetricsFrame` / `FRAME_SCORE` 的命名**：`softness` / `smoothness` / `roughness` / `rebound` / `composite`。
> 2. **表名与字段名与《小程序与微信云开发落地方案.md》§3 的集合/字段**一一对应（同名的用 `★` 标注），便于两方案对比、也便于**"云开发 → 自建"迁移脚本**直接搬运。
> 3. **命名风格**：为与文档/JSON/小程序端保持一致，SQL 中保留 **camelCase 并用双引号包裹**（`"dedupId"`）。这样 **DB 列名 == JSON 字段名**，中间零映射、零出错。若你偏好 SQL 惯例的 `snake_case`，请统一改为 `dedup_id` 等，但**接口 JSON 仍必须是 camelCase**（此项见 §15-P1）。
> 4. **时间**：统一 `timestamptz`（等价云开发 Date）。绝对时间用设备 SNTP（`startedAt`/`endedAt`），**权威接收时间**用服务端 `createdAt`（`now()`）。
> 5. **归属**：沿用云开发方案的 `openid`（★），并**新增 `ownerUid`** 作为自建用户体系主键 —— 网页/PC 用户没有 openid，两者并存：小程序用户 `openid` 有值、`ownerUid` 也可有值；纯网页用户 `openid` 为空、`ownerUid` 有值。**查询口径统一按"当前登录主体"过滤**（§7.2）。
> 6. **JSON 字段**：`weights` / `ranges` / `refMetrics` / `shareOpenids` 用 **JSONB / text[]**，与云开发的 `object`/`array` 语义等价。
> 7. **索引**：`dedupId` 唯一（幂等基石）、`deviceId+startedAt` 复合、`ownerUid+startedAt`、`openid+startedAt`、`composite`。
> 8. **标定唯一生效**：`calibration` 用**部分唯一索引**保证同 `scope+deviceId` 下只有一条 `isActive=true`（比云开发的"手动置旧版 false"更硬）。

### 6.2 四张核心表（+ 两张辅助表）

#### 6.2.1 `experiments` —— 一次实验一条（**核心表**，★ 全部与云开发方案同名）

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `_id` ★ | text PK | 主键（24 位 hex，等价云开发 `_id`）；用于 `GET /experiments/{id}` | `"a1b2c3d4e5f6a7b8c9d0e1f2"` |
| `dedupId` ★ | text UNIQUE | **去重幂等键**（设备生成，§8.6） | `"YD32S3-3C6108A1-000042-0007"` |
| `openid` ★ | text NULL | 微信身份（小程序登录时写入）；网页/PC 用户为空 | `"oXy7Zk9QwErTyUiOpAsDfGhJkLmN"` |

### 6.3 建表 SQL（PostgreSQL ≥ 13）

```sql
-- ============================================================================
-- 自建后端 · PostgreSQL 建表
-- 命名与《小程序与微信云开发落地方案.md》§3 完全一致（camelCase + 双引号）
-- ============================================================================
CREATE EXTENSION IF NOT EXISTS pgcrypto;   -- gen_random_bytes()

-- ---------- 1) users（可选：单一用户模式可跳过） ----------
CREATE TABLE IF NOT EXISTS users (
  uid           bigserial PRIMARY KEY,
  openid        text UNIQUE,
  unionid       text,
  username      text UNIQUE,
  "passHash"    text,
  nickname      text NOT NULL DEFAULT '',
  role          text NOT NULL DEFAULT 'user' CHECK (role IN ('user','admin')),
  "createdAt"   timestamptz NOT NULL DEFAULT now(),
  "lastLoginAt" timestamptz
);

-- ---------- 2) devices ----------
CREATE TABLE IF NOT EXISTS devices (
  "_id"               text PRIMARY KEY,                       -- = deviceId
  "deviceId"          text NOT NULL UNIQUE,
  "deviceName"        text NOT NULL DEFAULT '',
  model               text NOT NULL DEFAULT 'ESP32-S3-WROOM-1-N16R8',
  "fwVersion"         text NOT NULL DEFAULT '',
  "claimCode"         text UNIQUE,
  "claimCodeExpireAt" timestamptz,
  "ownerOpenid"       text,
  "ownerUid"          bigint REFERENCES users(uid) ON DELETE SET NULL,
  "boundAt"           timestamptz,
  "shareOpenids"      text[] NOT NULL DEFAULT '{}',
  "secretHash"        text NOT NULL,                          -- sha256(secret + salt)
  "secretVersion"     smallint NOT NULL DEFAULT 1,
  "lastSeenAt"        timestamptz,
  "lastIp"            inet,
  status              text NOT NULL DEFAULT 'active'
                        CHECK (status IN ('active','disabled')),
  "uploadEnabled"     boolean NOT NULL DEFAULT true,
  "createdAt"         timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT devices_owner_chk CHECK (NOT ("ownerOpenid" IS NULL AND "ownerUid" IS NULL) OR true)
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_devices_claim
  ON devices ("claimCode") WHERE "claimCode" IS NOT NULL;
CREATE INDEX IF NOT EXISTS ix_devices_owner ON devices ("ownerUid");

-- ---------- 3) fabrics ----------
CREATE TABLE IF NOT EXISTS fabrics (
  "_id"           text PRIMARY KEY,
  name            text NOT NULL,
  code            text NOT NULL DEFAULT '',
  material        text NOT NULL DEFAULT '',
  weave           text NOT NULL DEFAULT '',
  "thicknessMm"   double precision,
  gsm             double precision,
  "isReference"   boolean NOT NULL DEFAULT false,
  "refRole"       text NOT NULL DEFAULT '' CHECK ("refRole" IN ('','min','max','mid')),
  "refMetrics"    jsonb,
  "refComposite"  double precision,
  openid          text,
  "ownerUid"      bigint REFERENCES users(uid) ON DELETE SET NULL,
  "isPublic"      boolean NOT NULL DEFAULT false,
  "imageFileId"   text NOT NULL DEFAULT '',
  notes           text NOT NULL DEFAULT '',
  "createdAt"     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS ix_fabrics_ref ON fabrics ("isReference") WHERE "isReference";
CREATE INDEX IF NOT EXISTS ix_fabrics_owner ON fabrics ("ownerUid", "createdAt" DESC);

-- ---------- 4) experiments（核心表） ----------
CREATE TABLE IF NOT EXISTS experiments (
  "_id"                    text PRIMARY KEY
                             DEFAULT encode(gen_random_bytes(12),'hex'),  -- 24 hex
  "dedupId"                text NOT NULL UNIQUE,               -- 幂等基石
  openid                   text,
  "ownerUid"               bigint REFERENCES users(uid) ON DELETE SET NULL,
  "deviceId"               text NOT NULL REFERENCES devices("deviceId") ON DELETE RESTRICT,
  "deviceName"             text NOT NULL DEFAULT '',
  "fabricId"               text,
  "fabricName"             text NOT NULL DEFAULT '',
  "fabricCode"             text NOT NULL DEFAULT '',
  mode                     text NOT NULL DEFAULT 'real' CHECK (mode IN ('demo','real')),
  state                    smallint NOT NULL DEFAULT 3,
  softness                 double precision NOT NULL,
  smoothness               double precision NOT NULL,
  roughness                double precision NOT NULL,
  rebound                  double precision NOT NULL,
  composite                double precision NOT NULL
                             CHECK (composite >= 0 AND composite <= 100),
  "metricsNormalized"      boolean NOT NULL DEFAULT true,
  "metricsFlags"           smallint NOT NULL DEFAULT 1,
  weights                  jsonb,
  "calibrationVersion"     text NOT NULL DEFAULT '',
  "startedAt"              timestamptz,
  "endedAt"                timestamptz,
  "timeSource"             text NOT NULL DEFAULT 'device'
                             CHECK ("timeSource" IN ('device','estimated','server')),
  t0_relative_duration_s   double precision NOT NULL DEFAULT 0
                             CHECK (t0_relative_duration_s > 0 AND t0_relative_duration_s <= 3600),
  "sampleCount"            integer NOT NULL DEFAULT 0,
  "curveFileId"            text NOT NULL DEFAULT '',
  "resultFileId"           text NOT NULL DEFAULT '',
  notes                    text NOT NULL DEFAULT '',
  "operatorOpenid"         text NOT NULL DEFAULT '',
  "syncState"              text NOT NULL DEFAULT 'ok'
                             CHECK ("syncState" IN ('ok','pending','failed')),
  "schemaVersion"          smallint NOT NULL DEFAULT 1,
  "createdAt"              timestamptz NOT NULL DEFAULT now()
);
-- 查询索引
CREATE INDEX IF NOT EXISTS ix_exp_device_time  ON experiments ("deviceId", "startedAt" DESC);
CREATE INDEX IF NOT EXISTS ix_exp_owner_time   ON experiments ("ownerUid", "startedAt" DESC);
CREATE INDEX IF NOT EXISTS ix_exp_openid_time  ON experiments (openid,      "startedAt" DESC);
CREATE INDEX IF NOT EXISTS ix_exp_fabric_time  ON experiments ("fabricId",  "startedAt" DESC);
CREATE INDEX IF NOT EXISTS ix_exp_composite    ON experiments (composite DESC);
CREATE INDEX IF NOT EXISTS ix_exp_created      ON experiments ("createdAt" DESC);

-- ---------- 5) calibration ----------
CREATE TABLE IF NOT EXISTS calibration (
  "_id"                text PRIMARY KEY,                      -- = version
  version              text NOT NULL UNIQUE,
  scope                text NOT NULL DEFAULT 'global'
                         CHECK (scope IN ('global','device','user')),
  "deviceId"           text NOT NULL DEFAULT '',
  openid               text NOT NULL DEFAULT '',
  ranges               jsonb NOT NULL,
  weights              jsonb NOT NULL,
  "roughnessInverted"  boolean NOT NULL DEFAULT true,
  "referenceFabricIds" text[] NOT NULL DEFAULT '{}',
  "sampleCount"        integer NOT NULL DEFAULT 0,
  "isActive"           boolean NOT NULL DEFAULT true,
  "updatedBy"          text NOT NULL DEFAULT '',
  "updatedAt"          timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT calib_weights_sum_chk CHECK (
    abs( (weights->>'softness')::numeric
       + (weights->>'smoothness')::numeric
       + (weights->>'roughness')::numeric
       + (weights->>'rebound')::numeric - 1 ) < 1e-6
  )
);
-- ★ 同 scope+deviceId 下只允许一条 isActive（比云开发"手动置旧版 false"更硬）
CREATE UNIQUE INDEX IF NOT EXISTS ux_calib_active
  ON calibration (scope, "deviceId") WHERE "isActive";

-- ---------- 6) device_nonces（防重放） ----------
CREATE TABLE IF NOT EXISTS device_nonces (
  "deviceId"  text NOT NULL,
  nonce       text NOT NULL,
  ts          bigint NOT NULL,
  "createdAt" timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY ("deviceId", nonce)
);
CREATE INDEX IF NOT EXISTS ix_nonce_created ON device_nonces ("createdAt");
```

### 6.6 与云开发方案的字段差异一览（便于对比）

| 字段 | 云开发方案 | 自建后端 | 说明 |
|---|---|---|---|
| `_id` | 云自动 16 位 | 24 位 hex（`gen_random_bytes`） | 语义相同 |
| `openid` | 唯一归属口径 | 保留，但**可为空** | 自建多端：小程序有 openid，网页/PC 没有 |
| `ownerUid` | — | **新增** | 自建用户体系归属；单用户模式可恒为 NULL |
| `timeSource` | §5.6 提到但未建表 | **建表落地** | 时间退化标记（列表显示"≈"） |
| `curveFileId` | `cloud://` fileID | 本地路径 / OSS key | 语义相同，指向不同存储 |
| `ranges`/`weights`/`refMetrics` | `object` | `jsonb` | 等价 |
| `shareOpenids` / `referenceFabricIds` | `array<string>` | `text[]` | 等价 |
| 时间类型 | BaaS `Date` | `timestamptz` | 等价 |
| 唯一约束 | 集合索引（需手工建） | **DDL 部分唯一索引**（`ux_calib_active`） | 自建更硬 |
| 错误码 | 4000/4010/4011/4013/4014/4015/4020/4100-4103 | **完全相同** | 设备端代码可复用（§12.2） |

## 7. API 接口设计

### 7.1 通用约定

```text
Base URL          : https://api.example.com/api/v1          （本地部署：http://192.168.x.x:8080/api/v1）
统一返回结构       : { "code": 0, "message": "ok", "data": { ... } }
失败              : { "code": 4015, "message": "bad signature", "data": null }
HTTP 状态码        : 200（业务成功/业务错误均 200 + code）、4xx（协议/鉴权层）、5xx（服务端）
时间格式           : ISO-8601 UTC（"2026-09-06T10:21:03.000Z"）或毫秒时间戳（上传体用毫秒，与云开发方案一致）
分页              : page（从 1 开始）+ pageSize（默认 20，上限 200；小程序端沿用 50 上限）
鉴权              : 设备 = HMAC 头；用户 = Authorization: Bearer <JWT>；脚本 = X-Api-Key
幂等              : 写接口以 dedupId 保证；响应里的 dedup 字段告知是否命中已有记录
```

**错误码表（与《小程序与微信云开发落地方案.md》完全一致，便于设备端复用）**

| code | HTTP | 含义 | 触发 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `4000` | 200 | 缺少必需字段 | body 缺 `deviceId`/`dedupId`/`payload` |
| `4001` | 200 | 绑定码不存在 | `bind` |
| `4002` | 200 | 绑定码已过期 | `bind` |
| `4003` | 200 | 设备已被他人绑定 | `bind` |
| `4004` | 200 | 该用户已绑定此设备 | `bind` |
| `4010` | 200 | 设备未注册 | `devices` 中无此 `deviceId` |
| `4011` | 200 | 设备已停用 | `status=disabled` 或 `uploadEnabled=false` |
| `4013` | 200 | 时间偏移过大 | `\|now - ts\| > 300s` |
| `4014` | 200 | nonce 重放 | `device_nonces` 命中 |
| `4015` | 200 | 签名错误 | HMAC 不匹配（**常量时间比较**） |
| `4020` | 200 | 数值越界 | 四维/composite/duration 超范围 |
| `4029` | 413 | 请求体过大 | > 64KB（曲线抽稀后不会触发） |
| `4030` | 403 | 无权限 | JWT 有效但无权访问该资源 |
| `4040` | 404 | 资源不存在 | `experiments/{id}` 不存在 |
| `4100` | 200 | 标定缺少 version/参考布料 | `POST /calibration` |
| `4101` | 200 | 未找到有效参考布料 | 同上 |
| `4102` | 200 | 参考布料缺少 `refMetrics.<key>` | 同上 |
| `4103` | 200 | 权重之和不为 1 | 同上 |
| `4290` | 429 | 触发限流 | 按 `deviceId`/IP 限流 |
| `5000` | 500 | 服务端错误 | DB/磁盘异常（响应不含堆栈） |

### 7.2 `POST /api/v1/device/upload` —— **设备上云**（HMAC 鉴权）

```http
POST /api/v1/device/upload HTTP/1.1
Host: api.example.com
Content-Type: application/json
X-Device-Id: YD32S3-3C6108A1
X-Timestamp: 1756376463
X-Nonce:     b7f1c2
X-Sign:      3f9a...c1
X-Fw:        v0.9.3

{ ...见 §8.1 请求体... }
```

- **鉴权**：`sign = HMAC_SHA256(derivedKey, deviceId|dedupId|ts|nonce|sha256(rawBody))`，`derivedKey = sha256(deviceSecret + KEY_PEPPER)`（§8.2）
- **校验顺序**（任一失败即拒绝）：
  ```text
  1) 字段存在性（deviceId/dedupId/payload）                        → 4000
  2) devices 中 deviceId 存在、status=active、uploadEnabled=true    → 4010 / 4011
  3) |now - X-Timestamp| <= 300s                                    → 4013
  4) nonce 未在最近 300s 内用过（device_nonces 主键冲突即拒）        → 4014
  5) HMAC 重算并与 X-Sign 常量时间比较                               → 4015
  6) 数值范围：四维 ∈[0,1] 或 [0,100]（依 metricsNormalized）、
     composite ∈[0,100]、duration ∈(0,3600]、curve 点数 ≤4000        → 4020
  7) dedupId 已存在 → 幂等返回成功（不重复写、不覆盖）              → code 0, dedup=true
  ```
- **响应**：

```json
{ "code": 0, "message": "ok",
  "data": { "_id": "a1b2c3d4e5f6a7b8c9d0e1f2", "dedup": false,
            "curveFileId": "/data/curves/YD32S3-3C6108A1-000042-0007.json" } }
```

- **行为**：
  1. 若 `payload.curve` 存在 → 写文件存储 `curves/{dedupId}.json`（内容 `{"t0":<duration>,"points":[...]}`），得 `curveFileId`；
  2. `INSERT INTO experiments ... ON CONFLICT ("dedupId") DO NOTHING RETURNING "_id"`（**幂等 upsert**）；
  3. 反查 `devices.ownerOpenid`/`ownerUid` 填 `openid`/`ownerUid`；
  4. `UPDATE devices SET "lastSeenAt"=now(), "lastIp"=<X-Forwarded-For>, "fwVersion"=<X-Fw>`；
  5. 通过 WebSocket/SSE 广播事件 `{"type":"experiment.created","experimentId":"..."}`（客户端据此自动刷新）；
  6. 返回 `_id`。

> **安全实现要点**：`rawBody` 必须是"**设备实际发出的字节**"（不要 `JSON.stringify(解析后的对象)`，键序/空格不一致会导致验签永远失败——这是设备上云最常见的坑，云开发方案 §5.3 已强调，自建后端同样适用）。用 `raw-body` 中间件拿原始 buffer。

### 7.3 `GET /api/v1/experiments` —— 分页查询

```http
GET /api/v1/experiments?deviceId=YD32S3-3C6108A1&fabricId=f1001
    &startTime=2026-09-01T00:00:00Z&endTime=2026-09-07T00:00:00Z
    &minComposite=0&maxComposite=100&orderBy=startedAt&order=desc
    &page=1&pageSize=20&scope=mine HTTP/1.1
Authorization: Bearer <JWT>
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `deviceId` | string | — | 按设备筛选 |
| `fabricId` | string | — | 按布料筛选 |
| `startTime` / `endTime` | ISO8601 | — | 按 `startedAt` 区间 |
| `minComposite` / `maxComposite` | number | — | 按评分区间 |
| `orderBy` | enum | `startedAt` | `startedAt` / `composite` / `createdAt` |
| `order` | enum | `desc` | `asc` / `desc` |
| `page` / `pageSize` | int | 1 / 20 | `pageSize ≤ 200`（小程序端 ≤50） |
| `fields` | string[] | 白名单默认集 | 裁剪返回字段 |
| `scope` | enum | `mine` | `mine`=仅自己的；`all`=**仅 admin 可用**；`public`=公共 |

- **服务端强制**：`scope=mine` 时**服务端注入**归属过滤（`ownerUid = <当前用户>` 或 `openid = <当前 openid>`），**忽略客户端传的 openid/uid**（越权防范）。
- **响应**：

```json
{ "code": 0, "message": "ok",
  "data": {
    "total": 137, "page": 1, "pageSize": 20,
    "list": [
      { "_id": "a1b2c3d4e5f6a7b8c9d0e1f2", "deviceId": "YD32S3-3C6108A1",
        "fabricName": "纯棉平纹40支", "composite": 72.4,
        "softness": 0.62, "smoothness": 0.71, "roughness": 0.24, "rebound": 0.55,
        "startedAt": "2026-09-06T10:21:03.000Z", "timeSource": "device" }
    ]
  } }
```

- **要点**：默认**不返回曲线**（列表轻量）；`fields` 白名单裁剪，**绝不返回 `secretHash`**；`pageSize` 上限见上。
- **配套**：`GET /api/v1/experiments/latest?deviceId=...` → 返回最近 1 条（**准实时轮询用**，M2 主路径）。

### 7.4 `GET /api/v1/experiments/{id}` —— 详情

```http
GET /api/v1/experiments/a1b2c3d4e5f6a7b8c9d0e1f2 HTTP/1.1
Authorization: Bearer <JWT>
```

- **响应**：完整 `experiments` 记录 + `data.curveUrl`（抽稀曲线下载地址；本地存储走受保护路由 `/api/v1/files/curves/{dedupId}.json`，对象存储走**预签名 URL**，有效期 5–30 分钟）。
- **越权校验**：先查库，比对 `ownerUid == 当前 uid` **或** `openid == 当前 openid` **或** 当前用户 ∈ `devices.shareOpenids`；不满足 → `4030`。
- **错误码**：`4040` 不存在 / `4030` 无权限。

### 7.5 `GET` / `POST /api/v1/calibration` —— 标定读取与权重下发

**`GET /api/v1/calibration?deviceId=YD32S3-3C6108A1`**（设备与客户端都可调；设备用 HMAC，客户端用 JWT）

```json
{ "code": 0, "message": "ok",
  "data": {
    "version": "calib-2026-09-01",
    "ranges": { "softness":[0.05,1.20], "smoothness":[0.10,0.95],
                "roughness":[0.02,0.80], "rebound":[0.15,0.90] },
    "weights": { "softness":0.30, "smoothness":0.25, "roughness":0.20, "rebound":0.25 },
    "roughnessInverted": true,
    "updatedAt": "2026-09-01T08:00:00.000Z"
  } }
```

- 取优先级：`scope=device 且 deviceId 匹配 且 isActive` → `scope=user` → `scope=global`（最新一条）。

**`POST /api/v1/calibration`**（JWT + 管理员/设备 owner）

```json
{ "version": "calib-2026-09-02", "scope": "global", "deviceId": "",
  "referenceFabricIds": ["f1001","f1002"], "weights": {"softness":0.30,"smoothness":0.25,"roughness":0.20,"rebound":0.25},
  "method": "minmax" }
```

- **行为**（与云函数 `setCalibration` 完全一致）：读 `fabrics` 中 `isReference=true 且 _id ∈ referenceFabricIds` 的 `refMetrics` → 按 `minmax` 计算每维 `[min,max]`，**留 5% 余量**（`pad = (hi-lo)*0.05 || 0.05`）→ 权重和必须为 1（否则 `4103`）→ 写新 `calibration`（`isActive=true`）→ **同 `scope+deviceId` 下旧版本置 `isActive=false`**（靠部分唯一索引在事务内保证）→ **广播 `calibration.updated` 事件**。
- **响应**：`{ code:0, data:{ version, ranges:{...}, weights:{...}, isActive:true } }`
- **下发链路**：
  ```text
  网页/PC/小程序 改标定 → POST /api/v1/calibration → calibration 表更新
      └─► ESP32 启动时 / 每个实验上报前  GET /api/v1/calibration?deviceId=…（HMAC）
            └─► 存 NVS → 内嵌显示页 WEIGHTS/RANGE 以 NVS 为准（保留硬编码默认值兜底）
                  └─► 本地实时与云端历史口径一致（experiments 记录 calibrationVersion/weights 快照）
  ```

> **归属提醒（口径）**：四维归一化与综合评分**正式以 STM32 为准**，标定值最终需**同步/转发到 STM32**（本节链路目前只落到 ESP32 NVS，设计不改）。

## 8. ESP32 上传协议

> **结论先说**：ESP32 侧代码与《小程序与微信云开发落地方案.md》§5 **几乎完全一致**，差异只有 3 处：**① URL 换成自建域名；② TLS 证书策略（自建用 Let's Encrypt 根 CA 或 MVP 的 `setInsecure()`）；③ 标定拉取路径换成 `GET /api/v1/calibration`**。因此两方案可以**共用同一份 `cloud_client.cpp` / `upload_queue.cpp` / `hmac_sign.cpp`**，只把 base URL 做成 NVS 可配。

### 8.1 请求体（JSON 字段与 `experiments` 表对齐）

```json
{
  "deviceId": "YD32S3-3C6108A1",
  "dedupId": "YD32S3-3C6108A1-000042-0007",
  "ts": 1756376463,
  "nonce": "b7f1c2",
  "sign": "3f9a...c1",
  "fw": "v0.9.3",
  "frameCrc8": "A7",
  "payload": {
    "mode": "real",
    "state": 3,
    "softness": 0.62, "smoothness": 0.71, "roughness": 0.24, "rebound": 0.55,
    "composite": 72.4,
    "metricsNormalized": true,
    "metricsFlags": 1,
    "weights": { "softness":0.30, "smoothness":0.25, "roughness":0.20, "rebound":0.25 },
    "calibrationVersion": "calib-2026-09-01",
    "startedAt": 1756376463000,
    "endedAt": 1756376496800,
    "t0_relative_duration_s": 33.8,
    "fabricId": "f1001", "fabricName": "纯棉平纹40支", "fabricCode": "C-40S-PLAIN-03",
    "notes": "",
    "curve": [
      { "t": 0.00, "Fz": 0.02, "Fx": 0.00, "z": 0.00 },
      { "t": 0.02, "Fz": 0.15, "Fx": 0.01, "z": 0.01 }
    ]
  }
}
```

- 四维/评分**直接取自 `FRAME_METRICS` / `FRAME_SCORE`**，ESP32 **不做任何特征重算**（保持"STM32 算、ESP32 传"的职责边界）。
- `curve` 由 `FRAME_DATA`（抽稀到 20–50Hz）生成；M1 可整个省略该字段（只传摘要，~2–4KB）。
- `frameCrc8` 是对源帧做的 CRC8（poly 0x31 / init 0xFF），**仅作日志**，不作为鉴权依据（鉴权靠 `dedupId + sign`）。

### 8.2 请求头与 HMAC-SHA256 签名

```text
出厂/首次配网阶段（写入 NVS，不进固件源码）：
  deviceId     = "YD32S3-" + MAC 后 6 位            // 例：YD32S3-3C6108A1
  deviceSecret = 32 位随机 hex（每条设备唯一；云端只存 sha256(secret+salt)）
  claimCode    = 6 位短码（用于 bind，展示在内嵌页/串口）
  apiBase      = "https://api.example.com"（NVS 可配，便于本地/公网切换）

每次上报：
  ts        = SNTP 绝对秒（失败则退化为"上次成功时间 + 单调递增计数"，并置 timeSource=estimated）
  nonce     = 随机 6 位 hex
  body      = 待发送 JSON 的【原始字节字符串】（不含 sign 字段）
  bodyHash  = SHA256(body) 的 hex
  sign      = HMAC_SHA256(derivedKey, deviceId + "|" + dedupId + "|" + ts + "|" + nonce + "|" + bodyHash)
              derivedKey = SHA256(deviceSecret + KEY_PEPPER)     // 与后端派生方式完全一致

请求头：
  Content-Type: application/json
  X-Device-Id:  YD32S3-3C6108A1
  X-Timestamp:  1756376463
  X-Nonce:      b7f1c2
  X-Sign:       3f9a...c1
  X-Fw:         v0.9.3
```

**GET（如拉标定）的签名**：`body` 为空字符串（`bodyHash = sha256("")`），`dedupId` 传空串 `""`，其余不变。这样**同一套签名代码**覆盖 GET/POST。

**⚠️ 必须对"实际发出的 body 字节"求哈希**：ESP32 先序列化出 JSON 字符串 → 用**同一个字符串**既算 `bodyHash` 又作为请求体发送。后端侧必须用 **raw body**（`raw-body`/`Buffer`）计算，**不要** `JSON.stringify(解析后的对象)`（键序/空格/数字格式不一致 → 签名必然失败）。

### 8.3 密钥生命周期（**密钥绝不烧死**）

| 阶段 | 做法 |
|---|---|
| **不烧源码** | `deviceSecret` **不写进 `main.cpp`/`platformio.ini`/Git**；固件里只有"密钥存放位置"和"密钥为空时的行为" |
| **注入时机** | 首次配网成功后 / 出厂工具经串口注入 / 首次绑定流程写入 —— **NVS（`Preferences`）** |
| **服务端只存哈希** | `devices.secretHash = sha256(deviceSecret + SALT)`；**明文 secret 永不落库、永不入日志** |
| **验签方式** | 设备端与后端都派生 `derivedKey = sha256(deviceSecret + KEY_PEPPER)` 再做 HMAC —— 库中无明文仍可验签 |
| **轮换** | 泄漏/疑似泄漏 → `secretVersion++`，新密钥写入设备 NVS（可经内嵌页 `/device/secret` 路由，需本地物理可达）→ 旧版本短期并存后禁用 |
| **未注入时的行为** | 密钥为空 → **不上传**，内嵌页显示"未激活"，串口打印提示；避免用默认密钥上公网 |
| **绝不放在设备上的东西** | ❌ 小程序 AppSecret、❌ 数据库口令、❌ JWT 签名密钥、❌ 对象存储永久密钥 |

### 8.4 服务端校验顺序

见 §7.2 的 7 步。补充实现要点：

```text
· 常量时间比较：crypto.timingSafeEqual(Buffer.from(want), Buffer.from(sign))
  （先比长度，长度不等直接拒绝，避免 timingSafeEqual 抛异常）
· nonce 去重：INSERT INTO device_nonces ... ON CONFLICT DO NOTHING RETURNING 1
  返回 0 行 ⇒ nonce 重复 ⇒ 4014（比"先查后写"无竞态）
· 限流：按 deviceId ≤ 60 次/分钟、≤ 2000 次/天；超限 4290
· 体积：反向代理层限 64KB（§4.1）；curve 点数 ≤ 4000
· 归因：openid/ownerUid 一律由 devices 反查，**不信任请求体里的归属字段**
```

### 8.5 断网策略（**环形队列 + NVS 持久化 + 指数退避 + dedupId 幂等**）

```text
                    ┌──────────── 实验结束 (FRAME_STATUS=3 DONE) ────────────┐
                    ▼                                                        │
        ┌───────────────────────────┐                                        │
        │ 组实验摘要 summary        │  dedupId = deviceId-bootCount-seq      │
        │ (四维/评分/时间/抽稀曲线) │  bootCount: NVS 递增（防重启重复）      │
        └───────────┬───────────────┘  seq     : 本轮递增（防同一次多次入队）│
                    ▼                                                        │
        ┌───────────────────────────┐   队列满(默认 32 条)                    │
        │ 环形队列 push（RAM/NVS）  │ ─────────────► 丢弃最旧 + droppedCount++ ┘
        └───────────┬───────────────┘
                    ▼
       ┌─────────────────────────────────────────┐
       │ WiFi 已连? & uploadEnabled? & 时间已同步?│──否──► 等下一轮 loop()
       └───────────┬─────────────────────────────┘
                   ▼ 是
       ┌─────────────────────────────────────────┐
       │ HTTPS POST /api/v1/device/upload (超时5–8s)│
       │ 头带 X-Sign / X-Timestamp / X-Nonce      │
       └───────┬─────────────────────┬───────────┘
         2xx & code=0          失败/超时/网络断/4013时间偏移
               │                     │
               ▼                     ▼
       ┌───────────────┐   ┌──────────────────────────────────────────┐
       │ 队列 pop      │   │ 退避重试: 1s→2s→5s→15s→60s→300s(封顶)     │
       │ lastOkAt 更新 │   │ 每条最多重试 8 次；仍失败标 failed 留队列 │
       │ dropped 清零  │   │ （掉电不丢，下轮继续）                    │
       └───────────────┘   └──────────────────────────────────────────┘
```

| 机制 | 设计 |
|---|---|
| **缓存介质** | 元数据 + 摘要（不含曲线）存 **NVS**（`Preferences`；掉电不丢；≤32 条 × ~300B ≈ 10KB，远小于 NVS 分区）；曲线先写 **PSRAM** 临时缓冲，上传成功即释放（8MB PSRAM 充足） |
| **队列长度** | 默认 **32 条**，可配置；满则丢最旧 + `droppedCount++` |
| **重传** | 指数退避 `1/2/5/15/60/300s` 封顶；**仅在 WiFi 已连且时间已同步时**尝试；在**独立任务/非阻塞状态机**里做，`loop()` 不阻塞超过 ~50ms |
| **幂等** | 设备侧 `dedupId` 唯一；服务端 `dedupId` **唯一索引 + `ON CONFLICT DO NOTHING`** → 网络抖动/半成功**不会产生重复记录**，重发返回 `dedup:true` |
| **4013 特殊处理** | 时间偏移过大时**不要无脑重试**：先重新 SNTP 同步，再重算 `ts` 重签后重试（否则永远失败） |
| **掉电保护** | `push` 时立即落 NVS；`pop` 只在收到 `code=0` 之后执行 |
| **可观测** | 内嵌页显示 `队列深度 / dropped / 最后成功时间 / 最后错误码`；串口打印同一信息（复用现有 `WebServer` 加一条 `GET /cloud/status`） |

### 8.6 上传频率与数据粒度

| 策略 | 推荐 | 理由 |
|---|---|---|
| **每个实验一次**（`STATE_DONE` 触发） | ⭐**推荐（M1 起）** | 数据量最小、语义清晰、天然去重；与"一次实验一条 `experiments`"一一对应 |
| 周期上传（每 10s 一批） | ❌ MVP 不做 | 写库次数×N，且需要额外的会话/分段模型 |
| 实时流（常连 WSS 上云） | ❌ MVP 不做，M4 可选（§7.8） | 真正的毫秒级实时由设备内嵌页承担 |
| 曲线粒度 | **抽稀到 20–50Hz**（LTTB 或等间隔 min/max 保峰） | 单实验 5–30KB；**原始 500Hz/1kHz 不上传** |
| 四维/评分 | 每次实验 1 组（末值；可选按阶段各 1 组） | 与 `MetricsFrame`/`FRAME_SCORE` 语义一致 |
| **去重键生成** | `dedupId = deviceId + "-" + bootCount(6位) + "-" + seq(4位)` | `bootCount` 防重启重复；`seq` 防同一次多次入队 |

> `dedupId` 示例：`YD32S3-3C6108A1-000042-0007`（第 42 次启动的第 7 次实验）。

### 8.7 时间戳：相对 T0 与绝对时间**都存**

| 字段 | 类型 | 来源 | 用途 |
|---|---|---|---|
| `t0_relative_duration_s` | number | STM32（`TouchFrame.t` 末值，秒） | 与设备侧曲线/力控轨迹**严格对齐**（复现实验） |
| 曲线内每点 `t` | number | 沿用 `TouchFrame.t`（相对 T0 秒） | **曲线横轴** |
| `startedAt` / `endedAt` | timestamptz | **ESP32 SNTP 绝对时间** | 列表排序、按时间筛选、跨设备比较 |
| `timeSource` | text | `device` / `estimated` / `server` | 标明上面两个时间的可信度 |
| `createdAt` | timestamptz | **服务端 `now()`** | 权威接收时间，**不受设备时钟造假影响** |

**退化策略**：SNTP 未同步（无外网/DNS 失败）→ `startedAt = createdAt - duration`（服务端回算），`timeSource = "estimated"`，前端列表显示"≈"标记。

**曲线横轴为什么用相对 T0**：STM32 的 T0 是实验开始时刻，力的加载/卸载相位与位移轨迹都必须与它对齐；用绝对时间会把设备时钟抖动引入曲线分析。绝对时间只用于"这条记录是什么时候做的"。

## 9. 客户端接入

### 9.1 各端接入方式

| 端 | 接入方式 | 鉴权 | 跨域/白名单 | 备注 |
|---|---|---|---|---|
| **网页（浏览器 H5）** | `fetch` 直连 REST + `EventSource`(SSE) 或 `WebSocket` | JWT（登录后存内存/sessionStorage） | **需要服务端配 CORS**（§9.2） | 局域网或公网均可 |
| **PC 客户端**（Electron / Python 脚本 / CLI） | REST + WSS | JWT 或 `X-Api-Key` | 无 CORS 限制（非浏览器） | Python 侧 `requests` + `websockets` |
| **微信小程序** | `wx.request` / `wx.connectSocket` / `wx.uploadFile` | JWT（`wx.login` → `wechat-login`） | **域名必须在微信「服务器域名」白名单 + 已备案** | 与云开发方案最大差别（§9.3） |

### 9.2 网页/PC 直连 REST（**CORS 必须正确配置**）

```text
· 允许的来源白名单（不要用 *，尤其带 Cookie/凭据时）：
    Access-Control-Allow-Origin: https://app.example.com
    （本地开发可加 http://localhost:5173，但生产要收紧）
· 预检：对带 Authorization / 自定义头（X-Api-Key）的请求，浏览器会先发 OPTIONS
    → 必须响应 204 + Access-Control-Allow-Headers: authorization,content-type,x-api-key
    → Access-Control-Allow-Methods: GET,POST,PATCH,DELETE,OPTIONS
    → Access-Control-Max-Age: 600
· 凭据：用 JWT 放 Authorization 头（而非 Cookie）⇒ 无需 Allow-Credentials，也避免 CSRF
· 局域网注意：若网页是 HTTPS（如内嵌页被 https 包着）而后端是 http://192.168.x.x:8080
    → 浏览器会拦「混合内容」（Mixed Content）。解决：后端也上 HTTPS（自签/内网 CA），
      或网页也用 http（纯局域网场景通常 OK）
· 缓存：列表接口加 Cache-Control: private, max-age=5；详情加 ETag（可选）
```

**CORS 示例（Fastify）**

```js
await app.register(require('@fastify/cors'), {
  origin: ['https://app.example.com', 'http://localhost:5173'],
  methods: ['GET','POST','PATCH','DELETE','OPTIONS'],
  allowedHeaders: ['authorization','content-type','x-api-key'],
  maxAge: 600,
});
```

### 9.3 小程序接入（**与微信云开发的根本差别，务必看清**）

| 维度 | 微信云开发方案 | 自建后端方案 |
|---|---|---|
| 调用方式 | `wx.cloud.callFunction(...)` —— **内网调用，无需配置域名白名单、无需备案** | `wx.request({ url: 'https://api.example.com/...' })` —— **必须**把域名加入微信「服务器域名」白名单，且域名**必须已 ICP 备案** |
| 鉴权 | 云开发自动注入 `OPENID`，**无需自建登录** | 需 `wx.login` 拿 code → `POST /api/v1/auth/wechat-login` → 服务端 `code2session` → 返回 JWT |
| WebSocket | `db.watch` 实时推送 | `wx.connectSocket({ url: 'wss://api.example.com/api/v1/ws' })`，同样受白名单限制 |
| 局域网设备 | 真机连不上（本就需要云中转） | 真机同样连不上 → 本地实时仍归设备网页 |
| 上线门槛 | 低（无域名/无备案） | **高（域名 + 备案 1–3 周 + 白名单）** |

**小程序端配置清单**

```text
1) 微信公众平台 → 开发管理 → 服务器域名：
     request 合法域名 : https://api.example.com
     socket  合法域名 : wss://api.example.com
     downloadFile     : https://api.example.com     （详情页下载抽稀曲线）
     uploadFile       : https://api.example.com     （若要客户端上传）
   —— 域名必须：已备案 + HTTPS 有效证书 + 默认 443 端口 + 不能是 IP
2) app.js 或 utils/api.js 里做统一封装（统一 baseURL / token 注入 / 错误码映射 / 401 刷新重试）
3) 域名白名单修改有月度次数限制 → 先规划好（如 api.example.com 一个域名搞定全部）
4) 小程序不支持 EventSource（SSE）→ 实时用轮询 /api/v1/experiments/latest（2–5s）或 connectSocket
5) 开发期：开发者工具勾选"不校验合法域名"可连 http://192.168.x.x 调试；**真机无效**
```

**⚠️ 关键结论**：如果你**一定要小程序真机 + 不想备案**，只有两条路：
- **回退微信云开发**（免备案，但个人环境可能没有 HTTP 云函数入口）；
- **混合代理**：小程序 → `wx.cloud.callFunction`（免备案） → 云函数转发到你的自建后端（§12.3）。

### 9.4 多端如何连"同一个后端"

```text
                        ┌──────────────────────────────────────┐
                        │  自建后端  https://api.example.com    │
                        │  统一 REST + WSS + JWT/HMAC           │
                        └───────▲──────────▲──────────▲────────┘
                                │          │          │
              ┌─────────────────┘          │          └─────────────────┐
              │                            │                            │
   ┌──────────┴──────────┐      ┌──────────┴──────────┐      ┌──────────┴──────────┐
   │ 网页 (H5)            │      │ PC 客户端            │      │ 微信小程序           │
   │ fetch + SSE/WSS      │      │ REST + WSS           │      │ wx.request +         │
   │ JWT (账号密码)       │      │ JWT / X-Api-Key      │      │ wx.connectSocket     │
   │ CORS 白名单          │      │ 无 CORS              │      │ 域名白名单 + 备案    │
   └──────────────────────┘      └──────────────────────┘      └──────────────────────┘
              └────────────────────────────┬────────────────────────────┘
                                           │  同一套接口、同一张表、同一套 field 名
                                   数据天然一致、可互相引用
```

- **字段名一致** ⇒ 三端用同一份"记录 → 视图"的映射逻辑（甚至可共享一个 JS/TS 类型定义包）。
- **鉴权统一**：小程序用 `wechat-login` 换 JWT，网页/PC 用 `login` 换 JWT，之后**所有请求都是同一种 `Authorization: Bearer`**，后端只有一套权限中间件。
- **数据归属统一**：`ownerUid` / `openid` 至少一个非空；`scope=mine` 的服务端过滤对三端一致。

## 10. 与"设备自带网页（产品形态 A）"共存

> **原则：本地实时归设备网页，自建后端负责归档 / 多端 / 标定下发。产品形态 A 不做减法。**

| 能力 | 设备内嵌页（产品形态 A，**原样保留**） | 自建后端（本方案，**新增**） |
|---|---|---|
| 实时曲线/四维/评分 | ⭐**毫秒级**（`ws://<ip>:81` 直连） | 准实时（事件推送/轮询，2–5s） |
| 离线可用 | ⭐**强**（同 WiFi 即可，不依赖外网） | 局域网部署时也强；公网部署弱 |
| 控制（ARM/START/STOP/RESET） | ⭐**支持**（`FRAME_CMD`） | 本地可；**远程控制**需新增下行通道（M4 可选，需评估安全） |
| WiFi 配网 | ⭐**门户配网（唯一入口）** | 不参与配网（避免引入 BLE 的复杂度） |
| 历史记录 | 无（除非加 SD 卡） | ⭐**完整历史**（多设备/多用户/跨时间） |
| 曲线对比/雷达图 | 仅当次 | ⭐跨实验/跨布料/跨设备对比 |
| 标定/权重下发 | 只读本地硬编码默认值 | ⭐**云端标定 → NVS 下发**（无需重烧固件） |
| 数据导出/分享 | 无 | ⭐CSV/JSON 导出、报告生成 |
| 成本 | 0 | 服务器/域名/备案（或 0，若纯局域网） |

**实现上的"只加不改"**（与云开发方案 §10.2 完全一致，**同一份 ESP32 新增代码可两用**）：

| 新增（ESP32，只加不改） | 作用 |
|---|---|
| `cloud_client.cpp/.h` | `WiFiClientSecure` + `HTTPClient`，HTTPS POST JSON（baseURL 从 NVS 读） |
| `upload_queue.cpp/.h` | 环形队列 + NVS 持久化 + 退避重传 |
| `hmac_sign.cpp/.h` | HMAC-SHA256（mbedtls） |
| `device_config.cpp/.h` | NVS 存 `deviceId` / `deviceSecret` / `claimCode` / `apiBase` / 标定缓存 |
| `exp_summary.cpp/.h` | 由 `g_metrics` / `g_score` / `g_state` 组实验摘要 |
| `curve_downsample.cpp/.h` | 曲线抽稀（LTTB / min-max）到 20–50Hz |
| `sntp_time.cpp/.h` | 绝对时间（TLS 握手的前提，§4.3） |
| 内嵌页新路由 | `GET /cloud/status`（队列深度/最后上传结果）、`POST /cloud/calibration`（接收下发标定） |
| `loop()` 里新增调用 | `cloudTask()` —— **非阻塞**状态机；不改 `pollUart()` / `dispatchFrame()` |

**保持不变（零改动）**：`src/protocol.h`（`TouchFrame`/`MetricsFrame`/`FrameType`/`ExpState`/`crc8_over`/`build_frame`）、UART 解析（`pollUart`/`dispatchFrame`）、门户配网（`AP_SSID`=`YD-ESP32S3` / `192.168.4.1` / DNS 劫持 / `force` 标志 / `CONFIG_HTML`）、本地实时（`WebSocketsServer(81)` / `pushFrame|pushMetrics|pushScore|pushState` / `INDEX_HTML`）、mDNS `datatouch.local`、DEMO 模式、`handleCommand()`、STM32 全部代码。

> **一句话**：上云 = 在 ESP32 的 `loop()` 里新增一条"实验结束时 HTTPS POST"的旁路，加上一个全新的自建后端。`protocol.h` 不动、STM32 不动、配网/WebSocket/显示页不动。

## 11. 部署与运维

### 11.1 部署方式

| 方式 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|
| **Docker Compose** | 一键起 API + PostgreSQL + Caddy；环境隔离；迁移=复制 `compose.yml` + 卷 | 需装 Docker | ⭐**首选**（本地/公网同一份配置） |
| 裸机 + systemd | 无 Docker 依赖；资源占用略低 | 依赖管理/升级麻烦 | 树莓派/极简环境 |
| PM2（Node.js） | `pm2 start app.js` + `pm2 startup` 开机自启 + 日志轮转 | 只管理 Node，DB/Caddy 另配 | 快速原型 |
| 云托管 / K8s | 弹性、可观测 | **对本项目严重过度设计** | 不推荐 |

| **业务看板** | 简单 SQL 视图：日实验数、按布料评分分布、设备在线率 | 也可只在网页端做一个"统计"页 |

### 11.5 安全加固（公网部署必做）

| 层面 | 措施 |
|---|---|
| **SSH** | 仅密钥登录（`PasswordAuthentication no`）、禁 root 直登、改非标端口（可选）、`fail2ban` |
| **防火墙** | `ufw default deny incoming`；只放 `22/tcp`、`80/tcp`、`443/tcp`（本地部署只放 22 + 内网段） |
| **数据库** | **绝不映射端口到公网**（§11.2 已用 `127.0.0.1` / compose 内部网络）；独立低权限 DB 用户；禁用远程超级用户 |
| **容器** | 非 root 用户运行；只读根文件系统（可选）；镜像固定 tag（不用 `latest`）；`docker compose pull` 定期更新 |
| **应用** | 请求体大小限制（64KB）；**全部输入校验**（zod/JSON Schema，`composite∈[0,100]`、四维范围、`duration∈(0,3600]`）；SQL 用参数化查询/ORM；**响应绝不带堆栈与密钥** |
| **限流/防刷** | 按 `deviceId`（60/分、2000/天）+ 按 IP（100/分）双层限流；`devices.uploadEnabled=false` 一键停用；`status=disabled` 拒绝 |
| **防重放** | HMAC + ±300s 时间窗 + nonce 去重表（§7.2/§8.4） |
| **越权** | `scope=mine` 服务端强制注入归属过滤；详情接口先查库比对归属；`fields` 白名单（**永不返回 `secretHash`**） |
| **凭据管理** | `.env` 不进 Git（`.gitignore`）；`JWT_SECRET`/`KEY_PEPPER`/`DB_PASSWORD` 用 `openssl rand -hex 32` 生成；定期轮换；不在日志里打印 |
| **TLS** | 只允许 TLS1.2+；HSTS；证书自动续期 + 到期告警；Caddy 证书目录必须持久化 |
| **系统** | `unattended-upgrades` 自动安全更新；关闭未用服务；`lynis` 自检（可选） |
| **小程序端** | 不在客户端存 AppSecret；token 存 `wx.setStorageSync`（非敏感）+ 过期刷新 |
| **设备端** | 密钥只存 NVS（§8.3）；生产固件**不要**用 `setInsecure()`（§4.3） |
| **数据合规** | 只采集设备/实验数据（力、位移、四维、评分、布料名），不采集个人信息；提供"删除我的数据"接口；隐私说明 |

## 12. 三方案对比与选型建议

### 12.1 对比表

| 维度 | **A. 微信云开发** | **B. 自建后端（本方案）** | **C. 腾讯云开发 CloudBase** |
|---|---|---|---|
| **客户端范围** | 小程序（主）+ 云开发 Web SDK 可做 H5；**PC 原生端支持弱** | ★**网页 / PC / 小程序 / 脚本全都能连**（同一套 REST + WSS） | 小程序 + Web（`@cloudbase/js-sdk`）+ 云函数；原生端需走 HTTP 访问服务 |
| **要不要域名备案** | **不要**（云开发提供域名，`wx.cloud.callFunction` 免白名单） | **小程序真机：要（必须备案 + 白名单）**；<br>仅网页/PC：内地公网仍建议备案；**局域网：不要** | 用默认域名（`*.tcloudbase.com`）时通常不需要自备域名；<br>**要用自定义域名 + 小程序真机 → 仍需备案**（以官方/控制台为准） |
| **运维量** | ★**极低**（无服务器；只管云函数与集合） | **中–高**：服务器、TLS 续期、DB 备份、监控、防火墙、升级 | **低**：无服务器运维；但仍要管环境/云函数/安全规则/计费 |
| **成本** | 套餐/按量，历史有免费档；量小时 ≈ **¥0–几十/年**；额度政策会变 | 本地 **≈¥0–400/年**；公网 **首年 ¥150–500，常规 ¥400–800/年** | 按量/套餐，与 A 同一量级；量小时 ≈ **¥0–几十/年** |
| **数据归属** | 在**你自己的小程序云开发环境**（腾讯云托管），不经第三方 | ★**完全在自己手里**（自己的服务器/磁盘；可自由导出、迁移、离线分析） | 在**你自己的 CloudBase 环境**（腾讯云托管） |
| **设备上云难度** | **低**（一个 HTTPS POST 到 HTTP 云函数）——**但个人环境可能没有「HTTP 云函数」入口**（本方案起因） | **低–中**（HTTPS POST 到自己的域名；需处理 TLS 根证书/时间同步；自建域名与备案是额外步骤） | **低**（云函数 + HTTP 访问服务）；入口名称/形态与微信云开发类似，个人可用性需在控制台确认 |
| **鉴权** | HMAC（自建）+ 云函数 `OPENID` 自动注入 | HMAC（设备）+ JWT（用户，**需自建登录**） | HMAC + CloudBase 身份认证（小程序可自动拿 openid） |
| **实时能力** | `db.watch` 推送（原生）；小程序友好 | WSS / SSE 自建，**网页/PC 体验最好**；小程序不支持 SSE → 轮询 | `db.watch` / 云函数 + WSS |
| **本地/离线** | ❌ 依赖外网 | ★**可完全局域网部署**（离线可用） | ❌ 依赖外网 |
| **多平台绑定风险** | 绑微信生态 | ★**无绑定**，随时迁云/迁机 | 绑腾讯云 |
| **适合场景** | 只做小程序、想最快上线、不想碰服务器/备案 | **多端（尤其网页/PC）+ 数据自控 + 要局域网离线 + 想要不被平台绑** | 想在腾讯云生态里少运维，同时保留 Web 端与自定义逻辑 |
| **本项目适配度** | 高（若环境有 HTTP 云函数） | ★**高（尤其"没有 HTTP 云函数入口"时是唯一自主选项）** | 中–高（需确认控制台入口与个人主体可用性） |

### 12.2 设备端代码可复用性（重要）

因为两方案的**请求体 JSON、签名公式、错误码、上传触发时机、断网策略**完全一致，**ESP32 侧只需要改 3 个东西**：

```text
① apiBase      : 云函数 HTTPS 地址  →  https://api.example.com/api/v1/device/upload
② TLS 校验     : 云开发域名（通常用 setInsecure 或内置其根 CA）
                 →  Let's Encrypt 的 ISRG Root X1（或 MVP 先 setInsecure）
③ 标定拉取     : GET getCalibration  →  GET /api/v1/calibration?deviceId=…
```

⇒ **推荐做法**：`apiBase` 与证书策略做成 **NVS 可配**，于是"先用云开发跑通、再切自建后端"或反之，**都不需要重新设计上传模块**。这也是两份文档刻意保持字段一致的原因。

### 12.3 混合架构 B+（小程序→云函数代理→自建后端）（**"没有 HTTP 云函数入口"时的最优解**）

```text
小程序 ──wx.cloud.callFunction('proxyToBackend', {path, method, body})──► 微信云开发云函数（免备案）
                                                                              │ HTTPS（服务端→服务端）
                                                                              ▼
                                                              自建后端  https://api.example.com
                                                              （查库/写库/文件存储）
网页/PC ──────────────────── 直连 HTTPS ───────────────────────────────────► 同上
ESP32  ───────────────── HTTPS POST /api/v1/device/upload ────────────────► 同上
```

| 优点 | 代价 |
|---|---|
| 小程序**真机免备案、免白名单**（走 `callFunction` 内网通道） | 需一个小程序云开发环境（个人主体可开）+ 一个"转发云函数" |
| 小程序 / 网页 / PC **共用同一张表、同一套业务逻辑** | 小程序侧多一跳（延迟 +50–200ms，可接受） |
| 不需要 HTTP 云函数入口（`callFunction` 是基础能力） | 云函数需持 `BACKEND_TOKEN`（放云函数环境变量，不进代码） |
| 备案可暂缓（但网页/PC 走公网域名仍建议备案；不备案则网页只能用局域网/香港） | 云函数出网流量计入云开发额度（量小可忽略） |

> **混合架构 B+ 是本项目"个人电脑、无 HTTP 云函数"情形下的推荐落地路径**：设备直奔自建后端（最简），小程序走云函数代理（免备案）。

### 12.4 明确选型建议

| 你的情形 | 推荐 | 理由 |
|---|---|---|
| **① 只要网页/PC，实验室单机，最省事** | ★ **自建后端（本地部署，SQLite 或 PostgreSQL）** | 零服务器成本、零备案、离线可用、数据在自己电脑 |
| **② 要小程序真机 + 环境**有** HTTP 云函数入口** | **微信云开发**（回退主方案） | 免备案、免运维、MVP 最快；设备端代码不用改 |
| **③ 要小程序真机 + 环境**没有** HTTP 云函数入口**（← 你的情形） | ★ **混合架构 B+**（小程序→云函数代理→自建后端），公网用轻量服务器 + 域名 + 备案（备案与开发并行） | 绕开入口缺失；多端共用一套数据；备案只是时间问题不是阻塞 |
| **④ 要小程序真机，但坚决不备案、也不碰云开发** | ❌ 无解。必须回到 ②/③，或接受"小程序只能连局域网 IP（真机不可用）" | 微信硬约束（《产品端方案对比.md》§1） |
| **⑤ 要跨设备/多用户/长期演进，且不想被平台绑** | ★ **自建后端（公网）**，CloudBase 作为备选 | 数据自主、接口自主、可随时迁机/迁云 |
| **⑥ 完全不想碰服务器与备案，且能用云开发** | **微信云开发** 或 **腾讯云 CloudBase** | 运维量为零；代价是额度政策与平台绑定 |
| **⑦ 要最稳的现场演示（答辩/验收）** | **设备内嵌页（产品形态 A）+ 本地自建后端** | 不依赖外网、不依赖备案进度、延迟最低；**风险最小** |

**针对你（个人电脑、可能没有 HTTP 云函数入口、要多端）的最终建议**：

```text
第一优先：M1 先用【本地自建后端】把"设备→后端→库里一条记录→网页看到"跑通
          （当天可完成，零成本、零备案、零外部依赖）

并行推进：① 买域名 + 内地轻量服务器 → 提交 ICP 备案（1–3 周，越早越好）
          ② 若之后确认云开发环境有 HTTP 云函数，可随时切回云开发（设备端只改 URL）

备案期间：网页/PC 用本地局域网后端；如需外网临时查看，用 Cloudflare Tunnel / frp
          （不用于小程序）

备案完成后：把本地后端迁到云服务器（docker compose 复制即可），
            小程序走混合架构 B+（云函数代理） 或 直接白名单直连（二选一）
```

## 13. 分阶段 MVP

### M1 — 后端跑通 + 设备上传 + 一条记录（**目标：打通"设备→自建后端→库里有数据"**）

**任务**

1. 定部署形态（本地 / 公网，§2）；起 `docker compose`（PostgreSQL + API + Caddy，§11.2）；
2. 建表（§6.3 的 SQL）+ 索引 + `dedupId` 唯一约束；
3. 实现 `POST /api/v1/device/upload`：**先不验签**，只做结构校验 + 幂等 upsert + 落库；
4. 实现 `GET /api/v1/health`；
5. ESP32：新增 `WiFiClientSecure` + `HTTPClient` 分支，在 `STATE_DONE`（**DEMO 模式即可**）POST 一条 JSON；`apiBase` 存 NVS；
6. 用 `curl` 手工造一条上传请求，确认落库。

**验收标准**

- [ ] `docker compose up -d` 后 `GET /api/v1/health` 返回 `{"status":"ok","db":"ok"}`
- [ ] `curl` 手造上传请求 → `code:0`，`experiments` 表出现 1 行
- [ ] **同一条 `dedupId` 重发 3 次 → 库里仍然只有 1 行**（幂等生效，`dedup:true`）
- [ ] ESP32 串口打印 `POST 200, code=0, _id=xxx`
- [ ] 云端存的四维/评分与 ESP32 内嵌页显示的**一致**（差 ≤ 0.1）
- [ ] 拔网 1 次后重连，能自动补传（队列 + 退避生效）
- [ ] **未改动** `protocol.h`、STM32 代码、现有配网/WebSocket/显示页
- [ ] 数据文件落盘位置明确，`pg_dump` 手工备份成功一次

### M2 — 查询 API + 网页/PC 看历史（曲线 + 雷达图）

**任务**

1. `GET /api/v1/experiments`（分页/筛选/`fields`/`scope=mine`）+ `GET /{id}` + `GET /latest`；
2. 文件存储：曲线抽稀（20–50Hz）→ 落盘 `curves/{dedupId}.json` → `curveFileId`；`GET /api/v1/files/curves/{id}` 受保护下发；
3. CORS 白名单 + 简易鉴权（MVP 可用静态 `API_TOKEN`，或直接上 JWT）；
4. 网页/PC：历史列表 + 详情页（曲线 canvas + 五边形雷达图 + 评分卡 + 四维 + 元数据）；
5. ESP32 侧补曲线抽稀与上传（或先只传摘要）；
6. 加 WSS/SSE 广播 `experiment.created`（网页自动刷新），并保留轮询兜底。

**验收标准**

- [ ] `curl` 分页/时间区间/评分区间筛选结果正确，`pageSize` 上限生效
- [ ] 网页能列出最近 20 条，加载 < 2s
- [ ] 详情页曲线与雷达图与**设备内嵌页同源同形**（同一实验评分差 ≤ 0.1）
- [ ] 未带 token 的请求返回 401；带他人 token 查询返回**只有自己的数据**
- [ ] CORS：白名单外的 Origin 被拒（`curl -H "Origin: https://evil.com"` 无 `Allow-Origin` 头）
- [ ] 新实验上传后，已打开的历史页在 ≤5s 内自动出现新记录
- [ ] 列表接口响应**不含** `secretHash` 等敏感字段

### M3 — 标定 / 权重下发

**任务**

1. `GET/POST /api/v1/calibration`（取值优先级 + 参考布料算 min/max + 5% 余量 + 权重和为 1 校验 + 旧版置 `isActive=false`，靠部分唯一索引保证）；
2. `fabrics` 表 + 参考布料标记（`isReference`/`refRole`）+ 参考集管理页；
3. ESP32：启动/上报前 `GET /api/v1/calibration?deviceId=…`（HMAC）→ 存 NVS；内嵌页 `WEIGHTS`/`RANGE` **改为读 NVS**（保留硬编码默认值兜底）；**正式以 STM32 为准，标定值最终需同步/转发到 STM32**；
4. `experiments` 记录 `calibrationVersion` + `weights` 快照；管理端"预览"（用新标定重算历史若干条的评分变化）。

**验收标准**

- [ ] 改权重/区间后，**新实验**的云端 `composite` 与设备内嵌页评分一致（差 ≤ 0.1）
- [ ] 任一历史记录都能看到它用的 `calibrationVersion` 与 `weights` 快照（可复现）
- [ ] 设备断网时用 NVS 里的上次标定，本地仍能正常算/显示
- [ ] **标定下发后无需重新烧录固件**
- [ ] 同一 `scope+deviceId` 下永远只有 1 条 `isActive=true`（并发提交也成立）
- [ ] 权重和 ≠ 1 时返回 `4103`；参考布料缺 `refMetrics` 时返回 `4102`

### M4 — 多设备 / 多用户（+ 可选实时直播）

**任务**

1. `users` 表 + 完整 JWT 体系 + `POST /api/v1/auth/wechat-login`（服务端持 AppSecret 调 `code2session`）+ 网页/PC 登录；
2. 绑定体系：`claimCode` 生成与展示（内嵌页）→ `POST /api/v1/devices/bind`（事务 + 防抢绑）→ `GET /api/v1/devices` → 解绑；
3. 设备密钥体系上线：`deviceSecret` 注入 NVS + HMAC 验签 + nonce 时间窗（§8.2–8.4）；
4. 限流 + 审计日志 + "删除我的数据" + 数据导出（CSV/JSON）；
5. 多设备切换、同布料跨设备对比；`shareOpenids` 共享；
6. （可选）WSS/SSE 实时直播：设备在 `RUNNING` 时周期上报四维/抽稀点，后端推给客户端。

**验收标准**

- [ ] 用绑定码能把设备绑到自己账号；换账号绑定返回 `4003`；绑定码过期返回 `4002`
- [ ] 篡改 body / 重用签名 / 时间偏移 > 300s / 重用 nonce 分别返回 `4015 / 4014 / 4013`（**四项全部实测**）
- [ ] 用未注册的 `deviceId` 上传返回 `4010`；`uploadEnabled=false` 时返回 `4011`
- [ ] 用户 A 登录后**看不到**用户 B 的数据；解绑后不再能读取该设备数据；共享用户只读
- [ ] 两台设备数据互不混淆，列表可按设备筛选
- [ ] `secretVersion` 可轮换：轮换后旧密钥失效、新密钥上传成功
- [ ] （选做）实时推送延迟 < 2s；客户端断开后服务端 60s 内回收连接

## 14. 风险与注意

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| **R1** | **ICP 备案耗时长**（1–3 周，可能退回补材料） | 小程序真机上线延期 | **第一天就启动备案**；M1/M2 用本地或香港环境并行开发；M3 前完成 |
| **R2** | **公网暴露被攻击**（扫描、爆破、刷接口、注入） | 数据泄漏/被篡改/资源耗尽 | §11.5 全套：SSH 密钥、ufw、只暴露反代、DB 不对外、限流、输入校验、参数化查询；**不用默认口令** |
| **R3** | **断网**导致设备数据丢失 | 实验白做 | 环形队列 + NVS 持久化 + 指数退避 + `dedupId` 幂等（§8.5）；队列深度内嵌页可见 |
| **R4** | **数据量/存储增长** | 磁盘满、备份变慢、查询变慢 | 只存摘要 + 抽稀曲线；**原始高频数据不上传**；曲线按策略清理（§15-P6）；磁盘 >85% 告警；列表默认不带曲线 |
| **R5** | **HTTPS 证书在嵌入式端的坑** | 上传全部失败（且难定位） | **时间同步优先于握手**（§4.3-1）；**不用指纹 pinning**（90 天轮换）；用根 CA；`setBufferSizes`；根 CA 过期留升级路径；上传失败在串口/内嵌页给出**明确错误码**（TLS 错误 vs 业务错误码） |
| **R6** | **单机宕机**（云服务器/家里断电） | 服务不可用、可能丢数据 | 每日 `pg_dump` + 异地同步；健康检查 + 告警；本地部署接 UPS；关键数据本地留存；紧急时可切回设备内嵌页（本地实时不受影响） |
| **R7** | **证书自动续期失败**（Caddy 证书目录丢失/端口被占/ACME 限流） | 到期后 HTTPS 全挂（小程序立刻不可用） | Caddy 的 `/data` 必须持久化；"剩余 <15 天"告警；续期失败告警；备用云厂商 DV 证书 |
| **R8** | **备份从未恢复演练** | 真出事时备份不可用 | 每季度在另一台机器演练 `pg_restore` + 起服务 |
| **R9** | **家宽无法备案 / 无公网 IP / 80·443 被封** | 本地部署无法对外，小程序彻底不可用 | 家宽只做局域网；对外用云服务器（§2.5）；或 Cloudflare Tunnel/frp 仅给网页/PC |
| **R10** | **密钥泄漏**（设备端或服务端） | 伪造数据/刷库 | 每设备独立密钥；只存 `secretHash`；`secretVersion` 轮换；密钥不进固件源码/Git；`KEY_PEPPER` 独立存服务端环境变量 |
| **R11** | **设备时间不准/未同步** | `startedAt` 错乱、列表排序错 | 双时间戳（相对 T0 + 绝对时间）+ `timeSource` 标记 + 服务端 `createdAt` 权威（§8.7）；`4013` 触发重新 SNTP 而非盲目重试 |
| **R12** | **`metricsNormalized` 口径**（已裁定：四维在 STM32 归一化 [0,1]、综合评分在 STM32 算，权威值；前端只显示） | 云端评分与设备页不一致、二次归一化 | 用 `metricsNormalized`（恒为 `true`）+ `calibrationVersion` + `weights` 快照显式固化口径（§15-P5） |
| **R13** | **字段命名风格混用**（camelCase vs snake_case） | 设备/客户端/DB 之间映射出错 | 本方案默认**全链路 camelCase**（DB 列名 == JSON 字段名）；若改 snake_case 必须集中映射（§15-P1） |
| **R14** | **小程序与云端"实时"预期错位** | 用户以为能远程毫秒级监控 | **明确分工**（§10）：毫秒级实时=设备内嵌页；远程=准实时（事件推送/轮询 2–5s）；UI 上标注"准实时" |
| **R15** | **上传频率失控**（将来改成周期上报） | 写库/流量/成本上升 | 默认"每实验一次"；周期上报需单独评估（§7.8 的诚实说明）；限流兜底 |
| **R16** | **NVS 写入寿命**（若队列频繁写 NVS） | Flash 磨损 | 队列条目 ≤32 条且只在实验结束时写；曲线放 PSRAM 不写 NVS；避免在循环里反复写 NVS |
| **R17** | **固件/后端版本漂移** | 字段不兼容 | `schemaVersion` 字段 + 后端向后兼容（新增字段可选、不删字段）+ 设备 `X-Fw` 记录 |
| **R18** | **合规风险**（数据出境/隐私） | — | 香港/海外部署时评估数据出境；只采集设备数据；提供删除接口；隐私说明（§11.5） |

## 15. 需要你拍板的点

| # | 待拍板事项 | 选项 | 我的建议 |
|---|---|---|---|
| **P1** | **数据库与命名风格** | (a) **PostgreSQL + camelCase 列名（双引号）+ JSONB**；(b) MySQL 8；(c) **SQLite（纯本地/单机）**；(d) 全部改 snake_case + 接口层映射 | **(a) 公网/多设备；(c) 纯局域网单机**。camelCase 的理由：**DB 列名 == JSON 字段名 == 云开发字段名**，三方案零映射、便于对比与迁移。若你更看重 SQL 惯例，选 (d) 但必须集中写映射层 |
| **P2** | **部署形态：本地 / 公网 / 两者都要** | (a) 只本地（局域网，免备案，小程序不可用）；(b) 只公网（备案 + 小程序可用）；(c) **本地 + 公网双活** | **先 (a) 跑通 M1，并行启动 (b) 的备案**，最终可演进为 (c)。**不要因为等备案而停开发** |
| **P3** | **要不要小程序端**（决定是否必须备案） | (a) 不要，只做网页/PC（**免备案**）；(b) 要，走自建 + 备案 + 白名单；(c) 要，但走 **混合架构 B+**（小程序→云函数→自建后端，免备案） | 若小程序是刚需：**要么 (b) 提前备案，要么 (c) 混合代理**。若只是"顺便想要"，**(a) 最省事** |
| **P4** | **是否需要用户体系** | (a) **单一用户模式**（静态 token，无登录无 users 表）；(b) 完整多用户（JWT + 微信登录 + 账号密码 + 角色） | **M1–M3 用 (a)**（省一半工作量）；**M4 再上 (b)**。多设备隔离可先用 `deviceId` 维度顶着 |
| **P5** | **四维归一化归属**（与云开发方案 P8/D2 同一问题） | **已裁定：STM32 归一化（权威）** —— 四维在 **STM32** 上归一化 `[0,1]`、综合评分(0-100)也在 **STM32** 上算（**权威值**）；前端（网页/PC/小程序）只显示 | `metricsNormalized` **恒为 `true`**；前端 JS 融合仅 DEMO 演示；权重/归一化区间可调整，但**正式以 STM32 为准**（标定值最终需同步/转发到 STM32） |
| **P6** | **是否上传原始文件 / 数据保留策略** | (a) 只传摘要；(b) 摘要 + **抽稀曲线**；(c) 全量原始（数 MB–数十 MB）；保留：永久 / N 个月 / 按容量 | **M1 只传 (a)，M2 加 (b)，(c) 不自动上传（仅手动导出）**；摘要永久保留，**曲线保留 12 个月**后归档/清理（曲线是存储主要消耗） |
| **P7** | **ESP32 的 TLS 证书策略** | (a) `setInsecure()`（快，不安全）；(b) 内置 Let's Encrypt **根 CA（ISRG Root X1）**；(c) 证书指纹（❌ 因 90 天轮换不推荐） | **MVP 用 (a) 联调，上线切 (b)**。**绝不长期用 (c)** |
| **P8** | **`apiBase` 是否做成 NVS 可配**（本地/公网/云开发三态切换） | (a) 编译期宏；(b) **NVS 可配（内嵌页可改）** | **(b)**。这样"本地后端 ↔ 公网后端 ↔ 云开发"切换**不用重烧固件** |
| **P9** | **文件存储：本地磁盘 vs 对象存储** | (a) 本地磁盘（0 成本，最简单）；(b) OSS/COS（多副本、CDN） | **先 (a)**；数据量 >10GB 或多机部署时再切 (b)（`curveFileId` 语义不变，只改读取实现） |
| **P10** | **实时通道形态**（给网页/PC） | (a) 轮询 2–5s；(b) **SSE**；(c) **WebSocket**；(d) 设备常连 WSS 直播（最真但最重） | **M2 用 (a) 轮询 + (b/c) 事件推送**（"有新实验"通知，非流式数据）；**(d) 放 M4 且默认不开** |
| **P11** | **是否需要远程控制**（网页/PC/小程序 → 设备 ARM/START/STOP） | (a) 不做（控制只在设备内嵌页，产品形态 A）；(b) 做（后端→设备下行通道） | **先 (a)**。远程控制需要设备保持长连接 + 命令鉴权 + 安全评估，**M4 之后再议** |
| **P12** | **公共参考布料集** | (a) 每人自建；(b) 全局公共参考集（`isPublic`，管理员维护） | 先 (a)；需要统一评分基准时再引入 (b)（数据模型已预留 `isPublic`/`isReference`） |
| **P13** | **是否用混合架构 B+**（小程序免备案） | (a) 不用，直连 + 备案；(b) 用（需一个小程序云开发环境 + 一个转发云函数） | 若你的云开发环境**能用 `callFunction`**（不用 HTTP 云函数），**混合架构 B+ 是最优解**：小程序免备案、多端共用一套数据 |
