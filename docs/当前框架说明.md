# 织物触觉舒适度检测系统 — ESP32-S3 网关端 当前框架说明

> 本文档**对应当前实际代码**（以 `src/main.cpp`、`src/protocol.h`、`platformio.ini` 为准，不保证与 `README.md` 完全一致，见文末"与 README 的差异"）。
> 设备型号：**YD-ESP32-S3 经典版（ESP32-S3-WROOM-1-N16R8，16MB Flash + 8MB Octal PSRAM）**。
> 框架：Arduino + PlatformIO / VSCode。

---

## 一、项目概述

这是"织物触觉舒适度检测系统"的 **ESP32-S3 网关端**。整个系统分为两层：

- **STM32 端（采集/控制，尚未实现）**：采集六维力传感器（RS485，460800，500Hz，28B 帧，CRC16/MODBUS）、振动（ADXL335）、并驱动 3 台闭环步进电机（UART）；在 STM32 上计算舒适度特征/评分，再通过 **UART** 发给 ESP32。
- **ESP32 端（本工程，网关）**：通过 **UART2** 接收 STM32 的二进制帧 → 解析 → 通过 **WiFi + WebSocket** 把实时曲线、四维特征、综合评分、状态推送给**手机网页**。

**ESP32 的角色只是"通信网关 + 显示"**：它不做采集算法，不做特征/评分计算；只负责转发数据、解析帧、把数据推给网页，并把网页的控制命令（ARM/START/STOP/RESET）回传给 STM32。

### 当前阶段
- ✅ 工程**可编译/烧录**，`DEMO_MODE=true` 时用 **ESP32 内部模拟数据**跑通全部显示（曲线、四维卡片、雷达图、评分、状态机、控制按钮）。
- ❌ **STM32 端还没做**，真实传感器/电机/特征/评分公式未接入。
- 也就是说：**DEMO 演示可用，STM32 未接**。

## 二、系统架构与数据流

### 2.1 目标数据流（真实模式，STM32 接好后）

```
[六维力传感器]─RS485(460800/500Hz/28B帧/CRC16-MODBUS)─┐
[振动 ADXL335] ─模拟量───────────────────────────────┤
[3台闭环步进电机]─UART─┐                             ▼
                       ├──►  STM32(F4VET6)  ──UART2/460800──►  ESP32-S3  ──WiFi+WebSocket──►  手机网页
                       │     采集+控制+算特征/评分        (0xAA 0x55 二进制帧)   │               (实时曲线+四维
                                                                               │                 +雷达图+评分)
                                                                               └─  ARM/START/STOP/RESET ──►  (回传控制)
```

- **六维力 / 振动 / 电机**：都接在 **STM32** 侧，ESP32 完全不参与，也不感知这些总线。
- **STM32 ↔ ESP32**：**UART2**，电平直连（3.3V），默认波特率 **460800**（已统一裁定），8N1，二进制帧（见第五节协议）。
- **ESP32 ↔ 手机/电脑浏览器**：**WiFi + WebSocket**（`ws://<host>:81`），网页本身由 ESP32 的 HTTP 服务（端口 80）下发。
- 控制方向：手机网页发 `arm/start/stop/reset` → ESP32 收到后**真实模式下**打包成 `FRAME_CMD` 经 UART 发给 STM32。

### 2.2 当前 DEMO 数据流（现在跑通的状态）

当前 `DEMO_MODE=true`，不读串口、不做 UART 帧解析，改为：

- ESP32 在 `loop()` 里每圈调用 **`demoStep()`**，内部用一段"**按压→保压→滑动→抬起**"的时间曲线，**合成**出 `TouchFrame`（t/x/y/z/Fx/Fy/Fz/Mx/My/Mz/contact）、四维特征 `MetricsFrame`（softness/smoothness/roughness/rebound/flags）和综合评分 `g_score`。
- `loop()` 里按 `PUSH_HZ` 节拍调用 `pushFrame()` / `pushMetrics()` / `pushScore()`，以 **WebSocket CSV 文本**广播给网页。
- 于是**不接任何硬件，刷新手机页面就能看到滚动曲线、四维卡片、雷达图和评分**。

> 一句话：**真实模式靠 `pollUart()` 读 STM32 帧；DEMO 模式靠 `demoStep()` 生成假数据。** 两者在 `loop()` 里二选一。

## 三、ESP32 功能清单

### 3.1 WiFi 配网（门户配网 / Captive Portal）
代码实现的配网逻辑（见 `setup()`、`handleConfig()`、`handleReset()`）面向"设备自带网页 + 门户"形态：

1. **开机读 NVS**：`prefs.begin("wifi")`，读取保存的 `ssid`/`pass` 和强制配网标志 `force`。
2. **若 `force` 未置位且已存 WiFi** → 先以 **STA** 模式尝试连接已保存 WiFi（最多等 ~15s）。
   - 另：`DEV_QUICK_WIFI=1` 且带 `CUSTOM_SSID` 时，再尝试开发用 WiFi（产品保持 0）。
   - **连上** → 仅 STA（热点关闭），打印"本机 IP"，启动 **mDNS** `MDNS.begin("datatouch")` → `http://datatouch.local/`。
3. **没连上 / 被强制配网** → 进入**配网模式**：
   - 开热点 **`AP_SSID`（默认 `YD-ESP32S3`）**，密码 **`AP_PASS`（默认 `12345678`）**。
   - 打印配网地址 **`http://192.168.4.1/`**，并启动 `DNSServer`（端口 53）做 **DNS 劫持**：所有域名解析到本机，手机连热点后通常**自动弹出**配网页。
   - HTTP `/` 在配网模式下返回 **`CONFIG_HTML`**（配网表单），否则返回 **`INDEX_HTML`**（显示页）。
4. **`POST /config`（handleConfig）**：接收 `ssid`/`pass` 表单 → 存 NVS → 清 `force` 标志 → **就地**切到 `WIFI_AP_STA` 并 `WiFi.begin()` 连接（保持热点让手机仍可访问，等页面发完）。
   - **连上** → 显示"已连接"成功页并打印**真实 IP 地址** `http://<ip>/`，同时 `MDNS.begin("datatouch")`；等待约 1.2s 后 `WiFi.mode(WIFI_STA)` **关闭热点**，进入纯 STA。
   - **连不上** → 保持配网模式，提示重试。
5. **`GET /reset`（handleReset，"重新配网"）**：清除 NVS 里的 `ssid`/`pass`，置 **`force=true`** 强制配网标志 → `ESP.restart()` → 下次开机必定进配网模式。返回页提示用户连热点 `YD-ESP32S3` / `12345678`。

> 摘要流程：**未存 WiFi + 未配网 → 开热点(192.168.4.1) 门户配网 → 保存后连家里 WiFi、关热点 → 用真实 IP 或 mDNS `datatouch.local` 访问 → 之后要改 WiFi 就点"重新配网"(走 force 标志)**。

### 3.2 WebSocket 服务器
- `WebSocketsServer webSocket(WS_PORT)`，端口 **81**。
- `webSocket.begin()` + `webSocket.onEvent(onWsEvent)`。
- 事件回调 `onWsEvent`：客户端连接时立即 `pushState()`；收到文本则 `handleCommand()`。
- 服务端→网页的消息：`STATUS`/`DATA`/`METRICS`/`SCORE`（见 5.2）。
- 网页→服务端：文本命令 `arm`/`start`/`stop`/`reset`。

### 3.3 HTTP 服务器（显示页 / 配网页 / 重新配网）
- `WebServer server(WEB_PORT)`，端口 **80**。
- 路由：
  - `GET /`：`g_provisioning ? CONFIG_HTML : INDEX_HTML`（配网页或显示页）。
  - `POST /config`：配网提交，`handleConfig`。
  - `GET /reset`：重新配网，`handleReset`。
  - `onNotFound`：用作**门户探测重定向**（苹果/安卓 captive portal 探测 URL → 302 跳转到本机首页 `http://<bindIP>/`），从而**自动弹出**配网页。

### 3.4 UART 帧解析（真实模式）
- `HardwareSerial STM32(2)`，UART2，`STM32_RX_PIN=18`、`STM32_TX_PIN=17`、`STM32_BAUD=460800`。
- `pollUart()`：逐字节状态机收帧 → 校验 CRC8 → `dispatchFrame()` 分发（见 5.1）。仅 `DEMO_MODE=false` 时调用。

### 3.5 DEMO 模拟（`demoStep()`）
见 2.2；`demoStep()` 用时间分段合成"按压→保压→滑动→抬起"，实时更新 `g_frame`/`g_metrics`/`g_score`。

### 4.2 `src/protocol.h` — 帧协议定义
- 常量：`FRAME_SYNC0=0xAA`、`FRAME_SYNC1=0x55`。
- 枚举 `FrameType`：`FRAME_DATA(0x01)`、`FRAME_STATUS(0x02)`、`FRAME_METRICS(0x03)`、`FRAME_SCORE(0x04)`、`FRAME_CMD(0x05)`。
- 枚举 `ExpState`：`STATE_IDLE(0)`、`STATE_ARMED(1)`、`STATE_RUNNING(2)`、`STATE_DONE(3)`、`STATE_ERROR(4)`。
- 结构 `TouchFrame`（`#pragma pack(1)`）：`t,x,y,z,Fx,Fy,Fz,Mx,My,Mz`（10 个 `float`）+ `contact`（`uint8`）。`DATA_FLOAT_CNT=10`。
- 结构 `MetricsFrame`（`#pragma pack(1)`）：`softness,smoothness,roughness,rebound`（4 个 `float`）+ `flags`（`uint8`）。`METRICS_FLOAT_CNT=4`。
- 校验：`crc8_over(buf,n)` —— **CRC-8，多项式 0x31，初值 0xFF**。
- 组帧：`build_frame(buf,type,payload,len)` → 返回帧总长。

## 五、协议

### 5.1 STM32 ↔ ESP32 二进制帧（`protocol.h`）
帧格式（二进制，**小端**）：

```
[0] sync0 = 0xAA
[1] sync1 = 0x55
[2] type   帧类型
[3] len    负载字节数
[4..] payload （len 字节）
[last] crc8  从 sync0 到 payload 末尾各字节校验
```

- **校验**：`crc8_over()`（多项式 `0x31`，初值 `0xFF`）。
- **帧类型**：

| 框架值 | 名称 | 负载 | 说明 |
|---|---|---|---|
| `0x01` | `FRAME_DATA` | `TouchFrame`（10×float + contact，约 41B） | 单帧时间序列 `t,x,y,z,Fx,Fy,Fz,Mx,My,Mz,contact` |
| `0x02` | `FRAME_STATUS` | `uint8` | 状态机（`0..4`） |
| `0x03` | `FRAME_METRICS` | `MetricsFrame`（4×float + flags） | 四维特征向量（STM32 归一化 [0,1]） |
| `0x04` | `FRAME_SCORE` | `float` | 综合评分 0~100 |
| `0x05` | `FRAME_CMD` | `uint8` | 手机 → STM32 控制命令（arm/start/stop…） |

- **`TouchFrame` 字段**（与任务书 MuJoCo/CSV 输出一致）：
  - `t` 时间戳(秒, 相对 T0)；`x/y/z` 位移(mm)，其中 `y` 为阶段二扩展轴（当前恒为 0）；
  - `Fx` 切向力(N)、`Fy` 侧向力(N)、`Fz` 法向力(N)；
  - `Mx/My/Mz` 力矩(N·mm)，DEMO 中默认 0；
  - `contact` 接触标志 0/1。
- **`MetricsFrame` 字段**（**STM32 归一化后的 [0,1] 值；综合评分也在 STM32 上算，为权威值；前端只显示**）：
  - `softness` 柔软度（越大越软）；`smoothness` 顺滑度（越大越顺滑）；
  - `roughness` 细腻度/粗糙度（**越小越细腻**，评分时应取反）；
  - `rebound` 回弹贴合度（越大越好）；`flags` bit0=数据有效。

> DEMO 中 `g_metrics.flags` 置 `0x01`（数据有效）。

### 5.2 WebSocket 消息格式（CSV 文本）
由 `pushFrame()`/`pushMetrics()`/`pushScore()`/`pushState()` 广播，用逗号分隔：

| 消息 | 格式 | 说明 |
|---|---|---|
| `DATA` | `DATA,t,x,y,z,Fx,Fy,Fz,Mx,My,Mz,contact` | 实时曲线帧（10 个物理量 + 接触标志） |
| `METRICS` | `METRICS,softness,smoothness,roughness,rebound,flags` | 四维特征（STM32 归一化 [0,1]）+ flags |
| `SCORE` | `SCORE,<0-100>` | 综合评分（设备端给出） |
| `STATUS` | `STATUS,<n>` | 状态机（`0`空闲 `1`已ARM `2`采集中 `3`完成 `4`错误） |

网页 → 设备（`ws.send`）：单条文本命令，取值 `arm` / `start` / `stop` / `reset`。
- `arm`→`STATE_ARMED`，`start`→`STATE_RUNNING`，`stop`→`STATE_DONE`，`reset`→`STATE_IDLE`。
- 真实模式下同时通过 `build_frame(buf, FRAME_CMD, &st, 1)` 转发给 STM32。

## 六、网页显示（`INDEX_HTML`）

`INDEX_HTML` 是由 ESP32 内嵌的、手机浏览器打开 `http://<ip>/`（STA 下）看到的**实时显示页**，功能包括：

- **顶部状态**：WebSocket 连接状态（已连接/断开）、**综合评分**（前端显示；DEMO 下由前端 JS 按权重融合，**仅演示**，不代表正式链路）、**设备评分**（`SCORE` 消息，来自 STM32，为**权威评分**，前端只显示）。
- **四维卡片**：柔软度、顺滑度、细腻度、回弹（各 0~100 分；`METRICS` 为 STM32 归一化后的 [0,1] 值，前端只显示）。
- **力/位移卡片**：Fx/Fy/Fz（N）、Mx/My/Mz（N·mm）、X/Y/Z（mm）。
- **控制按钮**：ARM / START / STOP / RESET，点击 `ws.send('arm'/'start'/'stop'/'reset')`。
- **实时曲线**（`#cv` canvas，最长 240 点）：**蓝=Fz（法向力）、红=Fx（切向力）、绿=Y（位移）**。
- **雷达图**（`#radar` canvas，五边形）：柔软度 / 顺滑度 / 细腻度 / 回弹 + **综合**（第 5 边）。
- **右上角"重新配网"**链接 → `GET /reset` → 清凭据、置 `force`、重启进配网。

### 权重与归一化（STM32 为准，前端只显示）

> **归属（权威）**：柔软度/顺滑度/细腻度/回弹 在 **STM32 上归一化到 [0,1]**，综合评分(0-100)也在 **STM32 上计算**，是**权威值**；前端（网页/小程序）**只显示**。DEMO 模式下的前端 JS 融合**仅为演示**，不代表正式链路。**权重 / 归一化区间可调整**，但**正式以 STM32 为准**，前端权重仅用于 DEMO/展示或可选微调。

网页 JS 顶部有**两个常量**（仅供前端 DEMO 融合 / 展示使用）：

```js
const WEIGHTS={softness:0.30,smoothness:0.25,roughness:0.20,rebound:0.25};
const RANGE={
  softness:[0.0,1.0],    // 归一化分段区间; 越大越软
  smoothness:[0.0,1.0],  // 越大越顺滑
  roughness:[0.0,1.0],   // 越小越细腻, 归一化时取反
  rebound:[0.0,1.0]      // 越大回弹越好
};
```

- `WEIGHTS`：四维的权重（前端 DEMO/展示用；**正式权重以 STM32 为准**）。
- `RANGE`：每维的归一化分段区间 `[min,max]`（前端 DEMO/展示用；**正式归一化区间以 STM32 为准**，可调整）。
- 综合评分：`computeScore(m)` 先 `normalize()` 把每维映射到 0~100（`roughness` 取反），再按 `WEIGHTS` 加权融合为 `composite`（**DEMO 演示值**）。
- **调整评分**：改这两行（`WEIGHTS` / `RANGE`）即可，**无需重新烧录固件**，刷新网页即生效（仅影响前端 DEMO 融合；权威评分需在 STM32 侧调整）。

> 注意：网页端 JS **在 DEMO 下**会按它自己的权重做一次融合得到"综合评分"（**仅演示**）；`SCORE` 消息的 `g_score`（DEMO 里由 `demoStep` 近似算出）即"**设备端评分**"，正式链路下就是 STM32 的**权威评分**，前端只显示在"设备评分"卡片上。

## 八、如何配网 / 烧录 / 测试

1. **打开工程**：VSCode 装好 **PlatformIO IDE**，`File → Open Folder`，打开 `D:\Develop\ESP32CODE\DataTouch\ESP32`（**不要**点 New Project）。
2. **选端口**：`platformio.ini` 里取消 `upload_port = COMx` 注释、填 CH340 口对应的 COM 号（设备管理器查看，通常 `COMx`）；不填也可，PlatformIO 有时能自动识别。烧录用 **CH340 那个 Type-C 口**（板上另一个原生 USB-OTG 口可不管）。
3. **编译+烧录**：PlatformIO 左下角 **Upload**（或 `pio run -t upload`）。
4. **打开串口监视器**（115200）：应看到芯片信息、`本机 IP:`（STA 下）或 `配网地址(AP): http://192.168.4.1/`（配网模式下）。
5. **第一次使用（配网）**：
   - 设备未存 WiFi → 开热点 `YD-ESP32S3`，手机连上该热点。
   - 浏览器打开 `http://192.168.4.1/`（一般会自动弹出配网页），输入家里 WiFi 的 SSID/密码。
   - 点"保存并连接" → 保存成功页会**直接显示真实 IP** `http://<ip>/`。
6. **使用**：手机连**同一 WiFi**，浏览器打开 `http://<ip>/`（或 `http://datatouch.local/`）→ 看到实时曲线、四维卡片、雷达图、综合/设备评分、ARM/START/STOP/RESET 按钮。
7. **重新配网**：显示页右上角"重新配网" → 清凭据 + 置 `force` → 重启进配网模式。
8. **DEMO / 真实切换**：`main.cpp` 里 `#define DEMO_MODE true`（演示）或 `false`（接真实 STM32），改后重新烧录。

> 用 `CUSTOM_SSID/PASS` + `DEV_QUICK_WIFI=1` 可在**开发时**快速连网（未配网也自动连它），产品请保持默认（0/空）。

## 九、待办 / 占位（重要）

当前代码是 **DEMO 演示**，以下均为**尚未实现**或**占位**：

- ❌ **未接 STM32**：`DEMO_MODE` 当前为 `true`；接真实硬件前需保持 `false` 并上电 STM32。
- ❌ **无真实特征/评分公式**：四维特征（softness/smoothness/roughness/rebound）与综合评分目前由 `demoStep()` 用模拟量近似；真实算法应在 **STM32 端**计算。
- ❌ **无振动（ADXL335）与电机（3 台闭环步进）实现**：这些是 STM32 侧子系统的职责，ESP32 端甚至不感知；本工程里无对应代码。
- ⚠️ **`protocol.h` 的 `MetricsFrame` 具体字段由 STM32 端定义**：当前四维字段（softness/smoothness/roughness/rebound + flags）是占位约定，STM32 组帧时需**按同样字段顺序 / 归一化区间（[0,1]）**来填，否则解析会错位。`FRAME_METRICS`/`FRAME_SCORE` 数据结构待联调确认。
- ✅ **WiFi 配网已定方案**：走"**设备自带网页 + 门户配网**"（Captive Portal + 热点 `192.168.4.1` + mDNS `datatouch.local` + `force` 重新配网标志）。产品形态上的更完整讨论见 `docs\产品端方案对比.md`。
- ⏸️ **看门狗暂缓**：当前代码未启用看门狗，长时间运行稳定性（尤其 WebSocket/UART）待后续评估。

### 下一步要接什么（按优先级）
1. 实现 STM32 端采集（六维力 RS485/ADXL335/3 电机）+ 计算特征/评分，并按 `protocol.h` 帧格式经 UART 发送。
2. 在 ESP32 上：`DEMO_MODE=false`，确认 `pollUart()` 能正确解析 `FRAME_DATA`/`FRAME_METRICS`/`FRAME_SCORE`/`FRAME_STATUS`，并通过 `FRAME_CMD` 把网页控制命令回传 STM32。
3. 联调两端波特率（当前 `STM32_BAUD=460800`，已统一；STM32 侧 USART2 同步为 460800）与帧字段对齐。
4. 视需要补：历史曲线/记录（存 SD 卡）、看门狗、更多状态机/异常处理。

## 十一、设备上云（HTTPS 上传实验记录）【新增】

> 详细说明见 `README.md` §六。此处只列与"当前框架"相关的要点。

- **新增文件**：`src/cloud_upload.h` / `src/cloud_upload.cpp`。**`protocol.h` 零改动**；配网/WebSocket/显示页/DEMO/UART 解析逻辑均未改动。
- **数据流（旁路）**：`g_metrics`(四维 0~1) + `g_score`(0~100) → JSON（云端约定字段，含 `dedupId`/`startedAt`/`source:"device"`）→ `WiFiClientSecure + HTTPClient` HTTPS POST → 云函数 `deviceUpload` → `experiments` 集合。
- **触发时机**：① `loop()` 里 `g_state` **状态沿检测**到 `STATE_DONE` 时自动入队一次（不会每轮重复入队）；② 网页「上传测试」按钮 → WebSocket `upload` → `cloudUploadTestNow()`（用当前值立刻传一条，便于验证）。
- **配置（NVS 命名空间 `cloud`）**：`url` / `token` / `devid` / `fabric`；编译期默认值在 `cloud_upload.h` 顶部（`CLOUD_UPLOAD_URL` / `CLOUD_TOKEN` / `DEVICE_ID` / `FABRIC_NAME`）。运行期用 `cloudUploadSetConfig()` 写 NVS。
- **断网/失败**：环形队列 16 条（`q0..q15` 存 NVS，掉电不丢；满则丢最旧并计数）+ 指数退避 5s/15s/60s/300s + 联网自动补传；`dedupId = deviceId-millis-seq`（`seq` 落 NVS，重启不重号）保证幂等。
- **非阻塞**：退避用 `millis()` 计时；仅"到期且有网"时做一次 HTTPS 调用（连接 6s / 握手 8s / 响应 6s 超时），每轮 `loop()` 最多一条。⚠ 单轮 loop 最坏会被 HTTP 超时占用几秒（MVP 有意取舍），本地实时推送不受实质影响。
- **网页**：`INDEX_HTML` 新增「上云」状态卡与「上传测试」按钮，状态经 `CLOUD,<事件>,<说明>` 广播（事件 `CFG/ENQ/SEND/OK/FAIL/OFF/DROP`）。
- **`startedAt`（已修正）**：必须是 **13 位 epoch 毫秒**（JSON number）。修复前 `nowEpochMs()` 返回 `uint32_t`，`(uint32_t)t * 1000UL`（`t` 已是 epoch 秒 ≈1.79e9，乘 1000 ≈1.79e12）按 2³² 取模 → 串口出现 `startedAt=2693757455`。现改为 `uint64_t`（`nowEpochMs()` / `CloudRecord::startEpochMs` / `buildBody()` 参数），子秒部分用 `esp_timer_get_time()` 推算。
  - **语义 = 实验开始时刻**：`main.cpp` `loop()` 在 `g_state` 进入 `STATE_RUNNING` 的**状态沿**调 `cloudUploadNoteRunningEdge()` 记录 `millis()`；`cloudUploadResolveStartedAt()` 用 `当前epoch - (millis()-记录时刻)` 回算（即使入队时才同步好也能算对）；从未运行（DEMO 直接 STOP）或记录超 1 天 → 回退**入队时刻**。
  - **有效性判据**：`epoch 秒 ≥ 1600000000`（2020-09）/ `epoch 毫秒 > 1600000000000`。
  - **未同步策略（择一：短等待，非无限等）**：入队时 `kickTimeSyncIfNeeded()` 重新发起 SNTP 并**最多等 1.5s**（`CLOUD_TIME_SYNC_WAIT_MS`，`loop()` 不能被长时间阻塞）；仍失败则 `startedAt` 传 **0** + 串口告警，**绝不发错误数字**。`configTime()` 本身不阻塞，同步由系统后台任务完成；`setup()` 在 WiFi 模式确定后调 `cloudUploadSntpSync()` 并打印同步状态，`loop()` 里同步成功/每 60s 打印 `epochMs`。
  - 注意：JSON 入队即冻结（保幂等），所以"时间无效时入队的那一条"其 `startedAt` 就是 0，之后同步成功不会改写它；新记录均为正常值。
- **设备网页「上云配置」页（新增路由，免重烧改配置）**：
  - `GET /cloud` → `CLOUD_CFG_HTML`（风格同 `CONFIG_HTML`：深色卡片 / 大字号 / 移动端友好），表单 `token`（密码框，回显当前值 + 掩码提示）/ `fabricName` / `deviceId`，提交到 `POST /cloud/config`；`INDEX_HTML` 右上角「重新配网」旁新增 **「上云配置」** 入口链接。
  - `POST /cloud/config` → `server.arg()` 取参（`WebServer::urlDecode()` 已把 `+` 还原为空格）→ `cloudUploadSetConfig(cur.url, token, deviceId, fabricName)` 写 NVS → 返回「✅ 已保存」页（新值回显、token 脱敏）。**无需重启，立即生效**；token 留空 = 沿用原值。
  - **未改动**：`/`、`/config`、`/reset`、`onNotFound` 门户重定向逻辑；新路由只是 `server.on` **追加**，注册在 `onNotFound` 之前。
- **安全（待改进）**：MVP 用 `WiFiClientSecure::setInsecure()`（不校验证书链），正式版改 `setCACert()` / `setFingerprint()`；`token` 为明文共享密钥，勿入库到 Git，后续建议换每设备密钥 + HMAC。
