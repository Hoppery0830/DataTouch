# 织物触觉舒适度检测系统 — 小程序 + 微信云开发 完整落地方案

> 目标：在**不改动 STM32↔ESP32 的 `protocol.h` 帧协议**、**保留现有 ESP32 WiFi 配网 / WebSocket / 内嵌显示页**的前提下，**新增一条 HTTPS 上云路径**，把实验数据存进**微信云开发**（云函数 + 云数据库 + 云存储），手机端用**微信小程序**看实时与历史。
> 核心收益：**免服务器、免域名、免 ICP 备案**（云开发由微信侧提供 HTTPS 域名与调用链路）。
> 本文档**只描述方案，不改任何源码/工程**。

## 0. 先对齐：术语、字段与已定前提

### 0.1 设备侧（已定）

| 端 | 型号/角色 | 现状 |
|---|---|---|
| STM32 | **STM32F407**（采集 + 力控 + **算四维特征与综合评分**） | 六维力 RS485 **500Hz**；振动 ADXL335 **1000Hz**；3 路闭环步进电机 UART；摄像头回弹 **UART5**；设计已完成待实现 |
| ESP32 | **YD-ESP32-S3（WROOM-1-N16R8，16MB Flash + 8MB PSRAM）**，网关 | 已跑通：门户配网、WebSocket、内嵌显示页、DEMO 模式、UART 解析 `protocol.h` 帧 |
| UART 链路 | STM32 **USART2** ↔ ESP32 **UART2**（GPIO17/18） | **460800, 8N1**（已统一裁定：ESP32 `STM32_BAUD=460800`，STM32 USART2 同步 460800 + DATA 抽稀；`Serial.begin(115200)` 是 ESP32 USB 调试口，不属本链路） |

### 0.2 帧协议（`src/protocol.h`，**不改动**）

帧格式（二进制、**小端**）：

```
[0] 0xAA   [1] 0x55   [2] type   [3] len   [4..] payload(len 字节)   [last] crc8
crc8：多项式 0x31，初值 0xFF，覆盖 sync+type+len+payload
```

| type | 名称 | 载荷 | 说明 |
|---|---|---|---|
| `0x01` | `FRAME_DATA` | `TouchFrame` = 10×float + `uint8 contact`（约 41B） | 单帧时间序列，抽稀到 50–100Hz 后发送 |
| `0x02` | `FRAME_STATUS` | `uint8` | `ExpState`：0 IDLE / 1 ARMED / 2 RUNNING / 3 DONE / 4 ERROR |
| `0x03` | `FRAME_METRICS` | `MetricsFrame` = `softness, smoothness, roughness, rebound`(4×float) + `uint8 flags`（约 17B） | 四维特征；`flags` bit0 = 数据有效 |
| `0x04` | `FRAME_SCORE` | `float` | 综合评分 0–100 |
| `0x05` | `FRAME_CMD` | `uint8` | ESP32→STM32：arm / start / stop / reset |

`TouchFrame` 字段：`t`(s, **相对 T0**) / `x,y,z`(mm) / `Fx,Fy,Fz`(N) / `Mx,My,Mz`(N·mm) / `contact`(0/1)。

`MetricsFrame` 字段方向（**云数据库必须沿用同一命名，不要用中文别名当字段名**）：

| 字段 | 中文标签 | 方向 |
|---|---|---|
| `softness` | 柔软度 | 越大越软 |
| `smoothness` | 顺滑度 | 越大越顺滑 |
| `roughness` | 细腻度/粗糙度 | **越小越细腻（融合时取反）** |
| `rebound` | 回弹贴合度 | 越大回弹越好 |
| `composite` | 综合评分 | 0–100（对应 `FRAME_SCORE`） |

### 0.3 归一化与权重（**标定项**）

```text
norm = clamp((x - min) / (max - min), 0, 1)     # min/max 由"参考布料集"标定
score = ( 0.30*softness + 0.25*smoothness + 0.20*(1.0 - roughness) + 0.25*rebound ) * 100
WEIGHTS = { softness:0.30, smoothness:0.25, roughness:0.20, rebound:0.25 }
RANGE   = { softness:[0,1], smoothness:[0,1], roughness:[0,1], rebound:[0,1] }
```

> **归一化 / 评分归属（权威）**：四维特征在 **STM32 上归一化到 [0,1]**，综合评分(0-100)在 **STM32 上计算**，是**权威值**；前端（网页/小程序）**只显示**。ESP32 内嵌页 JS 的 `WEIGHTS`/`RANGE` 仅用于 **DEMO/展示或可选微调**，**正式以 STM32 为准**。云端 `calibration` 集合就是这套参数（权重 / 归一化区间，**可调整**）的**可下发存储**（见 §3.4）。

### 0.4 为什么"必须走云"（关键约束，来自 `产品端方案对比.md`）

- 小程序**真机**（预览/体验/正式版）的 `wx.request` / `wx.connectSocket` **只允许 HTTPS/WSS**，且域名必须在微信后台**服务器域名**白名单内；
- **局域网 IP（`192.168.x.x`）无法加入白名单** → **真机小程序连不上设备本地 IP**（只有开发者工具勾选"不校验合法域名"才行）。

**结论：本方案 = 设备网页（产品形态 A，本地实时）保持不变 + 云开发（新增云端历史与远程查看）**，两条路各自解决不同问题（§8.5）。

本项目**量级估算**（用于判断成本风险）：

| 项 | 单次实验消耗 | 每天 100 次实验 | 每月（30天） | 结论 |
|---|---|---|---|---|
| 数据库写入 | 1 条 ≈ **2–4 KB** | 100 条 ≈ 0.3 MB | ≈ 9 MB | 1GB 量级可撑**多年** |
| 云函数调用 | 1 次 | 100 次 | 3,000 次 | 远低于万次/月量级 |

**超限/收费点提示**：
- 数据库**读写次数**、**容量**（容量超限可能写入失败，需清理或升级）；
- **云函数调用次数 + 资源使用量（GB·s）+ 外网流量**（HTTPS 云函数被设备调用算外网流量）；
- **云存储容量 + CDN 下行流量**（存原始高频 CSV 最容易吃掉额度）；
- 建议：**只上传摘要（四维+评分+元数据）**，曲线**抽稀后**再传（§5.5），**不传**500Hz/1000Hz 原始数据。

## 3. 云数据库表结构（collections）

> 通用约定
> - 每个文档自动带 `_id`(string)。**归属用户统一用 `openid` 字段**（不是微信自动注入的 `_openid`）：
>   - 小程序**客户端直写**时微信会自动注入 `_openid`，但本方案**客户端一律不写库**（安全规则 `write:false`），所以不走这条路；
>   - **云函数写入**时不会自动注入任何归属字段，因此由云函数**显式填写 `openid`**（`uploadExperiment` 用 `wxContext.OPENID`，`deviceUpload` 用 `devices.ownerOpenid`）；
>   - 安全规则与所有查询一律基于 `doc.openid`，口径统一、无歧义。
> - 时间统一用 **BaaS Date 类型**（云函数写 `new Date()`，小程序端展示用 `db.serverDate()` 保持一致）；**相对 T0 的秒数**另存 `t0_relative_duration_s`（与 `protocol.h` 的 `TouchFrame.t` 同源）。
> - **字段名严格沿用 `protocol.h` / `MetricsFrame` / `FRAME_SCORE` 的命名**：`softness` / `smoothness` / `roughness` / `rebound` / `composite`。
> - 建索引建议：`experiments` 上建 `deviceId+startedAt`(复合)、`openid+startedAt`、`dedupId`(唯一)。

### 4.1 `deviceUpload`（**ESP32 设备上云** · HTTP 云函数 · 主路径）

- **入口类型**：**HTTP 云函数**（拿到 HTTPS 地址，设备直接 POST）；若环境不支持，回退 §5.2 的 HTTP API 方案。
- **入参**（HTTP body，JSON）：

```json
{
  "deviceId": "YD32S3-3C6108A1",
  "dedupId": "YD32S3-3C6108A1-000042-0007",
  "ts": 1756376463,
  "nonce": "b7f1c2",
  "sign": "3f9a...c1",
  "fw": "v0.9.3",
  "frameCrc8": "A7",
  "payload": {
    "mode": "real",
    "state": 3,
    "softness": 0.62, "smoothness": 0.71, "roughness": 0.24, "rebound": 0.55,
    "composite": 72.4,
    "metricsNormalized": true,
    "metricsFlags": 1,
    "weights": { "softness":0.30, "smoothness":0.25, "roughness":0.20, "rebound":0.25 },
    "calibrationVersion": "calib-2026-09-01",
    "startedAt": 1756376463000,
    "endedAt": 1756376496800,
    "t0_relative_duration_s": 33.8,
    "fabricId": "f1001",
    "fabricName": "纯棉平纹40支",
    "fabricCode": "C-40S-PLAIN-03",
    "notes": "",
    "curve": [ {"t":0.00,"Fz":0.02,"Fx":0.00}, {"t":0.02,"Fz":0.15,"Fx":0.01} ]
  }
}
```

- **鉴权**：`sign = HMAC_SHA256(deviceSecret, deviceId + dedupId + ts + nonce + JSON.stringify(payload))`，云函数侧用 `devices.secretHash` 校验，并检查 `|now - ts| <= 300s`（防重放）+ `dedupId` 唯一（幂等）。详见 §5.3。
- **校验**：若设备带 `frameCrc8`（ESP32 侧对重组后的 JSON 字节流或对源帧做的 CRC8），云函数可选复核（**推荐用 `dedupId + sign`，`frameCrc8` 仅作日志**）。
- **出参**：

```json
{ "code": 0, "message": "ok",
  "data": { "_id": "a1b2c3d4e5f6a7b8", "dedup": false, "curveFileId": "cloud://.../curves/a1b2c3d4e5f6a7b8.json" } }
```

- **行为**：
  1) 校验 JSON 结构与范围（四维 ∈ [0,100] 或 [0,1] 依 `metricsNormalized`、`composite` ∈ [0,100]）；
  2) 验签 + 时间窗 + `devices.status != disabled` + `uploadEnabled`；
  3) 若 `payload.curve` 存在 → 写云存储 `curves/{dedupId}.json`，取 `fileId`；
  4) `experiments` 以 `dedupId` **upsert**（已存在则返回 `dedup:true`，不重复写）；
  5) 反查 `devices.ownerOpenid` 填 `openid`；更新 `devices.lastSeenAt`；
  6) 返回 `_id`。

**`getCalibration`**
- **入参**：`{ "deviceId": "YD32S3-3C6108A1" }`（可空 → 取 global）
- **出参**：

```json
{ "code": 0, "message": "ok",
  "data": {
    "version": "calib-2026-09-01",
    "ranges": { "softness":[0.05,1.20], "smoothness":[0.10,0.95], "roughness":[0.02,0.80], "rebound":[0.15,0.90] },

```

**`setCalibration`**
- **入参**：`{ "version":"calib-2026-09-02", "scope":"global", "deviceId":"", "referenceFabricIds":["f1001","f1002"], "weights":{...}, "method":"minmax" }`
- **出参**：`{ code:0, data:{ version, ranges:{...}, isActive:true } }`
- **行为**：读 `fabrics`（`isReference:true` 且 `_id ∈ referenceFabricIds`）的 `refMetrics` → 按 `minmax` 计算每维 `[min,max]` → 写新 `calibration` 文档（`isActive:true`）→ **把同 scope 下旧版本 `isActive` 置 false**（保证唯一生效）。
- **下发链路**：小程序改标定 → `calibration` 更新 → **ESP32 下次上报前先 `GET getCalibration`**（或由小程序经 ESP32 的 HTTP `POST /cloud/calibration` 转推）→ ESP32 存 NVS → **内嵌显示页的 `WEIGHTS`/`RANGE` 也随之变化**（仅影响前端 DEMO/展示；**正式评分以 STM32 为准**，标定值最终需同步/下发到 STM32）。

### 4.6 `bindDevice`

- **入参**：`{ "claimCode": "7K2M9Q", "deviceName": "一号检测台" }`
- **出参**：`{ code:0, data:{ deviceId:"YD32S3-3C6108A1", deviceName:"一号检测台", boundAt:"..." } }`
- **行为**：按 `claimCode` 查 `devices`（未过期、`ownerOpenid` 为空）→ **事务**写 `ownerOpenid = OPENID`、`boundAt`、`deviceName` → 把该设备历史无主记录（`openid == null`）回填（可选，异步分批）。
- **错误码**：`4001` 绑定码不存在 / `4002` 已过期 / `4003` 已被他人绑定 / `4004` 该用户已绑定此设备。
- **`getDevices`**：入参 `{}` → 出参 `{ code:0, data:{ list:[ {deviceId, deviceName, lastSeenAt, status} ] } }`
- **`unbindDevice`**：入参 `{ deviceId }` → 清 `ownerOpenid`（需校验是本人的设备）。

## 5. 设备上云（ESP32）细节

### 5.1 通道选型：HTTP 云函数 vs 云开发 HTTP API

| 方案 | 免服务器/免备案 | 设备端复杂度 | 鉴权 | 推荐度 |
|---|---|---|---|---|
| **A. 云函数 HTTP 触发器（HTTP 云函数）** | ✅ 云开发提供 HTTPS 域名 | 低：一个 HTTPS POST | 自建 HMAC 密钥 | ⭐**首选（MVP）** |
| **B. 云开发 HTTP API（`invokeCloudFunction`）** | ✅ 同上 | 中：需先 `getAccessToken`（有效期约 2 小时），再带 `access_token` 调 `https://api.weixin.qq.com/tcb/invokecloudfunction?access_token=...&env=...&name=deviceUpload` | **AppSecret 不能放设备**，需中间层换 token | 回退方案 |
| C. 云托管 / 自建服务器 | 云托管内置域名；自建则需备案 | 高 | 灵活 | 不推荐（违背"免备案"目标） |

**结论：主推 A（HTTP 云函数）**，理由：设备只需 `POST`，无需处理 token 续期，也**不必把 AppSecret 烧进固件**。
参考官方文档：[HTTP 云函数](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloud/HTTPCloudFunction.html)、[触发云函数 HTTP API](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloud/reference-http-api/functions/invokeCloudFunction.html)。

> ⚠️ 若当前环境控制台**不提供** HTTP 云函数入口：回退 B，但**必须**由一个小中转（例如小程序定期刷新 token 后经 BLE/局域网写给 ESP32，或用一个极小的常驻云函数代理）持 `AppSecret`，**绝不把 AppSecret 放进 ESP32 固件**。此点列为待拍板项（§11）。

### 5.3 鉴权（预置密钥 + HMAC 签名）

```text
出厂/绑定阶段（人工或首次配网时）：
  deviceId     = "YD32S3-" + 后 6 位 MAC            // 例如 YD32S3-3C6108A1
  deviceSecret = 32 位随机 hex（每条设备唯一，仅存 NVS 与云端 secretHash）
  claimCode    = 6 位短码（用于 bindDevice，展示在配网成功页/串口）

每次上报：
  ts    = SNTP 绝对秒（失败则退化为"最近一次成功时间 + 单调递增计数"）
  nonce = 随机 6 位 hex
  body  = 待发送的 JSON 字符串（**原样字节**，不含 sign 字段）
  bodyHash = SHA256(body) 的 hex
  sign  = HMAC_SHA256(derivedKey, deviceId + "|" + dedupId + "|" + ts + "|" + nonce + "|" + bodyHash)
          derivedKey = SHA256(deviceSecret + KEY_PEPPER)      // 与云函数侧派生方式完全一致
  请求头：
    Content-Type: application/json
    X-Device-Id:  YD32S3-3C6108A1
    X-Timestamp:  1756376463
    X-Nonce:      b7f1c2
    X-Sign:       3f9a...c1
    X-Fw:         v0.9.3
```

> ⚠️ **必须对"实际发出的 body 字节"求哈希**：ESP32 端先序列化出 JSON 字符串，再用**同一个字符串**既做 `bodyHash` 又作为请求体发送；不要在云函数侧对"解析后再序列化"的对象求哈希（键序/空格不一致 → 签名必然失败）。

云函数侧校验顺序（任一失败即拒绝）：

```text
1) X-Device-Id 存在且 devices 中存在、status=active、uploadEnabled=true
2) |now - X-Timestamp| <= 300s            → 否则 4013 时间偏移过大
3) nonce 未在最近 300s 内用过（用 devices 最近 nonce 或内存/数据库去重表）→ 4014 重放
4) HMAC 重新计算并与 X-Sign 比对（常量时间比较）→ 4015 签名错误
5) dedupId 已存在 → 直接返回成功（幂等，不重复写）
```

**密钥管理原则**：
- 每条设备**独立密钥**（不用全局共享密钥，避免一台泄漏全网失守）；
- 云端**只存哈希**（`secretHash = sha256(deviceSecret + salt)`）；泄漏后可 `secretVersion++` 轮换；
- 密钥**不进固件源码**：烧录后由"首次配网/绑定流程"写入 NVS，或由出厂工具/串口注入；
- **ESP32 侧不存 AppSecret、不存 CloudBase 管理凭据**。

### 5.4 断网策略（本地缓存 + 环形队列 + 重传 + 去重）

```text
                    ┌──────────── 实验结束 (FRAME_STATUS=3 DONE) ────────────┐
                    ▼                                                        │
        ┌───────────────────────────┐                                        │
        │ 组实验摘要 summary        │  dedupId = deviceId-bootCount-seq        │
        │ (四维/评分/时间/抽稀曲线) │  bootCount: NVS 递增（防重启重复）        │
        └───────────┬───────────────┘  seq: 本轮递增（防同一次多次入队）      │
                    ▼                                                        │
        ┌───────────────────────────┐   队列满(默认 32 条)                    │
        │ 环形队列 push（RAM/NVS）  │ ──────────────► 丢弃最旧 + 计数 dropped ─┘
        └───────────┬───────────────┘
                    ▼
       ┌─────────────────────────────────────────┐
       │ WiFi 已连? & 云上传已启用?               │──否──► 等下一轮 loop()
       └───────────┬─────────────────────────────┘
                   ▼ 是
       ┌─────────────────────────────────────────┐
       │ HTTPS POST deviceUpload (超时 5–8s)      │
       │ 请求头带 X-Sign / X-Timestamp / X-Nonce  │
       └───────┬─────────────────────┬───────────┘
         2xx & code=0          失败/超时/网络断
               │                     │
               ▼                     ▼
       ┌───────────────┐   ┌──────────────────────────────────────┐
       │ 队列 pop      │   │ 退避重试: 1s→2s→5s→15s→60s→300s(封顶) │
       │ 记录 lastOk   │   │ 每条最多重试 8 次；仍失败标 failed    │
       │ 清 dropped    │   │ 保留在队列，下轮继续（掉电不丢）      │
       └───────────────┘   └──────────────────────────────────────┘
```

| 机制 | 设计 |
|---|---|
| **缓存介质** | 元数据 + 摘要（不含曲线）存 **NVS**（`Preferences`，掉电不丢，适合 ≤32 条 × ~300B）；曲线若有则先写 **PSRAM** 临时缓冲，成功上传后即释放（8MB PSRAM 足够） |
| **队列长度** | 默认 **32 条**（约 32 次实验），可配置；满则丢最旧并累加 `droppedCount` |
| **重传** | 指数退避 `1/2/5/15/60/300s` 封顶；**仅在 WiFi 已连且 RTT 正常时**尝试，避免拖慢 `loop()`（建议在独立任务/非阻塞状态机里做，`loop()` 不阻塞超过 ~50ms） |
| **去重** | 设备侧 `dedupId`（唯一）；云端 `dedupId` **唯一索引 + upsert**，重复上报直接返回成功 → **网络抖动/half-success 也不会产生重复记录** |
| **掉电保护** | 队列条目在 `push` 时立即落 NVS；`pop` 在收到 `code=0` 后才执行 |
| **可观测** | 内嵌页显示 `队列深度 / dropped / 最后成功时间 / 最后错误码`；串口打印同一信息 |

### 5.5 上传频率与数据粒度

| 策略 | 推荐 | 理由 |
|---|---|---|
| **每个实验一次**（`STATE_DONE` 触发） | ⭐**推荐** | 数据量最小、语义清晰、天然去重；与"一次实验一条 `experiments`"一一对应 |
| 周期上传（如每 10s 一批曲线点） | ❌ 不做（MVP） | 写库次数×N，费用与去重复杂度上升 |
| 实时流（WebSocket 上云） | ❌ 不做（除非将来要远程实时） | 云开发无原生 MQTT；实时仍由设备本地 WebSocket 承担（§6.3） |
| 曲线粒度 | **抽稀到 20–50Hz**（`LTTB` 或 min/max 保峰） | 原始 50–100Hz 的 `FRAME_DATA` 一条实验可达数千点；抽稀后 5–30KB |
| 四维/评分 | **每次实验 1 组**（末值；可选：按阶段各 1 组） | 与 `MetricsFrame`/`FRAME_SCORE` 语义一致 |
| 原始 500Hz/1kHz | **不上传**（除非用户手动导出） | 保护免费额度 |

### 5.6 时间戳：相对 T0 还是绝对时间？

**两者都存，各司其职**：

| 字段 | 类型 | 来源 | 用途 |
|---|---|---|---|
| `t0_relative_duration_s` | number | STM32（`TouchFrame.t` 末值，秒） | 与设备侧曲线/力控轨迹**严格对齐**（复现实验） |
| `startedAt` / `endedAt` | Date | **ESP32 SNTP 绝对时间** | 列表排序、按时间筛选、跨设备比较 |
| `createdAt` | Date | **云函数服务端时间**（`new Date()`） | 权威接收时间，**不受设备时钟造假影响** |
| 曲线内每点 `t` | number | 沿用 `TouchFrame.t`（相对 T0 秒） | 曲线横轴 |

**退化策略**：若 SNTP 未同步（无外网/DNS 失败）→ `startedAt = createdAt - duration`（云函数侧回算），并在文档里置 `timeSource: "estimated"`，列表显示"≈"标记。

### 6.3 实时数据怎么来（三条路线，按阶段取舍）

## 7. 权限与安全

### 7.1 云数据库安全规则（核心原则：**客户端只读，写一律走云函数**）

云开发「自定义安全规则」使用类 JSON 的表达式。推荐配置：

| 集合 | 读 | 写（增/改/删） | 规则示例（**自定义安全规则**） |
|---|---|---|---|
| `experiments` | 仅本人 | **禁止**（走云函数） | `{"read": "doc.openid == auth.openid", "write": false}` |
| `fabrics` | 本人 + 公共 | **禁止**（走云函数） | `{"read": "doc.openid == auth.openid || doc.isPublic == true", "write": false}` |
| `devices` | 仅本人 | **禁止** | `{"read": "doc.ownerOpenid == auth.openid", "write": false}` |
| `calibration` | 全局可读（含未登录时机） | **禁止** | `{"read": true, "write": false}` |
| `telemetry`（若建） | 仅本人 | **禁止** | `{"read": "doc.openid == auth.openid", "write": false}` |

> 备选「简易权限配置」：`experiments` 选"**仅创建者可读写**"、`calibration` 选"**所有用户可读，仅管理端可写**"。
> 但**推荐显式写自定义安全规则**，并注意：
> - 客户端 `add()` 写入的文档会**自动带 `_openid`**；而**云函数写入的文档不会自动带**，必须手动填 `openid`（本方案统一用 `openid` 字段名，规则里也用 `doc.openid`）。
> - **`write: false` 是硬保障**：即使客户端被反编译，也无法伪造实验记录或篡改标定。

### 7.2 密钥管理

| 密钥 | 存放位置 | 绝不放在 |
|---|---|---|
| 云开发**环境ID** | 小程序 `app.js`、ESP32 NVS | —（环境ID 非机密） |
| **AppSecret** | **不使用**（走 HTTP 云函数方案则完全不需要） | ❌ ESP32 固件、❌ 小程序代码（小程序端也不该有） |
| 设备 **deviceSecret** | ESP32 **NVS**（非源码）；云端只存 `secretHash` | ❌ Git 仓库、❌ 明文数据库字段 |
| 云函数环境变量（如需第三方 key） | 云函数「环境变量」配置 | ❌ 代码里硬编码 |
| 云存储 fileID | 小程序按需取临时 URL | — |

### 7.3 防刷 / 防滥用

| 手段 | 做法 |
|---|---|
| **签名 + 时间窗** | HMAC 校验 + `|now-ts| ≤ 300s`，防伪造与重放 |
| **nonce 去重** | 每设备最近 nonce 记录，拒绝重复 |
| **幂等键** | `dedupId` 唯一索引 + upsert，重复上报不产生新记录 |
| **频率限制** | 云函数内按 `deviceId` 限流（如 ≤ 60 次/分钟、≤ 2000 次/天）；`devices.uploadEnabled` 可一键停用 |
| **体积限制** | 请求体 ≤ 64KB（曲线抽稀后远超不了）；`curve` 点数上限（如 ≤ 4000） |
| **数值范围校验** | 四维 ∈ [0,1] 或 [0,100]（依 `metricsNormalized`）；`composite ∈ [0,100]`；`t0_relative_duration_s ∈ (0, 3600]`，越界拒收 |
| **设备**白名单 | 未在 `devices` 注册的 `deviceId` 一律拒绝 |
| **告警** | 云开发「监控 → 告警」，配置云函数错误率/调用量突增告警 |
| **审计** | `experiments.createdAt` 用**服务端时间**；`devices.lastIp` 记录来源 IP，异常可追溯 |

### 7.4 越权访问防范（云函数内必须做）

```text
· getExperiments(scope:'mine')  → 服务端强制注入 openid == OPENID，忽略客户端传的 openid
· getExperimentDetail(expId)    → 先查库，比对 doc.openid == OPENID 或 OPENID ∈ devices.shareOpenids
· setCalibration                → 校验调用者是否为设备 owner / 管理员（不要只靠前端隐藏按钮）
· bindDevice                    → 事务 + 唯一性校验，防抢绑
· 所有 list 查询                 → fields 白名单，绝不返回 secretHash 等敏感字段
```

### 8.3 数据归属与隐私

- 数据存在**你自己的小程序云开发环境**里（腾讯云托管），**不经过任何第三方服务器**；
- 只采集**设备/实验数据**（力、位移、四维、评分、布料名），**不采集**姓名/手机号/位置等个人信息；
- 小程序需在「用户隐私保护指引」中说明数据用途；提供**数据删除**入口（云函数 `deleteMyData`，级联删除 `experiments` + 云存储文件）；
- 多用户共享时用 `shareOpenids` 显式授权，不做默认全员可见。

### 8.4 网络依赖与降级路径

| 场景 | 设备网页（本地） | 小程序（云端） |
|---|---|---|
| 有 WiFi + 有外网 | ✅ 实时 | ✅ 历史 + 准实时 |
| 有 WiFi + **无外网** | ✅ 实时（局域网内） | ❌ 无新数据（但可看已同步历史） |
| **无 WiFi**（AP 配网模式） | ✅ 可配网 + 实时 | ❌ |
| 断网后恢复 | ✅ | 设备队列自动重传 → 数据补齐 |

### 8.5 与"设备自带网页（产品形态 A）"如何共存

**分工原则：本地实时归设备网页，云端历史/远程归小程序。**

| 能力 | 设备内嵌页（产品形态 A，**保留**） | 小程序 + 云开发（本方案，**新增**） |
|---|---|---|
| 实时曲线/四维/评分 | ⭐**毫秒级**（WebSocket 直连） | 准实时（轮询，2–5s） |
| 离线可用 | ⭐**强**（局域网内即可） | 弱（依赖云） |
| 控制（ARM/START/STOP/RESET） | ⭐**支持**（`FRAME_CMD`） | 本地可（真机不行）；远程暂不支持（需上云下行，M4+） |
| WiFi 配网 | ⭐**门户配网**（唯一配网入口） | 仅引导用户去设备网页配网 |
| 历史记录 | 无（除非加 SD 卡） | ⭐**云端历史**（多设备/多用户/跨时间） |
| 数据导出/分享 | 无 | ⭐可做（CSV/图片/小程序分享） |
| 成本 | 0 | 云开发额度内极低 |

**关键：两者不是替代关系，产品形态 A 不做减法**——上云只是 `loop()` 里新增的一条 HTTPS 分支。

## 9. 分阶段实施（MVP → 完整）

### M1 — 云开发开通 + 最小闭环（**跑通"设备→云→看数据"**）

**任务**
1. 注册小程序（个人主体）→ 拿 AppID → 开发者工具新建项目；
2. 开通云开发 → 记 **环境ID** → `app.js` 里 `wx.cloud.init`；
3. 建 `experiments` 集合 + `dedupId` 唯一索引；
4. 建 **HTTP 云函数 `deviceUpload`**（先**不验签**，只做结构校验 + upsert）；
5. ESP32：加 `WiFiClientSecure` + `HTTPClient`，在 `STATE_DONE`（DEMO 模式下即可）POST 一条 JSON；
6. 在**云开发控制台数据库**里肉眼确认记录出现。

**验收标准**
- [ ] 小程序能打开，`wx.cloud.init` 无报错，控制台能读到环境；
- [ ] ESP32 串口打印 `POST 200, code=0, _id=xxx`；
- [ ] 云开发控制台 `experiments` 出现 1 条记录，四维与评分和 ESP32 内嵌页显示的**一致**；
- [ ] 断网重连后能补传（手工拔网验证 1 次）；
- [ ] **未改动** `protocol.h`、STM32 代码、现有配网/WebSocket/显示页。

### M2 — 小程序历史列表 + 详情（曲线/雷达图）

**任务**
1. 云函数：`getExperiments`（分页/筛选）、`getExperimentDetail`；
2. `experiments` 权限设为"仅本人可读、写禁止"；
3. 小程序页面：`history`（列表 + 筛选 + 分页）、`detail`（曲线 + 五边形雷达图 + 评分 + 四维）；
4. ESP32 侧补上曲线抽稀（20–50Hz）与云存储上传，或先只上传摘要；
5. `monitor` 页面接轮询（≥3s）做准实时。

**验收标准**
- [ ] 真机（体验版）能登录并看到自己的历史列表，分页正常；
- [ ] 详情页曲线与雷达图与设备网页**同源同形**（评分差 ≤ 0.1）；
- [ ] 另一微信号登录**看不到**别人的数据（权限规则生效）；
- [ ] 列表页 20 条加载 < 2s；详情页曲线渲染不卡顿（Canvas 2D）。

### M3 — 参考布料标定 / 权重下发

**任务**
1. 云函数：`getCalibration` / `setCalibration`；
2. `fabrics` 集合 + 参考布料标记（`isReference` / `refRole`）+ `calibration` 集合；
3. 小程序 `calibration` 页：勾选参考布料 → 自动算 min/max → 权重滑块 → **预览**（重算历史评分）→ 下发；
4. ESP32：启动/上报前拉取标定存 NVS；内嵌页 `WEIGHTS`/`RANGE` 改为读 NVS（**保留硬编码默认值兜底**；**正式评分/归一化以 STM32 为准**，标定值需最终同步到 STM32）；
5. `experiments` 记录 `calibrationVersion` / `weights` 快照。

**验收标准**
- [ ] 改权重后，**新实验**的云端评分与设备页评分一致（差 ≤ 0.1）；
- [ ] 标定版本可追溯：任一历史记录能看到它用的权重与标定版本；
- [ ] 设备断网时用 NVS 里的上次标定，仍能正常算/显示；
- [ ] 标定下发后**无需重新烧录固件**。

### M4 — 设备绑定 / 多设备 / 多用户

**任务**
1. 云函数：`bindDevice` / `getDevices` / `unbindDevice`（+ `claimCode` 机制）；
2. ESP32：首次配网成功后生成/显示 `claimCode`，并支持在设备页显示二维码；
3. 密钥体系上线：`deviceSecret` 注入 + HMAC 签名 + nonce/时间窗（§5.3）；
4. 多设备切换、数据看板（同布料跨设备对比）；`shareOpenids` 共享；
5. 进阶：`deleteMyData`、数据导出、（可选）HTTP 云函数 SSE 实时。

**验收标准**
- [ ] 用绑定码能把设备绑到自己账号；换账号绑定失败（已绑定提示）；
- [ ] 篡改请求体/重用签名/时间偏移 > 300s 均被云函数拒绝（400x 错误码）；
- [ ] 两台设备数据互不混淆，列表可按设备筛选；
- [ ] 解绑后不再能读取该设备数据；共享用户能只读查看。

### A.1 `deviceUpload/index.js`（HTTP 云函数）

```js
const cloud = require('wx-server-sdk');
const crypto = require('crypto');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const db = cloud.database();
const _ = db.command;

const MAX_SKEW_S = 300;
const CURVE_MAX_POINTS = 4000;

exports.main = async (event) => {
  // HTTP 云函数：body 在 event.body（字符串）或 event 已是对象，取决于触发形态
  const body = typeof event.body === 'string' ? JSON.parse(event.body || '{}') : (event.body || event);
  const headers = event.headers || {};

  const deviceId = headers['x-device-id'] || body.deviceId;
  const ts = Number(headers['x-timestamp'] || body.ts);
  const nonce = headers['x-nonce'] || body.nonce;
  const sign = headers['x-sign'] || body.sign;
  const { dedupId, payload } = body;

  // 1) 基础校验
  if (!deviceId || !dedupId || !payload) return err(4000, 'missing fields');
  const now = Math.floor(Date.now() / 1000);
  if (!ts || Math.abs(now - ts) > MAX_SKEW_S) return err(4013, 'timestamp skew too large');

  // 2) 设备校验
  const dev = await db.collection('devices').where({ deviceId }).limit(1).get();
  if (!dev.data.length) return err(4010, 'device not registered');
  const device = dev.data[0];
  if (device.status !== 'active' || device.uploadEnabled === false) return err(4011, 'device disabled');

  // 3) 签名校验
  //    ⚠️ 关键：签名必须覆盖【原始 body 的哈希】，不要用 JSON.stringify(解析后的对象)——
  //    重新序列化的键序/空格可能与设备端不一致，会导致签名永远对不上。
  const rawBody = typeof event.body === 'string' ? event.body : JSON.stringify(body);
  const bodyHash = crypto.createHash('sha256').update(rawBody, 'utf8').digest('hex');
  const want = crypto.createHmac('sha256', resolveDeviceKey(device))
    .update(`${deviceId}|${dedupId}|${ts}|${nonce}|${bodyHash}`).digest('hex');
  if (!timingSafeEqual(want, sign)) return err(4015, 'bad signature');

  // 4) 数值范围校验
  const v = validateMetrics(payload);
  if (!v.ok) return err(4020, v.msg);

  // 5) 幂等
  const exist = await db.collection('experiments').where({ dedupId }).limit(1).get();
  if (exist.data.length) return ok({ _id: exist.data[0]._id, dedup: true });

  // 6) 曲线写云存储（可选）
  let curveFileId = '';
  if (Array.isArray(payload.curve) && payload.curve.length) {
    const pts = payload.curve.slice(0, CURVE_MAX_POINTS);
    const up = await cloud.uploadFile({
      cloudPath: `curves/${dedupId}.json`,
      fileContent: Buffer.from(JSON.stringify({ t0: payload.t0_relative_duration_s, points: pts })),
    });
    curveFileId = up.fileID;
  }

  // 7) 写库
  const doc = {
    dedupId, deviceId: device.deviceId, deviceName: device.deviceName || '',
    openid: device.ownerOpenid || '',
    fabricId: payload.fabricId || '', fabricName: payload.fabricName || '', fabricCode: payload.fabricCode || '',
    mode: payload.mode || 'real', state: payload.state ?? 3,
    softness: payload.softness, smoothness: payload.smoothness,
    roughness: payload.roughness, rebound: payload.rebound, composite: payload.composite,
    metricsNormalized: !!payload.metricsNormalized, metricsFlags: payload.metricsFlags ?? 1,
    weights: payload.weights || null, calibrationVersion: payload.calibrationVersion || '',
    startedAt: payload.startedAt ? new Date(payload.startedAt) : new Date((ts - (payload.t0_relative_duration_s || 0)) * 1000),
    endedAt: payload.endedAt ? new Date(payload.endedAt) : new Date(ts * 1000),
    t0_relative_duration_s: payload.t0_relative_duration_s || 0,
    sampleCount: Array.isArray(payload.curve) ? payload.curve.length : 0,
    curveFileId, resultFileId: '',
    notes: payload.notes || '', operatorOpenid: device.ownerOpenid || '',
    syncState: 'ok', createdAt: new Date(), schemaVersion: 1,
  };
  const added = await db.collection('experiments').add({ data: doc });
  await db.collection('devices').doc(device._id).update({
    data: { lastSeenAt: new Date(), lastIp: headers['x-forwarded-for'] || '', fwVersion: headers['x-fw'] || '' },
  });
  return ok({ _id: added._id, dedup: false, curveFileId });
};

function ok(data) { return { code: 0, message: 'ok', data }; }
function err(code, message) { return { code, message, data: null }; }
function timingSafeEqual(a, b) {
  const x = Buffer.from(String(a)), y = Buffer.from(String(b));
  return x.length === y.length && crypto.timingSafeEqual(x, y);
}
// 生产写法：库中只存 secretHash = sha256(deviceSecret + salt)，此处用同一 salt 重算比对。
// 若要走 HMAC，则 HMAC 的 key 用"服务端派生密钥"（例如 sha256(secretHash + env pepper)），
// 而设备端用等价派生方式，从而避免把明文 secret 落库。
function resolveDeviceKey(device) {
  return crypto.createHash('sha256').update(String(device.secretHash) + process.env.KEY_PEPPER).digest('hex');
}
function validateMetrics(p) {
  const key = ['softness', 'smoothness', 'roughness', 'rebound'];
  const hi = p.metricsNormalized ? 1 : 100;
  for (const k of key) {
    const n = Number(p[k]);
    if (!Number.isFinite(n) || n < 0 || n > hi) return { ok: false, msg: `bad metric: ${k}` };
  }
  const c = Number(p.composite);
  if (!Number.isFinite(c) || c < 0 || c > 100) return { ok: false, msg: 'bad composite' };
  const d = Number(p.t0_relative_duration_s || 0);
  if (!(d > 0 && d <= 3600)) return { ok: false, msg: 'bad duration' };
  return { ok: true };
}
```

> ⚠️ 密钥校验的生产写法：**不要把明文 secret 存库**。推荐 `devices.secretHash = sha256(secret + salt)`，云函数用相同 salt 重算比对；若要走 HMAC，则 HMAC 的 **key 用服务端派生密钥**（如 `sha256(secretHash + 环境变量 pepper)`，设备端用等价派生方式），从而做到"库中无明文 secret 仍可验签"。
> ⚠️ **签名覆盖范围务必是"原始 body 的 sha256"**，而不是"解析后对象再 `JSON.stringify`"——后者在键序/空格/数字格式上可能与设备端不一致，导致签名永远校验失败（这是设备上云最常见的坑）。

### A.2 `getExperiments/index.js`（小程序可调用）

```js
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const db = cloud.database();
const _ = db.command;

exports.main = async (event = {}) => {
  const { OPENID } = cloud.getWXContext();
  const page = Math.max(1, Number(event.page) || 1);
  const pageSize = Math.min(50, Math.max(1, Number(event.pageSize) || 20));
  const w = {};
  if (event.scope !== 'all') w.openid = OPENID;            // 强制只看自己
  if (event.deviceId) w.deviceId = event.deviceId;
  if (event.fabricId) w.fabricId = event.fabricId;
  if (event.startTime || event.endTime) {
    const conds = [];
    if (event.startTime) conds.push(_.gte(new Date(event.startTime)));
    if (event.endTime) conds.push(_.lte(new Date(event.endTime)));
    w.startedAt = conds.length > 1 ? _.and(conds) : conds[0];
  }
  if (event.minComposite != null || event.maxComposite != null) {
    w.composite = _.and([
      _.gte(Number(event.minComposite ?? 0)),
      _.lte(Number(event.maxComposite ?? 100)),
    ]);
  }
  const fields = (event.fields && event.fields.length ? event.fields : [
    '_id', 'fabricName', 'fabricCode', 'composite',
    'softness', 'smoothness', 'roughness', 'rebound', 'startedAt', 'deviceId',
  ]).reduce((o, k) => (o[k] = true, o), {});

  const col = db.collection('experiments').where(w);
  const [cnt, list] = await Promise.all([
    col.count(),
    db.collection('experiments').where(w)
      .orderBy(event.orderBy || 'startedAt', event.order === 'asc' ? 'asc' : 'desc')
      .skip((page - 1) * pageSize).limit(pageSize).field(fields).get(),
  ]);
  return { code: 0, message: 'ok', data: { total: cnt.total, page, pageSize, list: list.data } };
};
```

### A.3 `setCalibration/index.js`（参考布料 → min/max + 下发）

```js
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const db = cloud.database();
const _ = db.command;
const KEYS = ['softness', 'smoothness', 'roughness', 'rebound'];

exports.main = async (event = {}) => {
  const { OPENID } = cloud.getWXContext();
  const { version, scope = 'global', deviceId = '', referenceFabricIds = [], weights } = event;
  if (!version || !referenceFabricIds.length) return { code: 4100, message: 'need version & reference fabrics' };

  const refs = await db.collection('fabrics')
    .where({ _id: _.in(referenceFabricIds), isReference: true }).limit(100).get();
  if (!refs.data.length) return { code: 4101, message: 'no reference fabrics found' };

  const ranges = {};
  for (const k of KEYS) {
    const vals = refs.data.map(f => Number(f.refMetrics?.[k])).filter(Number.isFinite);
    if (!vals.length) return { code: 4102, message: `missing refMetrics.${k}` };
    const lo = Math.min(...vals), hi = Math.max(...vals);
    // 留 5% 余量，避免新布落到边界外被 clamp 掉
    const pad = (hi - lo) * 0.05 || 0.05;
    ranges[k] = [Number((lo - pad).toFixed(4)), Number((hi + pad).toFixed(4))];
  }
  const w = weights || { softness: 0.30, smoothness: 0.25, roughness: 0.20, rebound: 0.25 };
  const sum = KEYS.reduce((s, k) => s + Number(w[k] || 0), 0);
  if (Math.abs(sum - 1) > 1e-6) return { code: 4103, message: 'weights must sum to 1' };

  const doc = {
    version, scope, deviceId, openid: scope === 'user' ? OPENID : '',
    ranges, weights: w, roughnessInverted: true,
    referenceFabricIds, sampleCount: refs.data.length,
    isActive: true, updatedBy: OPENID, updatedAt: new Date(),
  };
  await db.collection('calibration').add({ data: doc });
  // 同 scope/deviceId 下旧版本失效
  await db.collection('calibration')
    .where({ scope, deviceId, version: _.neq(version), isActive: true })
    .update({ data: { isActive: false } });

  return { code: 0, message: 'ok', data: { version, ranges, weights: w, isActive: true } };
};
```
