## 1. 总体架构与数据流

系统是一条"传感器 → STM32（采集/力控/特征） → ESP32（显示/转发） → 手机"的单向采集链路，控制闭环主要在 STM32 侧完成。

```text
┌─────────────── 六维力传感器 (RS485, USART1) ───────────────┐
│ 460800 bps · 500Hz 自主主动发送 · 28B 帧(点) · 帧头 0x53 0x54 │
│ 6×float32 小端 · CRC-16/MODBUS · 单点(one-shot)轮廓           │
└──────────────────────────┬──────────────────────────────────┘
                           │ 接收块 ISR: 拷贝+打时间戳+唤醒(异步)
┌─────────────── 振动 (ADXL335 模拟, ADC1) ───────────────────┐
│ ADC1 + TIM(1000Hz) + DMA 循环采样 · 3 轴(确定性定时触发)        │
└──────────────────────────┬──────────────────────────────────┘
                           │ ADC 半/满传递中断: 存样本+时间戳
┌─────────────── 三台闭环步进电机 (UART×3) ────────────────────┐
│ 速度/位置模式 · 细分16 · 螺距1mm/转 → 3200脉冲/mm · 行程50mm    │
└──────────────────────────┬──────────────────────────────────┘
                           │ 命令/响应 + 超时状态机(RT 实时)
┌─────────────── 视觉回弹测量 (摄像头, 测回弹) ──────────────────┐
│ OpenMV / ESP32-CAM / 树莓派相机 · 侧/顶视拍摄织物压陷与回弹恢复   │
│ 同步: STM32→GPIO 触发(开始/结束/T0) + 帧内同步LED 对齐视频T0    │
│ 通信: GPIO 触发/控制 + UART5 在线回传"回弹特征"给 STM32        │
└──────────────────────────┬──────────────────────────────────┘
                           │ 同步脉冲/触发 + UART5 回弹特征回传
                           ▼
        ┌───────────────────────────────────────────┐
        │        STM32F407 （FreeRTOS）              │
        │  · 主时基 = DWT 微秒计数(64位)             │
        │  · T0 = 实验开始                           │
        │  · 500Hz 主控节拍(力控)                    │
        │  · 任务: 控制/力解析/振动/特征评分/通信/健康 │
        └───────────────────┬───────────────────────┘
                            │ UART2 @ 460800 (二进制帧, protocol.h)
                            ▼
        ┌───────────────────┴───────────────────────┐
        │              ESP32-S3 (WebSocket)         │
        │  抽稀曲线 + 四维特征 + 评分 + 状态/命令         │
        └───────────────────┬───────────────────────┘
                            ▼
                        手机 (曲线 + 雷达图 + 评分)
```

**关键点**：
- 六维力是 **传感器自主推**（异步到达）。STM32 被动收，在 **接收事件 ISR 里记录字节块时间戳**，再由 `力解析` 任务组帧、校验并关联帧时间戳（精度约束见 §5.2），最后入样本环形缓冲。
- 振动由 **定时器确定性触发**（1000Hz），时序可预测。
- 两条链路**靠时间戳对齐**（按时间窗取段，必要时插值/取最近样本），**不逐点同步**。
- 控制闭环（Z 力控、X/Y 位置/速度）在 STM32 上以 **500Hz** 运行，由定时器信号量驱动。

## 3. 时间同步（关键）

### 3.1 主时基
- **主时基 = DWT 微秒计数器**，扩展为 64 位（`timestamp_us`），见 [5.1](#51-dwt-微秒计时)。
- **T0 = 实验开始**：在启动实验时执行"**记录 T0_us + 输出 T0 同步脉冲 + 开始记录实验数据**"。DWT 保持单调运行，不在实验开始时清零；同步脉冲与记录起点的偏差需测量。T0 同步脉冲可接外部示波器/记录仪，用于与力、振动、电机轨迹做离线对齐。
- 所有数据的时间戳统一换算为相对 T0 的秒：
  ```text
  t = (timestamp_us - T0_us) / 1e6   // 秒，float
  ```

### 3.2 500Hz 主控制节拍
- 由定时器生成 **500Hz** 信号量，驱动 `控制` 任务。
- **Z 轴力控**在每个 2ms 节拍内闭环一次（速度导纳 + PI，见 [5.7](#57-z-轴力控速度导纳--pi分阶段)）。
- 同一节拍内读取三台电机的**最新有效位置缓存**供阶段状态机与轨迹记录使用；`S_CPOS` 请求与回包由异步通信状态机处理，控制任务不得阻塞等待串口响应。
- **500Hz 是目标控制计算频率，不代表电机支持 500Hz 命令/位置回读**。按实际波特率、命令/响应字节数（8N1 每字节 10 bit）、驱动器处理时间核算吞吐与最坏延迟，分别确定下发和回读频率。尚未发出的速度指令可合并为最新值，避免积压。
- 每周期检查力/位置数据年龄及通信超时；阈值需实测确定，数据过期时进入停止/故障处理。记录控制执行耗时、周期超限和漏节拍，验证计算与必要调度可在 2ms 内完成。

### 3.3 时序对齐策略
| 数据 | 到达方式 | 打点位置 | 特征 |
|--|--|--|--|
| 六维力 | 传感器自推（异步） | 接收事件 **ISR**，任务关联到帧 | 帧间隔≈2ms，抖动取决于 Sensor 发送节奏 |
| 振动 | 定时器 1000Hz | 触发起点 + 样本序号；DMA 中断交付数据 | 每轴间隔 1ms，三轴扫描存在转换偏移 |
| 电机 | 命令/响应 | RT 任务内 | 来自响应回读 |

- 力与振动**靠时间戳对齐**：取某个时间窗 `[t, t+Δ]`，在力序列与振动序列中分别按时间戳取段；若采样率不匹配，则插值或取最近样本，**不做逐点同步**。
- 时间戳统一用 DWT 相对 T0 的微秒，保证两者可在同一时间轴上对齐。ADC 一块含多个样本时，按触发起点和样本序号重建各样本时间，不给整块样本赋同一个中断时刻；三轴扫描偏移及力传感器内部采样到串口接收的延迟需测量或记录。

## 4. FreeRTOS 任务划分

**调度策略**：优先级抢占 + 事件驱动（非轮转时间片）。ISR 只做"拷贝 + 打时间戳 + 唤醒信号量"，**长工作在任务里做**。

| 优先级 | 任务 | 触发 | 职责 |
|--|--|--|--|
| 高 | 控制 | 500Hz 定时器信号量 | Z 力控(速度导纳+PI)、X/Y 位置/速度、每阶段状态机、读电机位置 |
| 中 | 力解析 | 力帧 DMA 中断 → 队列 | CRC16 校验、解析 6 力、保留接收时间戳、入环形缓冲 |
| 中 | 振动采集 | ADC DMA 中断 | 存 ADXL 三轴 + 时间戳 |
| 中 | 特征 / 评分 | 窗口定时 | 滑窗算四维特征 + 融合评分（在 STM32 上） |
| 低 | 与 ESP32 通信 | 队列有数据才发 | 抽稀曲线(50–100Hz) + METRICS/SCORE/STATUS，460800 |
| 低 | 健康 / 调试 | 定时 | 心跳 / 看门狗 / 调试 |

**要点**：
- `控制` 任务优先级最高，保证力控节拍不被其它任务抢占。
- `力解析`/`振动采集` 是"ISR 入队，任务解析"的 SPSC 模式；无锁实现需满足下述所有权与可见性约束（见 [5.4](#54-hook回调事件注册表)）。
- `特征 / 评分` 任务只在"窗口积分满"/阶段切换时运行，负载可控（FFT 用滑窗，见 [6](#6-舒适度算法)）。
- `与 ESP32 通信` 是**数据驱动**（队列非空才发），并做曲线抽稀到 50–100Hz，避免 460800 带宽被满幅数据打满。

## 5. 关键模块设计（含 F407 移植说明）

### 5.1 DWT 微秒计时

**来源借鉴**：`source/bsp/dwt/dwt_bsp.c` / `dwt_bsp.h`（Engineer_26，STM32H723）。

核心实现（H7 原版）：
```c
void DWT_Init(uint32_t CPU_Freq_mHz) {
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;   // 使能 DWT 外设
    DWT->CYCCNT = (uint32_t)0u;
    DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;             // 使能 CYCCNT 计数
    CPU_FREQ_Hz = CPU_Freq_mHz * 1000000U;
    ...
}
uint64_t DWT_GetTimeline_us(void) { /* 32位回绕转64位, 见下 */ }
void DWT_Delay(float Delay) { /* CYCCNT 忙等 */ }
```

**64 位扩展（防回绕）**：CYCCNT 是 32 位，溢出会回绕。框架用 `DWT_CNT_Update()` 检测“当前计数 < 上一次”即溢出，`CYCCNT_RountCount++`，再合成 64 位：
```text
CYCCNT64 = ((uint64_t)CYCCNT_RountCount << 32) | (uint64_t)cnt_now
```

回绕基数为 `2^32`，不是 `UINT32_MAX`。168MHz 下约 **25.57s** 回绕一次，更新间隔必须小于该周期；可由固定周期中断维护。任务与 ISR 共享扩展状态时须保证更新/读取一致性，不能假设 64 位读写原子化；避免高优先级 ISR 自旋等待被其抢占的写者。

**F407 移植要点**：
1. 把入参改为核时钟 **168MHz**：`DWT_Init(168)`。
2. 其余接口（`DWT_GetTimeline_us` / `DWT_GetDeltaT` / `DWT_Delay`）可借鉴；回绕扩展与并发访问需按上述约束修正，**寄存器名一致**（`CoreDebug->DEMCR`、`DWT->CYCCNT`、`DWT->CTRL`）。
3. 移植后建议用 `DWT_Delay(0.5)` 对比一已知延时（如 SysTick）标定，确认 168MHz 换算正确。
4. 若开启 DWT 计时后出现 `DWT_GetTimeline_us` 精度异常，先检查 DWT 是否被调试器关闭（`TRCENA` 位）。

> 高分辨率计时也可用 `TIM`（如 TIM5 32 位）兜底；但 DWT 开销最小、无外设占用，作为主时基更合适。

### 5.2 UART/DMA + 环形缓冲 + 流式帧解析

**来源借鉴**：
- `source/bsp/uart/uart_api.c` + `uart_bsp.c`（`uart_rx_init`/`uart_rx_hook_reg`/`HAL_UARTEx_RxEventCallback`）
- `source/module/refereeSys/referee_api.c`（`ring_buffer_t{head/tail}` + 流式帧解析状态机：找 SOF → CRC8 验头 → 取长 → 凑帧 → CRC16 → 解析 → 失败丢 1 字节重同步）
- `source/module/computer/vision/vision_receive.c`（定长帧例）

本设计对**RS485 力传感器(28B 帧)** 与**电机 UART 命令/响应** 复用同一套三层结构：

**三层**：
1. **DMA-to-idle 接收字节块**（`HAL_UARTEx_ReceiveToIdle_DMA`，确认所用 HAL 版本支持）：处理 IDLE/半传输/全传输事件，按 DMA 写入位置提取新增字节，避免重复消费。**回调边界不等于协议帧边界**，可能出现半帧、多帧或跨回调帧；`ReceiveToIdle_IT` 是中断接收接口，不是 DMA。
2. **SPSC 环形缓冲**（`ring_buffer_t`：`head`/`tail`）：ISR 侧写、任务侧读。无锁前提是双方分别独占 head/tail，索引读写原子且数据先于索引发布（使用适当原子操作/内存屏障）；多个中断来源不得并发写同一生产端，并需定义缓冲溢出策略及丢帧计数。
3. **流式帧解析状态机**：从环形缓冲按"头 → 长度 → 校验 → 解析"循环取完整帧。

**流式帧解析循环（STM32↔ESP32 协议伪码，以当前 `src/protocol.h` 为准）**：
```text
while (ring_available() >= 4) {
    skip_until_sync(0xAA, 0x55);
    if (ring_available() < 4) break;
    ring_peek(header, 4);                 // 查看，不消费
    if (!valid_type_and_length(header)) { discard(1); continue; }
    frame_len = 4 + header.len + 1;       // 无独立头 CRC，尾部只有 CRC8
    if (ring_available() < frame_len) break;
    ring_peek(frame_buf, frame_len);      // 校验前不移除候选帧
    if (crc8_over(frame_buf, frame_len - 1) != frame_buf[frame_len - 1]) {
        discard(1); crc8_fail++; continue;
    }
    discard(frame_len);
    parse_frame(frame_buf, frame_len);
}
```

`valid_type_and_length` 校验已知类型、对应载荷长度及目标缓冲容量；不完整候选帧需设置超时，以免异常长度长期阻塞解析。力传感器另用 `0x53 0x54 + 24B 数据 + 2B CRC16` 的定长解析器，电机按厂家协议解析；三者复用字节接收层，不混用校验格式。接收块时间戳需随数据保留，跨块帧按含最后字节的块关联时间；若需更精确的帧完成时间，应专门设计接收事件或按已知串行时序估算，不能把 IDLE 回调等同于采样时刻。

**RS485 方向控制**：
- 用 **DE/RE 方向脚**（GPIO）控制收发方向。
- 发送完成后在 `HAL_UART_TxCpltCallback` 里**拉低 DE** 恢复接收状态（否则收不到从机应答）。

**F407 移植要点**：
- DMA 接收采用 `HAL_UARTEx_ReceiveToIdle_DMA`，先核对工程 HAL 版本及 DMA 配置；若版本不支持则实现 IDLE + DMA 接收（注意 `UART_HandleTypeDef` 的 `Instance` 宏依芯片而定，如 `UART5`/`USART6`）。
- 环形缓冲 `RING_BUF_SIZE` 需 ≥ 容纳多帧；力传感器帧 28B，`UART1` 的 DMA 缓冲建议 ≥ 64B。
- 用于电机的命令/响应帧长较短，可单独用"定长帧"例（参照 `vision_receive.c` 的 `memcpy` + `Verify_CRCXX`）。

### 5.3 CRC 校验

**来源借鉴**：`source/bsp/crc/crc_api.c` / `crc_api.h`（表驱动 CRC8 / CRC16）。

| 用途 | 算法 | 多项式 | 初值 | 备注 |
|--|--|--|--|--|
| STM32↔ESP32 帧（`protocol.h`） | **CRC-8** | **0x31** | **0xFF** | `build_frame` / `crc8_over` |
| 力传感器帧 | **CRC-16/MODBUS** | **0x8005** | **0xFFFF** | 见下方说明 |
| 电机指令/响应 | CRC-16/MODBUS 或厂家约定 | — | — | 以电机手册为准 |

**说明**：
- `protocol.h` 内联 `crc8_over` 用逐位法；`crc_api.c` 用 256 表加速（`CRC8_INIT=0xFF`）。替换为表驱动前必须核对反射方向、初值及异或输出，并用同一测试向量比对，不能仅凭多项式名称判断等价。当前 `protocol.h` 使用左移、非反射实现。
- 不能将参考框架的 CRC16 表直接认定为 MODBUS 表。力传感器必须使用独立核验过的 **CRC-16/MODBUS** 实现（poly 0x8005、反射实现用 0xA001、init 0xFFFF、无 XOR-out）；参考表及函数需通过已知报文比对后才能复用。
- **注意**：CRC 字节端序（低字节在前还是高字节在前）与帧字节序（float 小端）均需与传感器数据手册核对，建议先用已知样本在调试口验证一次。

**F407 移植**：CRC 表与校验函数为纯软件、与芯片无关，确认算法参数和测试向量一致后可移植；如需 CPU 硬件 CRC 外设可另评估（F407 只有 CRC32，不适合 CRC16/MODBUS，故建议保留软件表驱动）。

### 5.4 hook/回调事件注册表

**来源借鉴**：`uart_api.h` 中 `uart_rx_hook_reg(uart_rx_t*, void(*hook)(uint8_t*, uint32_t))` + 每串口一个函数指针 `uartN_rx_hook`。

**设计**：函数指针表 + `Reg()` + 在 ISR 触发 + "ISR 入队 / task 解析" SPSC，遵循 §5.2 的并发约束；回调应在启用接收中断前注册完成。

```text
uart_rx_hook_reg(&uartN_rx, my_hook);      // 注册
// uart_bsp.c: HAL_UARTEx_RxEventCallback 里:
//   -> 若 hook != NULL: hook(pData, size);   // 在 ISR 里调用
```

**要点**：
- 注册表按外设（UART/ADC/定时器）维度维护一个函数指针，避免各模块硬编码到某个具体中断里。
- 上层模块负责"拷贝 + 打时间戳 + 入队列"，**不在 hook 里做重活**。
- `hook` 在 ISR 上下文执行，需保证**短促**（只入队、打时间戳），长工作在对应任务中做。
- 回调注册**只注册一次**（`uart_reg_cheak` 会拒绝重复注册），防止重复叠加。

### 5.5 看门狗 / 健康监控（**计划，暂缓实现**）

> ⚠️ 当前阶段**暂缓**，本文档标注为"计划"项，不阻塞现有功能。

**来源借鉴**：`source/task/Watchdog_Task/`（`Watchdog_Task.c`/`.h` + `watchdog_config.h`）+ `Chassis_Task` 的 `Chassis_ForcePowerOff(flag)`。

设计为**两级**，且**它不是硬件看门狗、不复位**（软件层只做"在线检测 + 报警 + 标志解耦"）：

| 级别 | 机制 | 行为 |
|--|--|--|
| 硬件 | **IWDG**（F407 LSI≈32kHz，`prescaler=128, RLR=499 → 约 2.0s`；喂狗周期 **100ms**） | 兜底硬复位，防止系统完全崩溃 |
| 软件 | **低优先级喂狗任务 + 心跳门控** | 只有所有关键任务心跳新鲜才喂狗；喂狗任务优先级低于被保护实时任务，高优先级卡死 → 饿死喂狗 → 复位 |

**IWDG 时间计算**（F407）：
```text
LSI ≈ 32kHz
prescaler=128  ->  LSI/128 = 250Hz  ->  T_tick = 4ms
RLR=499        ->  溢出事 = (499+1) * 4ms = 2000ms ≈ 2.0s
喂狗周期        ->  100ms << 2.0s，余量充足
```

**软件层复用 DX 框架的设计**：
- `Watchdog_IsOnlineByCnt`：心跳计数 / 在线检测（有变化即刷新 `last_rx_ms`；无变化但未超时仍判在线）。
- `Watchdog_AlarmUpdate`：报警状态机（`alarm_active / alarm_type / alarm_start_ms`）。
- `__weak` 回调：`Watchdog_OnXxx_Online/Offline/Error`，用户可在别处重写空实现。
- `Watchdog_SetEnabled` / `Watchdog_IsEnabled`：运行时开关（默认关闭，调试时可开）。
- `watchdog_config.h`：集中超时宏（离线超时、报警时长、喂狗周期等）。
- **`Motor_Safety_PowerOff(flag)`**：只设标志解耦——函数仅置位/清位一个标志，真正掉电动作在别的高优先级上下文里消费该标志（对应 DX 的 `Chassis_ForcePowerOff`）。

**蜂鸣器报警设计**（**无源蜂鸣器**，需 PWM 驱动）：
- 用 **定时器 PWM** 产生音符：配置 TIM 通道输出方波，**频率**由 `prescaler/ARR` 决定、**占空比（约50%）**由 CCR 决定；无源蜂鸣器靠**改变频率/节奏**发出不同音调。驱动链路：`TIM PWM` → 三极管 → 无源蜂鸣器。
- 常用 API：`Buzzer_SetFreq(freq_hz)`（改频率，如 2~4kHz）、`Buzzer_On()`/`Buzzer_Off()`（开/停 PWM），可组合成"单次提示音 / 急促报警 / 长鸣"。
- 事件 → `Alarm_SetPattern(id)`，按"事件类型"选**音调 + 节奏**（对应 DX `Watchdog_AlarmStart`/`AlarmUpdate` 的频率爬升逻辑；无源可实现**不同音高**区分事件）。
- **采样期间静音**：为避免蜂鸣器音频/振动污染振动传感器（ADXL335）与音频采集，实验进行中禁止蜂鸣器发声（`Buzzer_Off()`）。

**F407 移植要点**：DX 框架的看门狗是 `Watchdog_Task` 软件任务 + 蜂鸣器；F407 需**新增硬件 IWDG**（DX 示例无 IWDG），并在 `main` 里初始化。软件部分直接搬 `Watchdog_Task.c/.h` + `watchdog_config.h`，把 `Chassis_ForcePowerOff` 换成本项目的 `Motor_Safety_PowerOff`。

### 5.6 闭环步进电机控制

**来源借鉴**：`module/motor/`（命令码 → 查对象链表 → 超时状态机）；`motor_basic.h`（电机对象结构）。

**硬件/传动参数**：
- 3 路 UART，命令/响应 + 超时 + 状态机，命令码分发。
- 闭环步进，使用 **速度/位置模式**；细分 **16**。
- **mm ↔ 脉冲** 换算：
  ```text
  200 步/转 × 16 细分 = 3200 脉冲/转
  螺距 1mm/转            → 3200 脉冲/mm
  50mm 行程              → 160000 脉冲
  速度: v(mm/s) × 3200          → 脉冲/s
        v(m/s) × 1000 × 3200    → 脉冲/s
  ```

**关键接口（Emm 系列）**：
| 接口 | 作用 |
|--|--|
| `Emm_V5_Pos_Control(addr, dir, vel, acc, clk, raF, snF)` | 位置控制（速度/加速度/相对-绝对标志） |
| `Emm_V5_Vel_Control(...)` | 速度控制 |
| `Emm_V5_En_Control(...)` | 使能/失能 |
| `Emm_V5_Read_Sys_Params(..., S_CPOS, ...)` | 读实时位置 |
| `Emm_V5_Reset_CurPos_To_Zero(...)` | 当前位置清零 |

**命令分发/状态机（参照 `module/motor`）**：
- 命令码 → 查对象链表（每台电机一个对象，含 `addr`/模式/位置/速度/状态）。
- 发送命令后启动**超时计时**；收到响应/回读则刷新对象；超时未回则打"离线"标志并回调健康任务。
- 状态机管理：使能 → 定位/匀速 → 到位/保持 → 停止/失能。

**F407 移植**：三台电机分别挂 USART3 / UART4 / USART6。注意 F407 `UART4`/`USART6` 与 H7 编号/`Instance` 宏不同；`HAL_UART_Transmit_IT` / 中断回调接口一致。

### 5.7 Z 轴力控（速度导纳 + PI，且 Z 分阶段）

**总原则：Z 不是一直恒力**，按实验阶段切换控制模式：

| 阶段 | Z 控制方式 | 说明 |
|--|--|--|
| 轻触 / 接近 | **位置** | 先下降到接近织物的位置 |
| 按压保持 (0.5–5N, 2s) | **力** | 闭环控制法向力 Fz |
| 恒压滑动 / 往复摩擦 | **力（恒力闭环）** | 保持恒 Fz，X/Y 做滑动 |
| 一维揉搓 | **混合** | Fz 基线 + 微扰（叠加正弦/扰动） |
| 按压释放 | **位置** | 退回初始位置 |

**力控算法（速度导纳 + PI）**：
- Fz 误差 → **PI** → Z 速度指令（速度导纳形式）。软、随织物形变进退——织物软则 Z 轴自动"退让"，避免突然顶死。
- 数据处理：
  - Fz **低通** fc≈30Hz（滤传感器纹波与振动信号耦合）。
  - **抗饱和**（anti-windup）：防止积分累积导致超调。
  - **限幅/限变化率**：限制 Z 速度幅值与加速度，保护织物与电机。
  - **死区**：Fz 误差小于死区时输出为 0，避免稳态抖动。
- **初参建议**：
  ```text
  Kp  ≈ 3–8   (mm/s)/N
  Ki  ≈ 0.05–0.2
  v_max ≈ 8 mm/s
  ```
- **标定顺序**：先在一批**硬布料**上用低增益标定，确认闭环稳定后再放开增益到软布料。

**对比说明**：位置式导纳（参考位置 + 导纳修偏）偏硬，响应更"刚性"；本设计采用**速度导纳 + PI**，输出的是 Z 速度，柔顺性更好，适合织物这类大柔顺对象。

### 5.8 摄像头（视觉回弹测量）与 STM32 的通信与同步

摄像头用于**测回弹**：侧/顶视拍摄织物在"按压→卸载"后的**压陷与回弹恢复过程**，得到回弹恢复曲线（`6.1` 回弹维度的视觉输入，与力传感器的卸载恢复曲线互补）。

**它与 STM32 的通信分两部分**：

1. **同步（对齐视频 T0）—— 必须**
   - STM32 在 T0 时刻输出一个**GPIO 触发/同步脉冲**（同时按任务书给"开始/结束**双脉冲**"），并配合**画面内同步 LED**（首次亮起帧作为视频 T0）。
   - 摄像头据此把**视频/图像的时间轴对齐到 STM32 的 T0**（与力、振动、电机轨迹统一时基），便于离线逐帧对齐回弹曲线。
   - 方式：`STM32 GPIO → 摄像头 外部触发/帧同步引脚`，或`帧内 LED`（任务书做法）。

2. **控制 / 数据回传（在线，UART5）**
   - **控制**：STM32 通过 **UART5** 向摄像头发"arm/start/stop"命令（也可用 GPIO 触发线，按摄像头模型定）。
   - **数据**：摄像头（如 OpenMV，自带视觉处理）在"卸载→回弹"阶段测量织物的**压陷/回弹恢复曲线**，算出回弹特征后经 **UART5 在线回传**给 STM32；STM32 在 `特征/评分` 任务里接收，并入"回弹"维度。
   - **帧格式**（复用 §5.2 的流式帧解析）：`0xAA 0x55 [type][len][payload][crc8]`，其中 `type = FRAME_CAM_REBOUND`，`payload = cam_rebound_t`：
     ```c
     #pragma pack(push,1)
     typedef struct { float recovery_ratio;  // 回弹恢复比例(0~1, 越接近1越好)
                      float recovery_time_s; // 回弹恢复时间(s, 越短越好)
                      uint8_t valid;         // 有效标志(bit0)
                    } cam_rebound_t;
     #pragma pack(pop)
     ```
   - **速率**：回弹特征在每个实验的"卸载→回弹"段结束后**发一次**（低频），**115200 baud 足够**；STM32 用时间戳对齐。
   - **时间戳**：摄像头帧带到 `ts_us`（相对 T0），STM32 据此与力/振动回弹曲线对齐。

**接口抽象**：
```c
void Cam_Sync_Pulse(void);                 // T0/开始/结束 同步脉冲(GPIO)
int  Cam_Start(void); int  Cam_Stop(void); // 控制(经 UART5)
typedef struct { float recovery_ratio; float recovery_time_s; uint8_t valid; } cam_rebound_t;
int  Cam_Read_Rebound(uint32_t *ts_us, cam_rebound_t *out);  // 取最新回弹特征+时间戳
```

> 通信已定：**同步用 GPIO 触发 + 帧内同步LED，数据用 UART5 在线回传**。剩余需确认的只有**摄像头具体型号**（OpenMV/ESP32-CAM/树莓派）与同步脚接线（见 §8.2）。

## 6. 舒适度算法

基于**任务书第七节**：四维特征 **在 STM32 上归一化到 [0,1]**、综合评分(0-100) **在 STM32 上计算**，为**权威值**；前端只显示。DEMO 模式下前端 JS 融合**仅为演示**，不代表正式链路。权重 / 归一化区间可调整，但**正式以 STM32 为准**，前端 `RANGE`/权重仅用于 DEMO/展示或可选微调。

### 6.1 四维特征定义

| 特征 | 对应 `MetricsFrame` | 阶段/数据 | 原始公式 | 越高语义 |
|--|--|--|--|--|
| **柔软度** | `softness` | 按压段 | **z–Fz 曲线回归斜率取倒数** | 越软→加载越缓→斜率越小→分越高 |
| **顺滑度** | `smoothness` | 恒压匀速滑动 | **动摩擦系数 μ = √(Fx²+Fy²)/Fz** | μ 越小越顺滑→分越高 |
| **细腻度/粗糙度** | `roughness` | 振动窗 | **Hann 加窗 + FFT，取有效纹理频段 RMS（暂定 200–400Hz，待实测确认）** | 越粗糙→RMS 越大→分越低（融合时取反） |
| **回弹** | `rebound` | 卸载段 | **恢复速度 + 滞回比 (A_loop/A_loading)** + **摄像头视觉回弹** | 恢复越快越好→分越高 |

**说明**：
- **柔软度**：对按压段 (z, Fz) 做线性回归得斜率 `dFz/dz`，取倒数 `1/slope`；越软→加载越缓→斜率越小→`1/slope` 越大→分越高。
- **顺滑度**：恒压匀速滑动期间，以 Fz 归一化切向合力得 **动摩擦系数 μ**；μ 越小越顺滑→分越高。
- **细腻度/粗糙度**：对振动窗（1024–2048 点）做 **Hann 加窗 + FFT**，统计**有效纹理频段 RMS（暂定 200–400Hz，待实测确认）**；粗糙表面高频能量大，RMS 大→分越低；方向为"越小越细腻"（`protocol.h` 注明**融合时取反**）。1000Hz 是每轴采样率，奈奎斯特频率为 500Hz；实际频带需结合传感器、模拟抗混叠滤波与噪声标定确定。若需分析至 5kHz，应更换具备相应带宽的传感链，并将每轴采样率提高到大于 10kHz、为滤波过渡带留余量。1024–2048 点在当前采样率下对应 1.024–2.048s，须与实验阶段长度匹配。
- **回弹**：卸载后取**恢复速度**与**滞回比（A_loop/A_loading，加载-卸载曲线包围面积 / 加载面积）**；恢复越快、滞回越贴近理想弹性→分越高。**视觉辅助**：摄像头测织物的**压陷/回弹恢复曲线**（恢复时间、恢复比例，边缘/高度恢复），与力卸载曲线互补；若摄像头在线回传 `cam_rebound_t`，STM32 把它与力通道融合后再归一化。

### 6.2 归一化（**在 STM32 上做，权威**）
- 各原始特征在 **STM32 上**映射到 **[0,1]**：`norm = clamp((x - min)/(max - min), 0, 1)`。
- **min/max 用"参考布料集"标定**（在 STM32 上执行，为**权威值**；前端 `RANGE` 仅供 DEMO/展示或可选微调，正式归一化区间**以 STM32 为准**）。参考布料集的选取需覆盖"最软/最硬、最滑/最糙"边界。
- 统一字段方向：`softness = norm(1/slope)`；`smoothness = 1 - norm(μ)`；`roughness = norm(频带RMS)`，值越大越粗糙，**归一化时不取反，仅在评分时取反一次**；`rebound` 将恢复时间、滞回比等原始量统一成越大越好的方向后融合，具体映射待标定。
- `max > min` 才能归一化；回归斜率、法向力分母、数据有限性及有效样本数需检查，不满足条件时标记无效，不输出看似有效的评分。

### 6.3 融合评分
- 权重：`{软 0.30, 滑 0.25, 糙 0.20, 弹 0.25}`。
- 细腻度(`roughness`)在融合时取反：
  ```text
  score = ( 0.30 * softness
          + 0.25 * smoothness
          + 0.20 * (1.0 - roughness)   // 细腻度取反
          + 0.25 * rebound ) * 100
  ```
- 输出 **0–100 综合评分**（对应 `FRAME_SCORE`）。

> 与 ESP32 `main.cpp` 内 `WEIGHTS={softness:0.30,smoothness:0.25,roughness:0.20,rebound:0.25}`、`RANGE={softness:[0,1],...}`、`g_score=fused*100` 保持同口径（便于比对）。**正式以 STM32 为准（权威）**：STM32 归一化到 [0,1] 并算综合评分，前端只显示；DEMO 下前端 JS 融合仅供演示，权重 / 归一化区间可调整，但前端权重仅用于 DEMO/展示或可选微调。

### 6.4 滑窗 / 阶段
- 特征按**实验阶段**（按压 / 保压 / 滑动 / 往复 / 揉搓 / 释放）+ **时间窗**计算。
- 振动用**滑窗 FFT**（每次移动固定步长，重叠或非重叠），在 `特征/评分` 任务内做。
- `MetricsFrame` 对应 `softness/smoothness/roughness/rebound/flags`（`flags` bit0 = 数据有效），并可由 `FRAME_SCORE`（0–100）一并发出。

## 7. STM32↔ESP32 通信协议

**使用 `protocol.h`**（二进制帧，小端；`[0]=0xAA, [1]=0x55, [2]=type, [3]=len, [4..]=payload, [last]=crc8`，CRC-8 poly 0x31/init 0xFF）。

| 帧类型 (`FrameType`) | 载荷 | 方向 | 内容 |
|--|--|--|--|
| `FRAME_DATA` (0x01) | `TouchFrame` | STM32→ESP32 | 抽稀曲线（t,x,y,z,Fx,Fy,Fz,Mx,My,Mz,contact），**抽稀到 50–100Hz** |
| `FRAME_METRICS` (0x03) | `MetricsFrame` | STM32→ESP32 | 四维特征（softness/smoothness/roughness/rebound/flags） |
| `FRAME_SCORE` (0x04) | `float` | STM32→ESP32 | 综合评分 0–100 |
| `FRAME_STATUS` (0x02) | `uint8` | STM32→ESP32 | 实验状态机（STATE_IDLE/ARMED/RUNNING/DONE/ERROR） |
| `FRAME_CMD` (0x05) | 命令 | ESP32→STM32 | arm / start / stop / reset |

**波特率**：**460800**。

**建议补充**：加一帧 `STATS`，带 `sample_counter` + `dropped`，用于统计丢帧/时序，便于调试与链路健康评估。

**时间戳**：帧内 `t` 用 DWT 相对 T0（秒，见 [3](#3-时间同步关键)）。

## 8. F407 移植注意与待定项

### 8.1 移植注意
1. **DWT**：入参改 **168MHz**；寄存器名与 H7 一致，借鉴 `DWT_Init/GetTimeline_us/GetDeltaT/Delay`，按 §5.1 修正回绕转 64 位与并发访问。
2. **UART 编号**：F407 只有 `USART1/2/3`、`UART4`、`UART5`、`USART6`；"UART6"在 F407 上实为 `USART6`。三台电机建议 `USART3/UART4/USART6`，摄像头使用 `UART5`，调试使用 SWO/ITM。
3. **IWDG（新增）**：F407 硬件 IWDG 用 LSI≈32kHz，`prescaler=128, RLR=499 → 约 2.0s`，喂狗 100ms；DX 框架无 IWDG，需在 `main` 初始化并接入"全部机器心跳新鲜才喂狗"的门控。
4. **RS485 方向脚**：在 `HAL_UART_TxCpltCallback` 拉低 DE；无硬件流控，务必处理收发方向切换。
5. **CRC**：软件表驱动，与芯片无关；力传感器用 **CRC-16/MODBUS**（poly 0x8005/init 0xFFFF/反射），字节端序需核对。
6. **ADC1 + TIM + DMA**：F407 ADC1 支持 DMA + 外部触发，用 TIM（如 TIM2）作 1000Hz 触发源，3 轴循环采样。
7. **FreeRTOS**：按 [第4节](#4-freertos-任务划分) 的任务表建 6 个任务；ISR 只"拷贝+打时间戳+唤醒"，长工作在任务。

### 8.2 待确认 / 待补充项

| 项 | 说明 | 需确认 |
|--|--|--|
| **振动传感器带宽** | ADXL335 及板上滤波的实际带宽需按器件手册、外接电容和实测确认。当前每轴 1000Hz 采样，分析频段暂定 **200–400Hz**；若必须覆盖 5kHz，需重新选型传感器、抗混叠滤波和采样率。 | 与硬件/任务书核对 |
| **力控参数** | 初参 `Kp≈3-8 (mm/s)/N、Ki≈0.05-0.2、v_max≈8mm/s`、Fz 低通 fc≈30Hz、死区/限幅——需现场实测标定。 | 现场标定 |
| **权重标定** | 权重 `{0.30/0.25/0.20/0.25}` 与归一化 **min/max 参考布料集**需你确认/替换；两者**正式以 STM32 为准**，前端 `RANGE`/权重仅供 DEMO/展示或可选微调。 | 用户确认 |

| **回弹滞回比** | `A_loop/A_loading` 的积分窗口与"卸载段"时间窗需定义。 | 细化 |
