# 数据保存

测评日志固定为 `/sdcard/data_touch_results/u_curve.txt`，无表头，每行只有“测评序号、U_curve”，不记录日期或时刻：

```text
1,0.581635
2,0.632418
3,0.497263
```

- 序号表示成功保存的测评次数，从 1 开始。生产测评和 `capture_evaluate_save()` 共用序号，重启后接着已有日志递增。失败测评在回滚成功后不占序号。
- U_curve 保留六位小数。首次使用时逐行校验日志；之后缓存计数，每次只检查文件大小、刷新追加内容并回读新增字节，不反复读取全文。
- 旧的“时间戳、U_curve”日志首次使用时转换为编号格式，原文件保留为 `u_curve.txt.legacy`；已有备份不会覆盖。
- 这版 CanMV 固件不支持重命名覆盖已有文件。替换时使用 `.replace_previous` 保留原文件，启动时恢复中断的替换；历史备份仍保留。
- 没有换行但内容完整的末行会补上分隔换行。未写完整的尾部会备份为 `.recovered` 后恢复；中间损坏、编号不连续或完整行格式错误会明确报错，不跳过记录。
- 短写入、刷新、关闭或回读失败会报错，并尝试恢复追加前的内容。异常内容保留在 `.failed` 备份。若 SD 故障使回滚也失败，会同时报告两个错误，此时需检查 SD 卡及备份，不能当作保存成功。
- 调试测评照片使用 `/sdcard/debug_capture/measure_1.jpg` 等名称，与日志序号对应。照片先写入 `.pending`，刷新后再计算和提交；普通失败时清理本次照片，断电遗留的未提交照片在再次使用该序号前归档为 `.orphan`，不覆盖。
- `capture_once()` 使用独立的 `capture_1.jpg` 等编号，不增加测评次数；`evaluate_once()` 只计算和打印，不保存或增加计数。生产模式仍只保存评分。
- UART 发送失败不会撤销已成功保存的评分，程序返回带 `uart_ack=False` 的测评结果。
- 使用上传脚本的 `ResultBackupPath` 恢复日志时，先上传到暂存文件，再保留设备原日志为 `.before_restore`，最后替换；普通代码上传不会清空结果日志。

应用启动、模式切换、照片命名和代码上传已移除 RTC 设置及时间快照保存。`runtime_ms` 等性能耗时仍用于控制台诊断，不写入测评日志。

照片与日志分属两个文件，不能承诺任意断电时刻的跨文件原子提交；上述尾部恢复和遗留照片归档用于处理这种情况。

主机回归命令：

```powershell
python -B -m unittest discover -s K230/tests -v
```

更新开发板时需上传本次修改的 `main.py`、`mode_config.py`、`debug_main.py`、`data_touch/app.py` 和 `data_touch/result_log.py`，然后重启以清除旧模块缓存。旧格式日志会在新程序首次初始化测评日志时转换。
