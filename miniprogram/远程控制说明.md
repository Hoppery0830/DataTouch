## 1. 整体链路

```
                ① callFunction(sendCommand)
   小程序 控制页 ─────────────────────────▶ 云函数 sendCommand
   pages/control                                  │ 写一条 pending（60s 有效）
                                                  ▼
                                        ┌───────────────────────┐
                                        │  云数据库 commands     │
                                        └───────────────────────┘
                                                  ▲ │
        ③ ack（置 done + result）                  │ │ ② poll（取走 pending→sent，
   设备 ESP32 ──HTTP──▶ 云函数 deviceCommand ──────┘ └─ 顺带把超时的 pending → expired）
   （HTTP 访问服务路由 /deviceCommand，token 校验）
```

时序：点按钮 → 命令入库（待发送）→ 设备下一次轮询取走（已下发）→ 设备执行完回执（已执行）。
若 60 秒内没有任何设备取走，命令会在**下一次该设备轮询时**被惰性标记为「已过期」。

## 2. 集合 `commands`（需要你手动新建）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `deviceId` | string | 目标设备号，如 `esp32-dev01` |
| `cmd` | string | 命令，白名单：`arm` \| `start` \| `stop` \| `reset` \| `mode_press` \| `mode_rub` \| `mode_slide` |
| `state` | string | `pending`(待发送) \| `sent`(已下发) \| `done`(已执行) \| `expired`(已过期) |
| `openid` | string | 下发该命令的小程序用户 openid（云函数用 `cloud.getWXContext()` 取，审计用） |
| `createdAt` | Date | 服务端时间（`db.serverDate()`） |
| `expiresAt` | Date | `createdAt + 60s`（`new Date(Date.now()+60000)`），过了就作废 |
| `sentAt` | Date? | 设备取走（poll）的时刻，由 `deviceCommand` 回填 |
| `doneAt` | Date? | 设备确认执行（ack）的时刻，由 `deviceCommand` 回填 |
| `result` | string? | 设备回执内容（如 `ok` / `busy` / 错误码），最长 500 字符 |

**建议索引**（控制台 → 数据库 → commands → 索引管理）：

| 索引名 | 字段 | 类型 |
| --- | --- | --- |
| `idx_device_state` | `deviceId`(升序) + `state`(升序) | 复合，非唯一 |
| `idx_created_desc` | `createdAt`(降序) | 单字段，非唯一 |

- `idx_device_state`：`deviceCommand` 的 poll/过期清理都用 `deviceId + state` 过滤，建了才高效。
- `idx_created_desc`：小程序控制页按 `createdAt` 降序取最近 10 条；不建也能跑（数据少时），
  但记录多了之后查询可能报「排序字段缺索引」。

> 建议（可选，不影响功能）：给 `commands` 加一个定时清理（云开发控制台 → 定时触发器或
> 自建清理云函数），定期删除 7 天前的记录，避免集合无限膨胀。本次未包含该功能。

### 集合权限（重要）

小程序控制页是**客户端直读** `commands`（只读，不写）。请在控制台把 `commands` 的权限设为：

- 联调阶段：**所有用户可读，仅管理端可写**（自定义安全规则可写 `{"read": true, "write": false}`）
- 上线后：改成只读自己的命令，例如 `{"read": "doc.openid == auth.openid", "write": false}`

写入口只有云函数 `sendCommand`（云函数默认拥有管理端权限，不受安全规则限制）。

## 3. 云函数 `sendCommand`（小程序调用）

**位置**：`cloudfunctions/sendCommand/`（`index.js` + `package.json`，`wx-server-sdk ~2.4.0`）

**入参**（`wx.cloud.callFunction({name:'sendCommand', data:{...}})`）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `deviceId` | string | 是 | 目标设备号，最长 64 字符 |
| `cmd` | string | 是 | 白名单 `arm`/`start`/`stop`/`reset`/`mode_press`/`mode_rub`/`mode_slide`（大小写不敏感，入库统一小写） |

**出参**：

| 情况 | 返回 |
| --- | --- |
| 成功 | `{ ok:true, id:"<commands._id>" }` |
| cmd 不在白名单 | `{ ok:false, code:4001, message:"非法的 cmd：xxx；只允许 arm / start / stop / reset / mode_press / mode_rub / mode_slide" }` |
| 缺 `deviceId` | `{ ok:false, code:4002, message:"缺少 deviceId：..." }` |
| 集合不存在 | `{ ok:false, code:5002, message:"集合 commands 不存在：请在云开发控制台 → 数据库 → 新建集合 commands" }` |
| 其它写库失败 | `{ ok:false, code:5000, message:"写库失败：..." }` |

行为：校验白名单 → `cloud.getWXContext()` 取 `openid` → 写
`{deviceId, cmd, state:"pending", openid, createdAt: db.serverDate(), expiresAt: new Date(Date.now()+60000)}`。

> **白名单扩展（运动模式）**：`ALLOWED_CMDS` 已追加 `mode_press` / `mode_rub` / `mode_slide`
> 三个字符串，其余逻辑（校验顺序、`state="pending"`、`expiresAt=+60s`、`openid`、返回 `{ok,id}`、
> 错误码 4001/4002/5000/5002 语义）**一行未改**。`cmd` 入库前统一 `toLowerCase()`，所以
> 传 `MODE_SLIDE` 也会被接受并统一存成 `mode_slide`。

## 4. 运动模式（`mode_*`，只选模式、不启动）

STM32 端有三种动作模式，由「模式命令 + START」两步配合生效：

| 模式 | 云命令 `cmd` | 动作含义 | 控制页显示 |
| --- | --- | --- | --- |
| 按压 | `mode_press` | Z 轴下压再回位 | 按压 PRESS（蓝） |
| 揉搓 | `mode_rub` | Z + Yaw 往复运动 | 揉搓 RUB（绿） |
| 滑动 | `mode_slide` | Z + X 方向平移 | 滑动 SLIDE（橙） |

对应 STM32 侧的动作枚举：`ACTION_PRESS=0` / `ACTION_RUB=1` / `ACTION_SLIDE=2`。

### 4.1 语义：只选模式，不启动

- `mode_press` / `mode_rub` / `mode_slide` 的语义是**只把 STM32 的动作模式切过去，设备不会动**；
- 切换之后必须再点 **START**，设备才真正执行当前模式；
- 三个模式命令与 `arm/start/stop/reset` 走**完全相同**的通道：写入 `commands`（`state=pending`）、
  设备 poll 取走（`sent`）、执行后 ack（`done`）、60 秒未取走 `expired`；
- `commands` 集合**字段无需任何改动**（`cmd` 本来就是字符串，`mode_slide` 直接存进去即可）。

### 4.2 控制页交互（`pages/control/`）

- **运动模式区**：在「下发命令」卡片下方新增一张卡片，内含 3 个整行的模式卡片
  （按压/揉搓/滑动，带英文后缀与动作说明），点击其中一项 →
  `wx.cloud.callFunction({name:'sendCommand', data:{deviceId, cmd:'mode_slide'}})`；
- **成功 toast**：`已发送：模式=滑动（设备 1~3 秒内生效）`；
- **当前模式（高亮）**：选中项整体高亮并在右侧显示「当前 ✓」；
- **顶部状态区一行文字**：`当前模式：按压 / 揉搓 / 滑动`，从未选过时显示 `当前模式：未知`；
- **模式区下方**：一行推导说明 + 「模式说明」小框（三种动作含义 + 「先选模式，再点 START 执行」）；
- **最近命令列表**：`mode_*` 显示为友好中文「选择模式：按压 / 揉搓 / 滑动」，
  并在条目左侧加一条蓝色竖线以便与动作命令区分；时间/状态展示完全沿用原有逻辑。

### 4.3 「当前模式」的推导逻辑（无需额外云函数）

控制页**不新增任何云函数、也不额外查库**，直接复用「最近命令」那一次查询的结果推导：

1. 列表本来就按 `createdAt desc` 取前 10 条，所以 `list[0]` 是最新的一条；
2. 从新到旧找第一条 `cmd` 以 `mode_` 开头的记录，它的模式就是「当前模式」；
3. **`expired` 的记录会被跳过**：一条 60 秒内没被设备取走的选择，设备很可能从没收到、
   也就没生效，把它显示成「当前模式」会误导；跳过它继续往前找，全都过期则显示「未知」；
4. 找不到任何 `mode_*`（或换了一台设备）→ `当前模式：未知`；

实现位置：`pages/control/control.js` 的 `isModeItem()` / `buildModePatch()`，在 `loadCommands()`
成功回调里与列表一起 `setData`。点击模式卡片成功时会先**乐观更新**选中态，失败则回滚为推导值。

> 局限性（已知且可接受）：列表只取最近 10 条，如果 10 条内没有任何 `mode_*`，就会显示「未知」；
> 若将来要求精确，可改为单独查一条 `cmd: db.command.in(['mode_press','mode_rub','mode_slide'])`
> 并 `orderBy('createdAt','desc').limit(1)`，无需新云函数。

### 4.4 ✅ 两份白名单已同步扩展（`sendCommand` + `deviceCommand`）

设备链路有**两份**独立白名单，`deviceCommand` 在 poll 时还会**逐条二次校验**，
不在白名单里的命令会被直接跳过（只记 warn 日志，不返回给设备、也不置 `sent`）。
因此**两份必须一致**，否则 `mode_*` 到不了设备：

| 文件 | 常量 | 是否已扩展 `mode_*` | 不扩展的后果 |
| --- | --- | --- | --- |
| `cloudfunctions/sendCommand/index.js` | `ALLOWED_CMDS` | ✅ 已扩展 | 小程序点模式卡片直接返回 4001 |
| `cloudfunctions/deviceCommand/index.js` | `ALLOWED_CMDS` | ✅ **已扩展（同步补齐）** | 不扩展则 `mode_*` 被静默跳过，ESP32 永远收不到，记录停在 `pending` → `expired` |

两处现均为：

```js
const ALLOWED_CMDS = ["arm", "start", "stop", "reset", "mode_press", "mode_rub", "mode_slide"];
```

> ⚠️ 改了源码后**必须重新上传部署这两个云函数**（`sendCommand` 与 `deviceCommand`），云端才会生效。

## 5. 云函数 `deviceCommand`（设备经 HTTP 访问服务调用）

**位置**：`cloudfunctions/deviceCommand/`（`index.js` + `package.json`）

**event 兼容**：请求体在 `event.body`（JSON **字符串**，会 `JSON.parse`）或本身就是对象（控制台测试 / 直接调用）；
两种形态都统一取 `payload`（也接受把字段直接放在最外层，便于 Postman 联调）。
token 还可以放在请求头 `x-token` 里兜底。

**token 校验**：与 `deviceUpload` 使用**同一个共享密钥常量** `SHARED_TOKEN = "REPLACE_ME"`
（⚠️ 该常量在两个云函数里各有一份，**必须同时改成同一个随机长字符串**；上线请改并用 HMAC，见方案 §5.3）。
不一致返回 `{ok:false, code:4011, message:"token 校验失败：..."}`。

### action = `poll`（设备轮询取命令）

入参：`{ payload: { action:"poll", token:"REPLACE_ME", deviceId:"esp32-dev01" } }`

处理步骤：

1. **先做过期清理**：把该 `deviceId` 下 `state=="pending"` 且 `expiresAt < now` 的记录置为 `expired`；
2. 取该 `deviceId` 下 `state=="pending"` 且 `expiresAt >= now` 的记录，按 `createdAt` **升序**，最多 **5** 条；
3. 逐条再校验白名单 `cmd`，合法则置 `state:"sent"`、`sentAt: now`（带 `deviceId` 条件更新，防越权）；
4. 返回：

```json
{ "ok": true, "commands": [ { "id": "<_id>", "cmd": "start" } ], "serverTime": 1756376463000, "insecure": true }
```

- `serverTime` 为**毫秒**时间戳，方便设备判断链路延迟。
- 无可执行命令时 `commands` 为空数组（`ok` 仍为 `true`）。
- `insecure:true` 表示仍在使用占位密钥 `REPLACE_ME`，只可联调。

### action = `ack`（设备确认执行）

入参：`{ payload: { action:"ack", token:"REPLACE_ME", deviceId:"esp32-dev01", id:"<_id>", result:"ok" } }`

处理：按 `{_id: id, deviceId}` 条件更新为 `state:"done"`、`doneAt: now`、`result`（`result` 可省略）。

- 成功：`{ ok:true, insecure:true }`
- 记录不存在或不属于该 `deviceId`：`{ ok:false, code:4040, message:"命令不存在或不属于该设备：<_id>" }`
- 缺 `id`：`{ ok:false, code:4003, message:"缺少 id：..." }`

### 其它 action

`{ ok:false, code:4004, message:"未知 action：xxx；只支持 poll / ack" }`

### 其它错误码

| code | 含义 |
| --- | --- |
| `4001` | 请求体不是合法 JSON |
| `4002` | 缺少 `deviceId`（或超过 64 字符） |
| `4011` | token 校验失败 |
| `5002` | 集合 `commands` 不存在 |
| `5000` | 其它数据库错误 |

### 安全约束（已在代码中落实）

- **只处理白名单 cmd**：`arm/start/stop/reset` + `mode_press/mode_rub/mode_slide`（**两处白名单已同步扩展**，见 §4.4），库里出现别的值也绝不返回给设备（记 warn 日志跳过）。
- **查询/更新强制带 `deviceId`**：poll、过期清理、ack 全部带 `deviceId` 条件，A 设备无法读取或篡改 B 设备的命令。
- **先鉴权后动库**：token 不对时不做任何数据库读写。
- 单次 poll 最多 5 条、`result` 截断到 500 字符，避免被滥用。
- 常量时间比较 token（`safeEqual`），与 `deviceUpload` 保持一致。

## 7. 你必须做的手动步骤（缺一不可）

### 步骤 1：新建集合 `commands`

云开发控制台（开发者工具左上「云开发」→ 数据库）→ 集合管理 → **新建集合** → 名称填 `commands`（全小写）。
然后按第 2 节建两个索引（`deviceId+state` 复合、`createdAt` 降序），并把权限设为
「所有用户可读，仅管理端可写」（联调用）。

### 步骤 2：上传部署两个云函数

在微信开发者工具的资源管理器中：

1. 右键 `cloudfunctions/sendCommand` → **上传并部署：云端安装依赖（不上传 node_modules）**；
2. 右键 `cloudfunctions/deviceCommand` → **上传并部署：云端安装依赖（不上传 node_modules）**。

> 若右键菜单没有「云端安装依赖」，选「上传并部署：所有文件」也可以（本函数没有第三方依赖，只有 `wx-server-sdk`）。
> **不要**改 `deviceUpload`，它不需要重新部署。

### 步骤 3：给 `deviceCommand` 加 HTTP 路由 `/deviceCommand`

云开发控制台 → **HTTP 访问服务**（也叫「云接入」/「HTTP 网关」）→ 添加路由：

| 项 | 填 |
| --- | --- |
| 路径（Path） | `/deviceCommand` |
| 关联云函数 | `deviceCommand` |
| 请求方法 | `POST`（若必须选全部，也可放开 GET，但设备请用 POST） |
| 是否需要鉴权 | 不需要（鉴权由函数内的 `token` 完成） |

保存后控制台会给出一条形如
`https://cloud1-d5gncnkxj2606d114.service.tcloudbase.com/deviceCommand`
的访问地址，把它填给 ESP32 端（设备子代理按同一约定实现）。

> ⚠️ 如果这里是首次开通 HTTP 访问服务，控制台可能要求你先「新建环境」/确认默认域名，
> 按提示操作即可；**这一步是本通道能否跑通的关键**。

把下面两处的 `REPLACE_ME` 改成**同一个**随机长字符串（32 位以上），并同步改 ESP32 端：

- `cloudfunctions/sendCommand`… 无需改（小程序侧不校验 token）；
- `cloudfunctions/deviceCommand/index.js` 里的 `SHARED_TOKEN`；
- `cloudfunctions/deviceUpload/index.js` 里的 `SHARED_TOKEN`（保持与上一条一致）。

改完重新部署 `deviceCommand`（和 `deviceUpload`）。

### 步骤 5（运动模式）：✅ 白名单已同步扩展（直接部署即可）

`cloudfunctions/deviceCommand/index.js` 与 `sendCommand` 的 `ALLOWED_CMDS` **均已扩展为**

## 8. 如何验证

### 8.1 快速自检（不需要设备）

1. **集合建对了吗**：控制台 → 数据库 → `commands` 能看到空集合。
2. **小程序能下发吗**：编译小程序 → 列表页点「远程控制」→ 设备号保持 `esp32-dev01` → 点 **ARM**。
   预期：toast「命令已发送…」，列表中立刻出现一条 `ARM（待命） / 待发送`。
3. **数据写对了吗**：控制台刷新 `commands`，应看到一条记录：
   `cmd:"arm"`, `state:"pending"`, `openid:"oXXXX..."`, `createdAt` 是当前时间, `expiresAt` 比 `createdAt` 大 60 秒。
4. **白名单生效吗**：在控制台「云函数 → sendCommand → 云端测试」里传
   `{"deviceId":"esp32-dev01","cmd":"reboot"}`，预期返回 `{"ok":false,"code":4001,...}`，且库里没有新记录。
5. **过期清理生效吗**：等上面那条 ARM 超过 60 秒后，用下一步的 poll 调一次，再看控制台——
   该记录的 `state` 应变成 `expired`。

### 8.2 运动模式专项验证（推荐照这个顺序走一遍）

1. **云函数白名单**：「云函数 → sendCommand → 云端测试」传
   `{"deviceId":"esp32-dev01","cmd":"mode_slide"}` → 预期 `{"ok":true,"id":"..."}`；
   再传 `{"deviceId":"esp32-dev01","cmd":"mode_kick"}` → 预期 `{"ok":false,"code":4001,...}`。
2. **控制页选中态**：控制页点「滑动 SLIDE」→ 预期 toast `已发送：模式=滑动（设备 1~3 秒内生效）`，
   该卡片高亮并显示「当前 ✓」，顶部出现 `当前模式：滑动`，模式区下方显示
   「已下发「选择模式：滑动」，等待设备确认」。
3. **云库记录**：控制台刷新 `commands` → 应新增一条
   `cmd:"mode_slide"`, `state:"pending"`, `expiresAt = createdAt + 60s`（**字段与动作命令完全一致，无需加字段**）。
4. **最近命令列表**：控制页列表里该条显示为 **`选择模式：滑动` / 待发送**，带蓝色左侧竖线；时间与状态沿用原展示。
5. **设备是否真的收到（关键）**：用 §8.3 的 poll 测试拉一次 → 预期返回里出现
   `{"id":"...","cmd":"mode_slide"}`，且该记录变 `sent`。
   *若 poll 返回里**没有** `mode_slide`、记录仍是 `pending`，说明 `deviceCommand` 白名单还没扩展（§4.4）。*
6. **ack 后变已执行**：用 §8.3 的 ack 测试确认该 id → 预期记录变 `state:"done"`、
   控制页列表显示 **`选择模式：滑动` / 已执行**。
7. **当前模式推导**：点「按压 PRESS」→ 顶部变 `当前模式：按压`、按压卡片高亮、滑动卡片取消高亮；
   再把这条 `mode_press` 记录改成 `expired`（或等 60 秒后 poll 触发惰性过期）→ 顶部应回退到
   `当前模式：滑动`（跳过过期的选择）；把库里的 `mode_*` 记录都删掉 → 顶部显示 `当前模式：未知`。
8. **先选模式再 START**：选「滑动」→ 点 **START** → 预期 START 正常下发（`cmd:"start"`），
   顶部「当前模式」仍是**滑动**（START 不会改变模式）。

### 8.3 用控制台模拟设备（不需要 ESP32）

「云函数 → deviceCommand → 云端测试」，测试模板（事件）填：

```json
{ "payload": { "action": "poll", "token": "REPLACE_ME", "deviceId": "esp32-dev01" } }
```

预期返回：`{"ok":true,"commands":[{"id":"...","cmd":"arm"}],"serverTime":1756376463000,"insecure":true}`，
同时控制台里那条命令的 `state` 变为 `sent`、多出 `sentAt`。

再测 ack（把 `id` 换成上一步返回的 id）：

```json
{ "payload": { "action": "ack", "token": "REPLACE_ME", "deviceId": "esp32-dev01", "id": "上一步的id", "result": "ok" } }
```

预期 `{"ok":true,"insecure":true}`，记录变为 `state:"done"`、有 `doneAt` 与 `result`。

再测鉴权：把 `token` 改成 `"wrong"` → 预期 `{"ok":false,"code":4011,...}`。

### 8.4 用 HTTP 路由裸测（验证网关通了）

PowerShell（把地址换成步骤 3 拿到的地址）：

```powershell
curl.exe -X POST "https://cloud1-d5gncnkxj2606d114.service.tcloudbase.com/deviceCommand" `
  -H "Content-Type: application/json" `
  -d '{\"payload\":{\"action\":\"poll\",\"token\":\"REPLACE_ME\",\"deviceId\":\"esp32-dev01\"}}'
```

> 若返回 HTML 错误页 / 404，说明路由没配好（步骤 3 未生效）；
> 若返回 `{"ok":false,"code":4011}`，说明路由通了、只是 token 不对；
> 返回 `{"ok":true,...}` 即整条云端链路 OK。

### 8.5 端到端（接了 ESP32 之后）

1. 设备上电联网后，日志里应能看到周期性的 poll 请求；
2. 小程序点 **START** → 列表状态 `待发送` → 1~3 秒内变 `已下发` → 设备执行后变 `已执行` 并显示 `result`；
3. 把设备断电，点 **STOP**，等 60 秒以上再给设备上电 → 该命令应显示 `已过期`（不会在设备恢复后被补执行）。
4. 运动模式端到端：控制页选「**滑动**」→ 云 `commands` 出现 `mode_slide` → ESP32 poll 取到并执行
   （按约定映射到 `ACTION_SLIDE=2`）→ 设备 ack → 控制页列表该条变成 **`选择模式：滑动` / 已执行**，
   顶部「当前模式」显示 **滑动**；随后点 **START** → 设备按滑动模式真正动作。

## 9. 安全注意

1. **token 是唯一的门禁**：`REPLACE_ME` 只是占位，任何人知道这个值都能伪造设备拉命令。
   上线前务必改成随机长密钥，并尽快升级为 HMAC-SHA256 签名 + 时间戳窗口 + nonce 防重放（方案 §5.3）。
2. **HTTP 路由不要开「需要鉴权」的误解**：这里指的是云开发网关自带的鉴权；
   本通道的鉴权完全由函数内 `token` 完成，所以密钥强度就是安全强度。
3. **命令白名单是硬约束**：小程序端与设备端都必须只认
   `arm/start/stop/reset/mode_press/mode_rub/mode_slide`；
   云端已经做了二次校验，设备端也要做（防止有人直接往数据库塞记录）。
   ⚠️ 新增 `mode_*` 时，**两份白名单（`sendCommand` 与 `deviceCommand`）必须同步扩展**（§4.4）。
4. **deviceId 隔离**：所有查询/更新都带 `deviceId`。设备号是明文、可猜的，不要把它当凭据。
5. **`commands` 不要开放写权限**：安全规则保持 `"write": false`，写入口只有云函数。
   读权限上线后收紧为「只能读自己的命令」（`doc.openid == auth.openid`）。
6. **远程命令有延迟，不能当急停**：链路是「小程序 → 云库 → 设备轮询」，正常 1~3 秒，设备离线则完全不执行。
   紧急情况请使用**设备现场按钮/急停开关**或设备自带的本地网页。
7. **60 秒有效期是安全阀**：避免设备离线期间堆一堆命令、恢复后成串执行而失控。
8. **建议加操作审计与限流**：`openid` 已入库，可用于审计；如需更严，可在 `sendCommand` 里加
   「同一 openid 每分钟最多 N 条」「同一设备同命令去重」等限制（本次未实现）。
