# 电机上电自检（非阻塞）

旧自检使用 `APP_MOTOR_AUTOSTART=0`、`APP_MOTOR_SELFTEST=1`，测试 Motor_X，目标 2mm、速度 1mm/s。
重新编译烧录后，会自动使能、将当前位置清零，再反复执行 **0 → 2mm → 0**。
当前位置清零不是机械回零；启动前确认参考位置、实际方向和行程适合这次运动。

## 执行方式

自检实现位于 `source/task/Motor_Task/motor_selftest.c`。
`MotorTask` 每次正常循环推进一步，串口接收、轮询、超时、状态发布和停止请求一直工作。
自检生成的命令交给与外部队列命令相同的分发逻辑处理，不再向自身队列发命令后阻塞等待。

流程：

1. 等待被测轴在线。
2. 下发使能，等待成功应答后的有效使能状态回读。
3. 下发当前位置清零，等待原点有效以及更新的位置/状态反馈，并确认位置接近零。
4. 提交两点路径：先到目标，再回零；`PATH_RECIPROCATING`，`cycles=1`。
5. 路径完成后停留 500ms，再提交下一轮。每轮都回零，持续运行到停止或故障。

只成功下发命令不算完成，只有对应反馈确认后才能进入下一步。
`cycles` 的原始含义仍是按顺序执行 A、B；本测试把 A 设为目标、B 设为零，因此每轮结束在零。

## 参数

在 `source/config/app_config.h` 修改：

```c
#define APP_MOTOR_SELFTEST 1
#define APP_SELFTEST_AXIS MOTOR_X
#define APP_SELFTEST_TARGET 2.0f
#define APP_SELFTEST_SPEED 1.0f
```

X/Z 单位为 mm、mm/s，Yaw 为度、度/s；同时核对 `motor_config.c` 中的传动比、方向和范围。
将 `APP_MOTOR_SELFTEST` 和 `APP_MOTOR_AUTOSTART` 都设为 0 后重新编译烧录，恢复只查询、不自动使能/清零/运动。

## 停止和故障

- 调用 `MotorTask_Stop()`：中止运动，自检保持 `SELFTEST_STOPPED`，不会再提交下一轮。
- 外部任务提交普通命令时，自检退出自动运行；普通命令仍受原来“路径运行中拒绝冲突操作”的规则约束。要立即中止当前路径，使用 `MotorTask_Stop()`。
- 等待在线、使能确认、清零确认分别最多 5s。
- 每段路径最多 10s；整轮另有 25s 上限。调整目标/速度时须考虑该上限。
- 失联、命令拒绝、路径失败或等待超时：自检进入 `SELFTEST_FAILED`，请求停止，保留故障，不自动清故障或重新移动。
- 关闭/停止/失败都是终止状态；本版没有自动或命令式重启自检接口，恢复自检需复位。

`MotorTask_GetStatus()` 新增：

| 字段 | 含义 |
|---|---|
| selftest_state | DISABLED / WAIT_ONLINE / ENABLE / ZERO / PATH / PAUSE / STOPPED / FAILED |
| selftest_rounds | 已完成并返回零点的轮数 |

完全不动也可能是命令拒绝、参数不合法或自检超时，不能单凭现象认定串口未接通。
原地目标不会仅因“时间戳必须更新”而必然超时；后续轮询仍会提供新时间戳，是否到位同时取决于驱动器的到位标志及位置容差。

## 编译与验证

```powershell
cmake --preset Debug
cmake --build --preset Debug
python tools/check_integration.py
```

固件位于 `build/Debug/DataTouchCode.hex`（另有 ELF/BIN）。
本机测试覆盖自检阶段、新反馈确认、回零路径、重复间隔、拒绝、停止锁存、超时回绕及故障；它不代替实际电机和 RTOS 调度验证。
