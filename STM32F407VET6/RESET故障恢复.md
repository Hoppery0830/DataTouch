# RESET 故障恢复

当前实现用于主工程的视觉接入前 F4。保留 ARM；不新增监测任务或查询周期，使用原有 MotorTask 串口恢复和反馈轮询。

## 操作

1. 烧录本目录重新构建的 build/Debug/DataTouchCode.elf。
2. 电机供电、驱动器通信恢复后，点击小程序 RESET。
3. RESET 先回报“已接受”，界面沿用已有“停止中”状态；等待三轴完成恢复，才回报“完成”。
4. 完成后选模式、ARM，再 START。RESET 会使三轴软件原点失效，ARM 在当前位置重新建立软件零点；这不是机械寻零，ARM 前须确认当前位置适合作为动作起点。

## 判定

- 无论选择了什么模式，RESET 都检查 X、Z、Yaw 三轴，未选择模式时也不能跳过停止确认。
- 每轴必须收到本轮的成功 STOP 应答，然后取得晚于该应答的位置及状态反馈。
- 反馈必须未过期、驱动器保护位已解除、端口正常，并持续满足检查条件 200ms；在事务空隙调用 Motor_ClearFault。
- STOP 失败时，在端口可用和无未完成事务的条件下，间隔至少 200ms 允许再次请求 STOP；不重发使能、设零或运动命令。
- RESET 总时限为 5 秒。任一轴未恢复或 ESP32 心跳失效，回报 RC_FAULT，并请求停止。已恢复轴可清除故障，失败轴保留故障；整次 RESET 只有全部恢复才成功。
- STOP 或本地取消会终止恢复；重复的同序号 RESET 只回放缓存结果，不重启计时。
- 恢复后处于空闲，保留已选择的模式，但必须重新 ARM；不会续跑中断动作。

协议沿用 RC_STOPPING、RC_COMPLETE、RC_FAULT，不要求修改 ESP32 或云函数。当前小程序仍显示通用“停止中”和“故障”，没有细分每轴恢复失败原因。Ozone 可观察 motors[i] 的 fault、stop_failed、stop_acks、stop_ack_ms、position_ms、flags_ms 以及 remote.resetting。

## 验证

主机回归覆盖停止 ACK 门控、停止后的新反馈、稳定窗口、保护未解除、反馈过期、停止失败重试、整体超时、链路失效、重复请求、STOP 取消及恢复后禁止直接 START；既有电机/路径/远程控制回归通过。F4 Debug 构建通过。

尚未烧录实测。现场需分别验证：通信恢复后 RESET 成功；断开单轴时 RESET 失败；恢复中 STOP 可取消；恢复后旧动作不续跑、重新 ARM 后才可 START。
