# motor：Emm 协议与单电机管理

文件分工：`emm_protocol.c/.h` 只负责报文；`motor.c/.h` 负责事务、反馈、使能/运动模式和故障。运动路径在任务层，这里不决定走哪个点。

## 协议与单位

采用厂家 HAL Emm 示例的固定尾字节 **0x6B** 模式。没有 CRC16，也没有事务序号。多字节命令参数和反馈幅值使用大端编码；方向为独立符号字节。

| 操作 | 功能码 | 命令长度 | 关键参数/反馈 |
|---|---|---|---|
| 使能 | F3 | 6B | 布尔使能；ACK 状态 02 表示成功 |
| 绝对/相对位置 | FD | 13B | 脉冲幅值、整数 RPM、方向、acc |
| 速度 | F6 | 8B | 方向、整数 RPM；最高 5000 |
| 立即停止 | FE | 5B | 请求停止后仍需确认应答 |
| 当前位置清零 | 0A | 4B | 不是机械回零 |
| 位置查询 | 36 | 3B | 8B 应答；65536 刻度/电机转 |
| 状态查询 | 3A | 3B | 4B 应答；使能/到位/堵转保护标志 |
| 速度查询 | 35 | 3B | 6B 应答；带符号 RPM |

编码接口要求调用者提供至少 13B 缓冲，返回实际帧长；编码不发送。解析器逐字节接收，失败移一字节重同步，半帧超时由 motor 层负责。`FD/9F` 为到位通知，不替代 `FD/02` 接受应答。

## 所有权和执行顺序

三个 `motor_t` 分别绑定三个 UART，默认地址均为 1（独立串口允许相同地址）。对象及所有 module API 只在 MotorTask 中访问；外部任务调用 `MotorTask_Submit`，不可绕过任务直接修改对象。

```text
Motor_Process：接收/应答/超时/故障恢复/优先停止
    → 任务分发业务命令
    → Motor_Poll：空闲时查询位置、状态、速度
```

每路一次只允许一个 pending 事务。命令 API 返回 true 代表发送已受理；通过应答更新 enable_requested、origin_valid 等，再结合新状态/位置判断可执行性。使能请求既要 ACK，也要驱动器使能位。

查询完成后间隔 20ms，再轮到下一种查询；不是每 20ms 同时查询三种数据。控制节拍 500Hz 不等于位置反馈 500Hz。

## 关键接口

- `Motor_Healthy`：无故障且位置和状态均在 300ms 内，不代表原点有效或已使能。
- `Motor_Enable`：健康且无停止请求时发使能/失能。
- `Motor_Zero`：非运动模式下清当前位置；原点先无效，ACK 后等待新位置。
- `Motor_Move`：需要健康、原点有效及使能，内部发绝对位置指令。
- `Motor_Velocity`：同样检查运动前提；此低层接口不实施物理限位，上层须持续约束。
- `Motor_RequestStop`：只置请求，待 TX 缓冲可用时可取代旧待应答事务。
- `Motor_ClearFault`：链路恢复、反馈新鲜、无异常/未完成停止时显式清故障，不重建原点。

## 故障和限制

应答超时 80ms。超时、串口错误、溢出使故障锁存并令原点无效，按需恢复通信、请求停止；运动命令不自动重发。停止被拒或超时令 stop_failed=true；再次取得停止 ACK 后才能清故障。

状态 bit0 是使能、bit1 是到位，bit2/bit3 用于堵转及保护检查；需与实机固件一致。反馈只接受匹配当前 pending 功能码的报文，固定尾字节不能检测所有损坏，也不能完全区分同功能迟到响应。

此模块没有机械回零、硬件限位输入、同步插补和硬件急停。协议测试及 HAL 桩测试不能替代驱动器实测。路径/单位适配见 [MotorTask](../../task/Motor_Task/README.md)。
